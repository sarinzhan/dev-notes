## Кратко
Абстрактный класс — это частично реализованная база для семейства родственных классов. Он описывает отношение «является» (is-a), может хранить общее состояние и иметь конструктор. Интерфейс — это контракт, который могут выполнять даже несвязанные классы. Он описывает способность, и один класс может реализовать много интерфейсов. С Java 8 в интерфейсах могут быть методы с телом: `default` и `static`. С Java 9 к ним добавились `private`-методы для внутренних нужд. С Java 17 и класс, и интерфейс можно объявить `sealed`, чтобы ограничить круг наследников.

## Основное
### Абстрактный класс
- Объявляется с ключевым словом `abstract`, и создать его экземпляр нельзя. Внутри могут быть абстрактные методы (без тела, с пометкой `abstract`) и обычные методы, поля с любыми модификаторами, конструкторы и статические члены. Конструктор вызывается из конструктора наследника через `super(...)`.
- Абстрактный метод не может быть `final`, `private` или `static`. Любой из этих модификаторов запрещает переопределение, а смысл абстрактного метода именно в том, чтобы его переопределили.
- Класс, в котором есть хотя бы один абстрактный метод, обязан быть абстрактным. При этом абстрактный класс может не иметь ни одного абстрактного метода: так запрещают создавать его напрямую.
- Наследование одиночное: класс расширяет ровно один класс, но может реализовать сколько угодно интерфейсов.

### Интерфейс
- Это набор правил (контракт), которым обязан следовать реализующий класс.
- Поля неявно `public static final`, то есть это константы. Абстрактные методы неявно `public abstract`. С Java 9 метод может быть `private` и служить помощником для default-методов.
- Java 8 добавила `default`-методы и `static`-методы. Default-метод — это метод экземпляра с телом, и реализации его наследуют. Static-метод не наследуется, его вызывают как `Interface.m()`.
- Интерфейс может расширять несколько интерфейсов. У него нет конструктора и нет состояния экземпляра.
- `default`- и `static`-методы интерфейса нельзя объявить `synchronized` или `final` в сигнатуре, хотя блок `synchronized` внутри тела метода допустим. `final` запрещён намеренно: класс должен иметь возможность переопределить default-метод.

### Зачем добавили default-методы
- Чтобы развивать интерфейсы, не ломая все существующие реализации. Так в JDK появились `Collection.stream()`, `Iterable.forEach`, `List.sort`.
- Чтобы добавлять утилиты прямо в функциональные интерфейсы: `Comparator.thenComparing`, `Predicate.and`, `Function.andThen` ([[functional-interfaces]]).
- Чтобы не дублировать код: реализация по умолчанию пишется один раз в интерфейсе, а не в каждом классе.

### Конфликт default-методов
- Если в двух интерфейсах есть default-метод с одинаковой сигнатурой, класс обязан его переопределить. Нужную реализацию можно выбрать через `A.super.m()`.
- Если один интерфейс расширяет другой и переопределяет этот default-метод, побеждает более конкретный интерфейс, и классу ничего делать не нужно.
- Метод суперкласса всегда побеждает default-метод интерфейса. Это правило «класс побеждает» (class wins).

### Функциональные интерфейсы
- В функциональном интерфейсе ровно один абстрактный метод, и аннотация `@FunctionalInterface` заставляет компилятор это проверять. Default- и static-методов может быть сколько угодно. Можно расширять другой интерфейс, если в сумме абстрактный метод остаётся один: переопределять методы родителя не нужно, просто нельзя добавлять второй абстрактный метод. Методы, совпадающие с публичными методами `Object` (например, `equals`), не считаются.
- Такие интерфейсы реализуются лямбдами и ссылками на методы ([[functional-interfaces]]). Абстрактный класс лямбдой реализовать нельзя, даже если у него один абстрактный метод.

### Что выбрать
| | Абстрактный класс | Интерфейс |
|---|---|---|
| Отношение | «является» (is-a), иерархия похожих классов | «умеет» (can-do), общая способность у несвязанных классов |
| Состояние | поля, конструкторы | только константы |
| Сколько у класса | один | много |
| Развитие | можно свободно добавить обычный метод | можно добавить `default`-метод |
| Типичные примеры | `AbstractList`, `InputStream`, `AbstractController` в Spring | `Comparable`, `Runnable`, `UserRepository` |

- `sealed` (Java 17) работает для обоих. Например, `sealed interface Shape permits Circle, Square` позволяет `switch` с pattern matching (Java 21) быть исчерпывающим без ветки `default`.

## Пример
```java
public interface Notifier {
    void send(String recipient, String text);

    default void sendAll(Collection<String> recipients, String text) {   // default-метод, Java 8
        recipients.forEach(r -> send(r, normalize(text)));
    }

    static Notifier noop() { return (r, t) -> {}; }                      // static-метод, Java 8

    private String normalize(String text) { return text.strip(); }      // private-помощник, Java 9
}

public abstract class RetryingNotifier implements Notifier {
    private final int attempts;                                          // состояние может хранить только класс
    protected RetryingNotifier(int attempts) { this.attempts = attempts; }

    @Override public final void send(String recipient, String text) {    // шаблонный метод (template method)
        for (int i = 1; ; i++) {
            try { doSend(recipient, text); return; }
            catch (IOException e) { if (i == attempts) throw new UncheckedIOException(e); }
        }
    }
    protected abstract void doSend(String recipient, String text) throws IOException;
}
```

## Подводные камни
- Константы в интерфейсе — признак плохого кода (антипаттерн «интерфейс констант»). Используй `enum` или final-класс.
- Default-метод не может переопределить `equals`/`hashCode`/`toString` и не имеет доступа к состоянию. Если реализации по умолчанию нужно состояние, ей место в абстрактном классе.
- Добавление абстрактного метода в опубликованный интерфейс ломает все реализации. Добавление default-метода незаметно меняет поведение тех реализаций, где уже был метод с таким именем.
