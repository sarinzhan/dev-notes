## Кратко
`java.lang.ref` определяет четыре силы ссылок. Сила определяет, когда сборщик мусора может освободить объект: никогда, пока он сильно достижим; только при нехватке памяти — для мягких; при следующей сборке — для слабых; и после финализации (с уведомлением через очередь) — для фантомных.

## Основное
- **Сильная** (strong): обычная `Object o = new Object()`. Пока существует хоть одна сильная ссылка, объект никогда не собирается.
- **Мягкая** (`SoftReference`): собирается, только когда JVM вот-вот исчерпает память, и в самую последнюю очередь. Предназначена для кешей, чувствительных к памяти: объект живёт, пока есть место.
- **Слабая** (`WeakReference`): собирается в следующем цикле GC, как только не осталось сильных ссылок; сама ссылка объект вообще не удерживает. После сборки `get()` возвращает `null`. Используется в `WeakHashMap` (ключи), слушателях, канонизирующих словарях.
- **Фантомная** (`PhantomReference`): `get()` всегда возвращает `null`; объект недостижим для программы. Когда объект становится фантомно достижимым, ссылка помещается в `ReferenceQueue`, что позволяет выполнить очистку *после* того, как объекта не стало (современная замена `finalize()`, её использует `Cleaner`).
- Любую несильную ссылку можно зарегистрировать в `ReferenceQueue`, чтобы получить уведомление, когда её объект будет собран.

## Пример
```java
Map<Key, WeakReference<Image>> cache = new HashMap<>();

Image load(Key key) {
    WeakReference<Image> ref = cache.get(key);
    Image img = ref == null ? null : ref.get();
    if (img == null) {
        img = decode(key);
        cache.put(key, new WeakReference<>(img));
    }
    return img;
}
```

## Подводные камни
- У кеша на `SoftReference` нет политики вытеснения, которой можно управлять; на практике Caffeine с явно заданным размером ведёт себя лучше.
- В `WeakHashMap` ключи слабые, а значения сильные: значение, ссылающееся на свой ключ, удерживает запись навсегда.
- `finalize()` устарел; вместо него используй `Cleaner` с фантомной ссылкой.
