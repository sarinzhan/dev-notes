## Кратко
В Java восемь примитивных типов, хранящих «сырые» значения, и для каждого есть неизменяемый `final` класс-обёртка, чтобы примитивы могли участвовать в дженериках, коллекциях и стримах. Целочисленные обёртки для значений в диапазоне -128..127 кешируются, поэтому `==` на маленьких `Integer` «работает», а на больших — нет.

## Основное
### Восемь примитивов
| Тип | Размер | Диапазон | По умолчанию |
|---|---|---|---|
| `boolean` | зависит от JVM (1 байт в массивах, часто слот `int` на стеке) | `true`/`false` | `false` |
| `byte` | 1 байт | -128..127 | 0 |
| `short` | 2 байта | -32 768..32 767 | 0 |
| `int` | 4 байта | ±2.1·10⁹ | 0 |
| `long` | 8 байт | ±9.2·10¹⁸ | 0L |
| `float` | 4 байта | IEEE 754 одинарной точности, ~7 цифр | 0.0f |
| `double` | 8 байт | IEEE 754 двойной точности, ~16 цифр | 0.0 |
| `char` | 2 байта | одна кодовая единица UTF-16, 0..65 535 | `'\u0000'` |

- Спецификация не фиксирует размер `boolean`; «1 бит» из источника — неверно. Всё остальное зафиксировано JLS, и это часть принципа «write once, run anywhere».
- Целочисленная арифметика молча переполняется (`Integer.MAX_VALUE + 1 == Integer.MIN_VALUE`); когда это важно, используй `Math.addExact` или `long`. Целочисленное деление на ноль бросает `ArithmeticException`; с плавающей точкой получается `Infinity`/`NaN`.
- `float`/`double` не могут точно представить 0.1: никогда не используй их для денег. Используй `long` в минимальных единицах (minor units) или `BigDecimal`.
- `char` — это не символ: кодовые точки вне BMP (эмодзи) занимают два `char`. Когда нужны настоящие символы, используй `String.codePoints()`.
- У локальных примитивов нет значения по умолчанию, и их нужно присвоить до использования; поля и элементы массивов получают значения по умолчанию из таблицы.

### Обёртки: зачем они нужны и почему они final
- `Boolean, Byte, Short, Integer, Long, Float, Double, Character` (плюс `Number` как абстрактный родитель числовых).
- Коллекции, [[generics]] и [[stream-api]] работают только с объектами (стирание типов запрещает `List<int>`), поэтому примитив приходится оборачивать. Обёртки также несут утилиты: `Integer.parseInt`, `Integer.toBinaryString`, `Character.isDigit`, `Double.compare`, `MAX_VALUE`.
- Они **неизменяемы**: ни один метод не меняет обёрнутое значение. Они **final**, потому что у неизменяемого класса не должно быть подклассов (подкласс мог бы добавить изменяемое состояние или переопределить `equals` и сломать все ключи `HashMap`), и потому что JIT полагается на их точные типы.
- Источник называет обёртки «частным случаем Decorator»; это натяжка. Decorator добавляет поведение к тому же интерфейсу; обёртка меняет представление. Думай об этом как об «упаковке» (boxing), а не о Decorator.

### Кеш
- `Integer.valueOf(n)` (его вызывает автоупаковка) возвращает кешированный экземпляр для -128..127; `Long`, `Short`, `Byte` делают то же самое, `Character` кеширует 0..127, у `Boolean` два экземпляра. `Float` и `Double` ничего не кешируют.
- Верхнюю границу кеша `Integer` можно поднять флагом `-XX:AutoBoxCacheMax=N`; полагаться на это не стоит никому.
- `new Integer(5)` всегда выделяет память и помечен устаревшим к удалению начиная с Java 9/16; используй `valueOf` или автоупаковку ([[casting-and-autoboxing]]).

## Пример
```java
Integer a = 127, b = 127;      // Integer.valueOf -> из кеша
Integer c = 128, d = 128;      // два разных объекта
System.out.println(a == b);           // true
System.out.println(c == d);           // false
System.out.println(c.equals(d));      // true: всегда сравнивай обёртки через equals

long balanceMinor = 1_250_00L;        // деньги в минимальных единицах, никогда не double
double ratio = 0.1 + 0.2;             // 0.30000000000000004
BigDecimal exact = new BigDecimal("0.1").add(new BigDecimal("0.2")); // 0.3
```

## Подводные камни
- `==` между двумя обёртками сравнивает ссылки; правильным это выглядит только для маленьких кешированных значений. Сравнение обёртки с примитивом распаковывает, поэтому `Integer x == 5` — нормально, а `Integer x == Integer y` — баг.
- Распаковка `null`-обёртки бросает `NullPointerException`: поле `Integer`, отображённое из nullable-колонки БД и использованное в арифметике `int`, — классический NPE в продакшене.
- Счётчики в `Map<String, Integer>` при каждом инкременте делают `get`, распаковку, сложение, упаковку и `put`; на горячих путях используй `merge`/`compute` или `long[]`/`LongAdder`.
- Арифметика над `char` повышает тип до `int`: `'a' + 1` равно `98`, а не `'b'`; приводи обратно.
- Связанные заметки: [[casting-and-autoboxing]], [[strings-and-string-pool]], [[immutable-objects]].
