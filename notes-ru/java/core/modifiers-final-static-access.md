## Кратко
Модификаторы доступа (`private`, package-private, `protected`, `public`) определяют, кто видит член класса; `final` запрещает изменение (повторное присваивание, переопределение, наследование); `static` привязывает член к классу, а не к экземпляру. `this` — скрытый аргумент-получатель каждого метода экземпляра, а `super` — тот же объект, рассматриваемый как его суперкласс.

## Основное
### Модификаторы доступа
| Модификатор | Тот же класс | Тот же пакет | Подкласс (любой пакет) | Все |
|---|---|---|---|---|
| `private` | да | | | |
| (нет) package-private | да | да | | |
| `protected` | да | да | да | |
| `public` | да | да | да | да |

- Классы верхнего уровня могут быть только `public` или package-private. Вложенные классы могут использовать все четыре ([[nested-and-anonymous-classes]]).
- `protected` включает доступ на уровне пакета, что удивляет многих: `protected`-поле видно каждому классу того же пакета, подкласс он или нет.
- Начиная с Java 9 система модулей добавляет уровень выше `public`: `public`-тип в неэкспортированном пакете невидим за пределами своего модуля.
- Переопределение может расширять доступ, но никогда не сужать ([[methods-overloading-overriding]]).

### final
- **Класс**: нельзя расширить (`String`, обёртки, records неявно final). Причина: гарантии неизменяемости и безопасность ([[immutable-objects]]).
- **Метод**: нельзя переопределить. JIT и так может инлайнить любой мономорфный вызов, поэтому `final` на методах — вопрос дизайна, а не скорости.
- **Поле**: должно быть присвоено ровно один раз — в объявлении, блоке инициализации или в каждом конструкторе; после этого измениться не может. Заметь, что замораживается ссылка, а не объект: `final List` всё ещё можно изменять.
- **Параметр / локальная переменная**: нельзя переприсвоить после инициализации.
- `final`-поля также получают гарантию модели памяти: финальные поля корректно созданного объекта видны каждому потоку без синхронизации ([[java-memory-model]]).
- **Effectively final** (Java 8): локальная переменная, которая ни разу не переприсваивается после инициализации, хотя и не объявлена `final`. Лямбды и анонимные/локальные классы могут захватывать только final или effectively final локальные переменные, потому что значение копируется в замыкание; если бы позднейшие изменения были разрешены, копия и оригинал разошлись бы.

### static
- `static`-поле или метод принадлежит классу и доступен без экземпляра; существует ровно одна копия на класс на загрузчик классов.
- Статический метод не может использовать `this` или `super` и напрямую обращается только к другим статическим членам. Конечно, он может принимать экземпляр как параметр.
- Статические методы можно перегружать, но **нельзя переопределять**: подкласс, объявивший ту же статическую сигнатуру, *скрывает* метод родителя, и вызов разрешается по статическому типу ссылки во время компиляции.
- `static` применяется к вложенным классам (статический вложенный класс не хранит внешний экземпляр) и к блокам инициализации (выполняются один раз при инициализации класса, [[class-initialization-order]]).
- Статические методы интерфейсов (Java 8) не наследуются реализующими классами; их вызывают как `Interface.method()`.

### this и super
- `this` — ссылка на текущий объект; под капотом это скрытый первый аргумент, который JVM передаёт каждому методу экземпляра (`invokevirtual` кладёт получателя на стек, см. [[oop-principles]]). Применение: отличить поле от параметра (`this.name = name`), вызвать другой конструктор (`this(...)`, должен быть первой инструкцией), передать текущий объект (`registry.register(this)`), вернуть его для fluent API.
- `super` ссылается на тот же объект в виде суперкласса: `super(...)` вызывает конструктор родителя (если не написан, неявно вызывается конструктор без аргументов), `super.method()` вызывает переопределённую реализацию, `super.field` обращается к скрытому полю.
- Внутри лямбды `this` — это охватывающий экземпляр; внутри анонимного класса `this` — это анонимный объект ([[nested-and-anonymous-classes]]).

## Пример
```java
public class RateLimiter {
    private static final int DEFAULT_PERMITS = 100;        // одна на класс, константа
    private static int instances;                           // общее изменяемое: требует осторожности

    private final int permits;                              // задаётся один раз на объект
    protected long windowMillis = 1_000;                    // видно подклассам и пакету

    public RateLimiter() { this(DEFAULT_PERMITS); }         // цепочка конструкторов через this(...)

    public RateLimiter(int permits) {
        this.permits = permits;
        instances++;                                        // статический метод не смог бы здесь использовать 'this'
    }

    public static int instances() { return instances; }

    public Runnable onExhausted(String clientId) {
        int snapshot = permits;              // effectively final: захватывается лямбдой
        return () -> log(clientId + " exceeded " + snapshot + " in " + this.windowMillis + " ms");
    }

    protected void log(String msg) { System.out.println(msg); }
}
```

## Подводные камни
- Изменяемое `static`-поле — это глобальное состояние, общее для всех потоков; защищай его или делай неизменяемым. Статические коллекции — классическая утечка памяти ([[garbage-collection]]).
- Вызов переопределяемого метода из конструктора выполняет версию подкласса до инициализации полей подкласса ([[constructors-and-initialization]]).
- `final` на параметре метода или локальной переменной — в основном шум; для неизменяемости и потокобезопасности важен `final` на полях.
- Скрытие статических методов и полей в подклассах почти всегда ошибка; IDE не зря об этом предупреждают.
- Связанные заметки: [[class-initialization-order]], [[immutable-objects]], [[abstract-classes-and-interfaces]].
