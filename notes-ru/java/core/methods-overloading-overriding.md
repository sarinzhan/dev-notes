## Кратко
**Сигнатура** метода — это его имя плюс типы параметров; тип возврата, исключения и модификаторы в неё не входят. **Перегрузка** (overloading) — несколько методов с одним именем и разными сигнатурами в одном классе, выбор происходит во время компиляции. **Переопределение** (overriding) — подкласс заменяет метод суперкласса с той же сигнатурой, выбор происходит во время выполнения по реальному классу объекта. Здесь же, потому что они слишком малы для отдельных заметок: виды циклов и формы выражений.

## Основное
### Метод и сигнатура
- Метод — это именованный блок, который принимает параметры, выполняет инструкции и возвращает значение (или `void`). Под капотом это функция со скрытым `this` ([[oop-principles]]).
- Сигнатура = имя + упорядоченные типы параметров. У `int parse(String s)` и `long parse(String s)` одинаковая сигнатура, и они не могут сосуществовать. Обобщённые типы стираются: `void f(List<String>)` и `void f(List<Integer>)` конфликтуют ([[generics]]).

### Перегрузка (время компиляции, ad-hoc полиморфизм)
- Одно имя, разные списки параметров; тип возврата тоже может отличаться, но не может отличаться только он.
- Порядок выбора, когда подходят несколько перегрузок: точное совпадение → расширение примитива (`int` → `long`) → упаковка/распаковка → varargs. `print(null)` при перегрузках `print(String)` и `print(Object)` выбирает `String` (наиболее конкретную); при `print(String)` и `print(Integer)` — ошибка компиляции (неоднозначность).
- Статические методы можно перегружать, но нельзя переопределять ([[modifiers-final-static-access]]).

### Переопределение (время выполнения, полиморфизм подтипов)
- Та же сигнатура в подклассе; `@Override` заставляет компилятор это проверить (иначе опечатка молча создаёт перегрузку).
- Правила:
  - Доступ можно **расширять**, но никогда не сужать: `protected` → `protected` или `public`; package-private → package-private, `protected` или `public`. `private`-методы не наследуются и не могут быть переопределены.
  - Тип возврата может быть **ковариантным**: переопределение может возвращать подтип исходного типа возврата (`Object clone()` → `Order clone()`).
  - Проверяемые исключения могут быть теми же, более узкими или убранными, но никогда не новыми или более широкими; непроверяемые исключения не ограничены ([[exceptions]]).
  - Методы `final`, `static` и `private` переопределить нельзя; `static` с той же сигнатурой — это *скрытие* (hiding).
- Диспетчеризация: `invokevirtual`/`invokeinterface` ищут метод в vtable/itable реального класса; JIT превращает мономорфные места вызова в прямые вызовы с проверкой типа.

### Циклы
| Вид | Когда проверяется условие | Форма в Java | Когда использовать |
|---|---|---|---|
| С предусловием | перед каждой итерацией | `while (cond)` | число итераций неизвестно, может не выполниться ни разу |
| С постусловием | после каждой итерации | `do { } while (cond)` | тело должно выполниться хотя бы раз (прочитать, потом проверить; циклы retry) |
| Со счётчиком | начало, конец и шаг в заголовке | `for (int i = 0; i < n; i++)` | по индексу, фиксированное число раз |
| For-each | пока не исчерпан итератор | `for (T x : iterable)` | каждый элемент, индекс не нужен; работает с массивами и `Iterable` ([[iterators-and-fail-fast]]) |

- `break`, `continue` и их формы с метками (`outer:`) управляют вложенными циклами; `return` внутри цикла выходит из метода. Стримы ([[stream-api]]) заменяют многие циклы со счётчиком, но не умеют прерываться досрочно, кроме как через короткозамыкающие операции.

### Формы выражений (положение оператора)
- **Префиксная** `++a`, `-a`, `!b`: оператор перед операндом; `++a` увеличивает и возвращает новое значение.
- **Инфиксная** `a + b`: между операндами; так устроены все бинарные операторы Java.
- **Постфиксная** `a++`: после операнда; возвращает старое значение, затем увеличивает.
- Оператор — это символ или ключевое слово (`+`, `instanceof`, `? :`), применяемое к операндам (значениям или переменным). В Java нет пользовательской перегрузки операторов; `+` для `String` — единственное встроенное исключение.

## Пример
```java
public class Money {
    private final long minor;
    private final Currency currency;
    Money(long minor, Currency currency) { this.minor = minor; this.currency = currency; }

    // Перегрузка: одно имя, разные списки параметров, выбор во время компиляции
    public Money plus(Money other)  { return new Money(minor + other.minor, currency); }
    public Money plus(long minor)   { return new Money(this.minor + minor, currency); }

    // Переопределение: та же сигнатура, что у Object.toString, выбор во время выполнения
    @Override public String toString() { return minor / 100 + "." + minor % 100 + " " + currency; }
}

class AuditedMoney extends Money {
    AuditedMoney(long minor, Currency c) { super(minor, c); }
    @Override public AuditedMoney plus(Money other) {        // ковариантный тип возврата, та же сигнатура
        AuditedMoney result = new AuditedMoney(0, null);     // (для иллюстрации)
        return result;
    }
}
```

## Подводные камни
- Перегрузка на `Object` и на конкретный тип при переменной статического типа `Object` вызывает версию для `Object`, даже если объект — `String`: выбор перегрузки никогда не смотрит на тип во время выполнения.
- `remove(int index)` против `remove(Object o)` в `List<Integer>`: `list.remove(1)` удаляет по индексу; чтобы удалить значение, упакуй его явно.
- Если забыть `@Override` на методе с немного другим типом параметра (`equals(Order)` вместо `equals(Object)`), получится перегрузка, которую коллекции никогда не вызывают ([[equals-and-hashcode]]).
- Перегрузки с varargs в сочетании с автоупаковкой дают трудночитаемые ошибки компиляции о неоднозначном вызове; не смешивай их.
