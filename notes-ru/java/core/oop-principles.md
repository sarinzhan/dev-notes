## Кратко
Объектно-ориентированное программирование представляет программу как набор объектов, каждый из которых — экземпляр класса, а классы образуют иерархию наследования. Четыре принципа: абстракция, инкапсуляция, наследование и полиморфизм. Полиморфизм шире, чем «подкласс переопределяет метод»: это семейство механизмов (параметрический, подтипов/включения, перегрузка, приведение), которые позволяют одному фрагменту кода работать с несколькими типами.

## Основное
### Четыре принципа
- **Абстракция**: показывать только существенные характеристики объекта и скрывать детали реализации. В Java это делается через абстрактные классы и интерфейсы ([[abstract-classes-and-interfaces]]).
- **Инкапсуляция**: данные и методы, которые с ними работают, находятся в одном объекте; внутреннее состояние защищено и доступно только через публичный API (геттеры/сеттеры, а лучше методы, ориентированные на поведение). Это обеспечивают модификаторы доступа ([[modifiers-final-static-access]]).
- **Наследование**: новый класс строится на основе существующего, переиспользуя его код и добавляя свойства или методы. Терминология: родитель = суперкласс = базовый класс; потомок = подкласс = производный класс.
- **Полиморфизм**: один и тот же фрагмент программы ведёт себя «похожим образом» с данными разных типов. См. ниже.

### Класс, объект, экземпляр
- **Класс** — это описание (шаблон, контракт) множества объектов с общими атрибутами и операциями. После компиляции это байткод в файле `.class`, который загрузчик классов загружает во время выполнения.
- **Объект** — конкретное воплощение этой абстракции: у него есть идентичность, состояние и поведение, и он живёт в куче ([[jvm-memory-areas]]).
- «Экземпляр класса» и «объект» — взаимозаменяемые термины. Утверждение источника, что «объект — это байткод, полученный из класса», неверно: байткод описывает класс; объекты существуют только во время выполнения.

### Методы, конструкторы и операторы — это просто функции
- Метод — синтаксический сахар над функцией, которая получает скрытый первый аргумент `this`. Ссылки на методы делают это видимым: `String::length` — это `Function<String, Integer>`, аргументом которой является получатель.
- Конструктор — функция, инициализирующая объект ([[constructors-and-initialization]]); оператор — функция с особым синтаксисом.

### Полиморфизм как следует
- Определение Пирса: «семейство механизмов, позволяющих использовать один и тот же фрагмент программы с разными типами в разных контекстах».
- Мономорфная функция работает с одним конкретным типом. Полиморфная функция — с несколькими.
- Стрейчи (1967) разделил его на **параметрический** (код написан обобщённо, абстрагируясь от конкретных типов) и **ad-hoc** (нет единого правила для типа результата; вызов направляется к одной из нескольких реализаций, выбранной по типу аргумента).
- Карделли и Вегнер (1985) уточнили это до двух семейств:

| Семейство | Вид | Механизм в Java | Открыт для новых типов? |
|---|---|---|---|
| Универсальный | параметрический | [[generics]] (`List<T>`) | Да: работает любой тип, удовлетворяющий ограничениям, функцию менять не нужно |
| Универсальный | включения (подтипов) | наследование и интерфейсы, переопределение | Да: новый подкласс просто работает |
| Ad-hoc | перегрузка | несколько методов с одним именем ([[methods-overloading-overriding]]) | Нет: новому типу нужна новая перегрузка |
| Ad-hoc | приведение (coercion) | неявное расширение, автоупаковка ([[casting-and-autoboxing]]) | Нет: преобразования зафиксированы языком |

- «Универсальный/открытый» означает, что пользователь может добавлять поддерживаемые типы, не трогая исходный код функции; «ad-hoc/закрытый» — что функцию (или набор её перегрузок) придётся править. Утиная типизация (динамические языки) и алгебраические типы данных (sealed-интерфейсы + records + `switch` с pattern matching, Java 21) — другие члены того же семейства.
- Когда на собеседовании спрашивают «что такое полиморфизм», ожидаемый для Java ответ — полиморфизм подтипов через переопределение плюс упоминание перегрузки; классификация выше — бонус.

## Пример
```java
// Универсальный полиморфизм (включения): одно место вызова, много реализаций
sealed interface PaymentMethod permits Card, Wallet {}
record Card(String pan) implements PaymentMethod {}
record Wallet(String phone) implements PaymentMethod {}

interface FeeCalculator { long feeMinor(long amountMinor); }

class CardFee implements FeeCalculator {
    public long feeMinor(long amountMinor) { return amountMinor * 2 / 100; }
}
class WalletFee implements FeeCalculator {
    public long feeMinor(long amountMinor) { return 0; }
}

// Ad-hoc (перегрузка): компилятор выбирает метод по статическому типу аргумента
class Formatter {
    String format(Card c)   { return "card ****" + c.pan().substring(12); }
    String format(Wallet w) { return "wallet " + w.phone(); }
}
```

## Подводные камни
- Перегрузка разрешается **во время компиляции** по статическому типу; переопределение — **во время выполнения** по реальному объекту. `format((PaymentMethod) card)` не скомпилируется с классом выше, потому что нет перегрузки, принимающей `PaymentMethod`.
- Геттеры и сеттеры на каждом поле — это не инкапсуляция; раскрытие изменяемого `List` через геттер ломает её так же, как публичное поле. См. [[immutable-objects]].
- Глубокие иерархии наследования привязывают подклассы к внутренностям суперкласса; предпочитай композицию ([[class-relationships]]) и оставляй наследование для настоящего «является» (is-a).
- Связанные заметки: [[solid]] — принципы проектирования, построенные на этих; [[class-relationships]] — ассоциация, агрегация и композиция.
