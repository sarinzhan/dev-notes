## Кратко
Дженерики (generics, Java 5) позволяют классам, интерфейсам и методам принимать тип как параметр, поэтому компилятор проверяет, что кладётся в `List<String>`, вместо того чтобы ты приводил значения из `Object`. Они существуют только во время компиляции: после **стирания типов** (type erasure) `List<String>` в байткоде — это обычный `List`, и этим объясняются все ограничения ниже.

## Основное
### Основы
- Параметр типа у класса или интерфейса: `class Box<T> { T value; }`; у метода: `static <T> T first(List<T> xs)`.
- Ограниченный параметр типа: `<T extends Comparable<T>>` ограничивает, каким может быть T, и позволяет вызывать `compareTo`.
- Сырые типы (raw types; `List` без параметра) ведут себя как `List<Object>` с предупреждениями; они существуют ради обратной совместимости. Их примешивание сводит проверки типов на нет.
- Инвариантность: `List<Integer>` **не** является `List<Number>`, хотя `Integer` является `Number`. Иначе через ссылку `List<Number>` можно было бы добавить `Double`. Wildcard-типы нужны, чтобы ослабить это правило.

### Wildcard-типы
- `?` без ограничения: список чего-то; читать можно как `Object`, добавить нельзя ничего, кроме `null`.
- `? extends T`, верхняя граница: список T или подтипа. **Читать** как T безопасно, добавлять — нет.
- `? super T`, нижняя граница: список T или супертипа. **Добавлять** T безопасно, прочитанное возвращается как `Object`.
- **PECS**: Producer `extends`, Consumer `super`. Метод, который только читает из коллекции, принимает `Collection<? extends T>`; метод, который только пишет, принимает `Collection<? super T>`. Именно так объявлен `Collections.copy(List<? super T> dest, List<? extends T> src)`.

### Что не может быть обобщённым (из-за стирания)
- Примитивы в качестве аргументов типа: `List<int>` недопустим, используй `List<Integer>` (автоупаковка).
- `new T()`, `new T[]`, `T.class`, `instanceof List<String>` и `catch (T e)`: во время выполнения никакого T нет.
- Статические поля типа T: статические члены общие для всех параметризаций.
- Обобщённые исключения: `class MyEx<T> extends Exception` недопустим.
- Перегрузки, отличающиеся только аргументом типа (`f(List<String>)` и `f(List<Integer>)`), после стирания имеют одинаковую сигнатуру.
- Обобщённые массивы: `List<String>[]` нельзя безопасно создать, потому что массивы ковариантны и проверяются во время выполнения.

## Пример
```java
// PECS на практике
static <T extends Comparable<? super T>> T max(Collection<? extends T> items) {
    Iterator<? extends T> it = items.iterator();
    T best = it.next();
    while (it.hasNext()) { T x = it.next(); if (x.compareTo(best) > 0) best = x; }
    return best;
}

static void fill(List<? super Integer> target, int n) {
    for (int i = 0; i < n; i++) target.add(i);     // Integer в List<Number> или List<Object>
}
```

## Подводные камни
- Непроверяемые приведения (`(T) obj`) компилируются с предупреждением и падают позже с `ClassCastException` далеко от причины.
- В коллекции `? extends T` нельзя добавлять: частый сюрприз, когда метод пытается изменить свой вход.
- Рефлексия видит только стёртые типы, за исключением обобщённых сигнатур, сохранённых в метаданных класса (`getGenericSuperclass`); так `TypeReference` в Jackson и `ParameterizedTypeReference` в Spring восстанавливают `List<User>`.
- Где дженерики встречаются со стандартной библиотекой: [[collections-framework]].
