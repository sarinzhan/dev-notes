## Кратко
Класс, объявленный внутри другого класса, называется **вложенным** (nested). Статический вложенный класс — это просто класс верхнего уровня в пространстве имён внешнего; нестатический **внутренний** (inner) класс несёт скрытую ссылку на охватывающий экземпляр. Локальные и анонимные классы — это внутренние классы, объявленные внутри метода. Лямбды похожи на анонимные классы, но классами вообще не являются: нет отдельного файла `.class`, `this` — это охватывающий объект, и они могут реализовывать только функциональные интерфейсы.

## Основное
### Четыре вида
| Вид | Где объявлен | Хранит внешний экземпляр | Может иметь статические члены | Типичное применение |
|---|---|---|---|---|
| Статический вложенный | `static class In` внутри `Out` | нет | да | вспомогательные типы, билдеры, `Map.Entry`, `HashMap.Node` |
| Внутренний (нестатический) | `class In` внутри `Out` | да (`Out.this`) | начиная с Java 16 | итераторы, представления, которым нужно внешнее состояние (`ArrayList.Itr`) |
| Локальный | внутри метода или блока | да, если в методе экземпляра | начиная с Java 16 | разовый помощник, видимый только в этом методе |
| Анонимный | выражение `new Type() { ... }` | да, если в контексте экземпляра | нет | разовая реализация интерфейса или подкласса |

- Вложенные классы существуют, чтобы обслуживать охватывающий класс; компилятор выдаёт их как `Out$In.class`, `Out$1.class`.
- Доступ: вложенный класс видит все члены внешнего класса, включая `private`, и внешний тоже видит приватные члены вложенного (начиная с Java 11 через *nestmates*; раньше — через синтетические методы доступа). В источнике сказано «но не наоборот»; это неверно, доступ взаимный. Что *действительно* верно — вложенность ослабляет инкапсуляцию: приватное состояние внешнего класса видно коду, который находится не в теле внешнего класса.
- Создание внутреннего экземпляра снаружи: `outer.new Inner()`. Внутри внутреннего класса `Out.this` обозначает охватывающий экземпляр.

### Анонимные классы
- Выражение, которое за один раз объявляет и создаёт безымянный подкласс класса или реализацию интерфейса: `new Comparator<String>() { public int compare(...) {...} }`.
- Может расширять класс **или** реализовывать один интерфейс, но не то и другое сразу; может переопределять любые методы, включая методы `Object` (`toString`); может иметь поля и блоки инициализации, но не конструкторы (используй блок инициализации или передай аргументы в конструктор суперкласса).
- `this` ссылается на сам анонимный объект.
- Захваченные локальные переменные должны быть final или effectively final ([[modifiers-final-static-access]]): компилятор копирует их в синтетические поля.
- Класс определяется во время компиляции, а не «создаётся во время выполнения», как сказано в источнике; во время выполнения происходит обычная загрузка класса.

### Лямбды против анонимных классов
- Лямбда — это реализация функционального интерфейса (ровно один абстрактный метод, [[functional-interfaces]]) в краткой форме. Она не может реализовать абстрактный класс, даже с единственным абстрактным методом.
- Формы: тело-выражение `x -> x * 2` и тело-блок `x -> { ...; return y; }`.
- `this` внутри лямбды — это охватывающий экземпляр; у лямбды нет собственной идентичности, и она не может сослаться на саму себя.
- Нет файла класса: `invokedynamic` + `LambdaMetafactory` создают скрытый класс при первом вызове; незахватывающая лямбда — синглтон, захватывающая выделяет память при каждом вычислении. Анонимные классы выделяют память каждый раз и хранят ссылку на внешний объект.
- Лямбда не может затенять локальные переменные охватывающей области видимости; анонимный класс может.
- Ссылки на методы (`String::length`, `this::handle`, `Order::new`) — это лямбды без тела: получатель несвязанной ссылки становится первым параметром.

### Память
- Каждый экземпляр внутреннего, локального и анонимного класса хранит `this$0` — внешний экземпляр. Долгоживущий слушатель или запись кеша, созданные как внутренний класс, удерживают весь внешний объект ([[garbage-collection]]). Делай вложенные классы `static`, если им не нужно внешнее состояние; это Effective Java, item 24, и частое предупреждение IDE.

## Пример
```java
public class RetryPolicy {
    private final int maxAttempts;
    private final Duration backoff;

    public RetryPolicy(int maxAttempts, Duration backoff) { this.maxAttempts = maxAttempts; this.backoff = backoff; }

    // Статический вложенный: внешнее состояние не нужно, просто пространство имён
    public record Attempt(int number, Throwable failure) {}

    // Внутренний: нужны maxAttempts и backoff этой политики
    private final class Loop implements Iterator<Duration> {
        private int attempt = 0;
        public boolean hasNext() { return attempt < maxAttempts; }
        public Duration next() { return backoff.multipliedBy(1L << attempt++); }   // RetryPolicy.this.backoff
    }

    public Iterator<Duration> delays() { return new Loop(); }

    // Лямбда там, где достаточно функционального интерфейса; 'this' здесь — это RetryPolicy
    public Runnable wrap(Runnable task, Consumer<Attempt> onFailure) {
        return () -> {
            int n = 0;
            for (Iterator<Duration> it = delays(); ; ) {
                try { task.run(); return; }
                catch (RuntimeException e) {
                    onFailure.accept(new Attempt(++n, e));
                    if (!it.hasNext()) throw e;
                    LockSupport.parkNanos(it.next().toNanos());
                }
            }
        };
    }
}
```

## Подводные камни
- Внутренние классы без `static` в сущностях, DTO для Jackson или вложенных тестах JUnit падают с «no default constructor» или «cannot instantiate», потому что у фреймворка нет внешнего экземпляра, который можно передать.
- Сериализация объекта с полем анонимного или внутреннего класса сериализует и внешний экземпляр либо падает с `NotSerializableException`.
- Анонимному классу, захватывающему переменную цикла, нужна свежая effectively final копия на каждой итерации; классический баг «все обработчики видят последнее значение» возникает, когда вместо этого захватывается изменяемое поле.
- Связанные заметки: [[functional-interfaces]], [[modifiers-final-static-access]], [[structural-patterns]] (анонимные реализации Adapter/Strategy).
