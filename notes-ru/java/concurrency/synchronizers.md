## Кратко
Синхронизаторы координируют, *когда* потоки продолжают работу, а не защищают данные. `CountDownLatch` позволяет потокам ждать, пока счётчик не дойдёт до нуля (одноразово). `CyclicBarrier` позволяет группе потоков дождаться друг друга в определённой точке и затем продолжить вместе (многоразово). `Semaphore` ограничивает, сколько потоков может одновременно находиться внутри секции.

## Основное
### CountDownLatch
- Создаётся со счётчиком. Ожидающие потоки вызывают `await()`; рабочие потоки вызывают `countDown()`. Когда счётчик доходит до нуля, все ожидающие продолжают.
- Одноразовый: счётчик нельзя сбросить. Типичное применение: «дождаться, пока N сервисов инициализируются», или в тестах: «запустить всех рабочих одновременно».

### CyclicBarrier
- Создаётся с числом участников и необязательным действием барьера. Каждый поток вызывает `await()`, когда доходит до барьера; когда все участники на месте, действие выполняется один раз, и все потоки продолжают.
- Многоразовый: автоматически сбрасывается после каждого срабатывания. Типичное применение: поэтапные параллельные алгоритмы (фаза вычисления, затем слияние, затем следующая итерация). `Phaser` — более гибкая версия с динамическим числом участников.

### Semaphore
- Набор разрешений (permits). `acquire()` блокируется, пока не освободится разрешение, `release()` его возвращает. С одним разрешением это мьютекс, который может освободить любой поток (в отличие от блокировки).
- Типичное применение: ограничение доступа к пулу из N ресурсов, ограничение числа одновременных вызовов внешнего API.

## Пример
```java
// Запустить 10 рабочих ровно в один момент и дождаться завершения всех
CountDownLatch start = new CountDownLatch(1);
CountDownLatch done  = new CountDownLatch(10);
for (int i = 0; i < 10; i++) {
    pool.submit(() -> {
        start.await();      // все ждут здесь
        doWork();
        done.countDown();
        return null;
    });
}
start.countDown();          // старт
done.await(30, TimeUnit.SECONDS);
```

## Подводные камни
- `countDown()`, пропущенный из-за исключения, оставляет ожидающих висеть; помещай его в `finally`.
- `await()` без таймаута в боевом коде — скрытое зависание; всегда ограничивай его.
- `CyclicBarrier` ломается, если какой-либо участник прерван или вышел по таймауту; остальные получают `BrokenBarrierException`.
