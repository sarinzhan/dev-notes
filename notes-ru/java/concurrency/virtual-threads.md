## Кратко
Виртуальные потоки (virtual threads) — дешёвые потоки, управляемые JVM и монтируемые на небольшой пул потоков-носителей (carrier, платформенных потоков). Они позволяют классической модели «поток на запрос» масштабироваться до миллионов одновременных блокирующих вызовов без переписывания кода в [[completable-future|асинхронный стиль]].

## Основное
- Preview в Java 19, финальная версия в Java 21 (JEP 444). Виртуальный поток стоит около 1 КБ кучи; платформенный поток резервирует 1–2 МБ стека.
- Платформенные потоки (носители) — это потоки ОС с **вытесняющей** многозадачностью: ОС прерывает поток после его кванта времени, закончил он или нет. Виртуальные потоки **кооперативные**: виртуальный поток выполняется на носителе, пока не заблокируется, затем уступает.
- Жизненный цикл: JVM монтирует виртуальный поток на свободный носитель из `ForkJoinPool` → при блокирующей операции (ввод-вывод, `sleep`, JDBC) он **паркуется**, его стек копируется в кучу, и носитель освобождается → когда приходит результат (данные из сети), JVM снова монтирует его на свободный носитель.
- Создаются через `Thread.ofVirtual().start(r)` или `Executors.newVirtualThreadPerTaskExecutor()`.
- Для работы, ограниченной процессором, не быстрее. Выигрыш — в *пропускной способности блокирующего ввода-вывода*, а не в задержке.
- Spring Boot 3.2+: `spring.threads.virtual.enabled=true` переключает Tomcat и `@Async` на виртуальные потоки.

## Пример
```java
try (var executor = Executors.newVirtualThreadPerTaskExecutor()) {
    List<Future<Profile>> futures = ids.stream()
        .map(id -> executor.submit(() -> client.fetchProfile(id)))
        .toList();
    for (var f : futures) profiles.add(f.get());
} // ждёт все задачи
```

## Подводные камни
- **Прикрепление (pinning)**: блокировка внутри блока `synchronized` или нативного вызова держит носитель занятым. На горячих путях используй `ReentrantLock`. Проверяется через `-Djdk.tracePinnedThreads=full`.
- Реальным ограничением становятся пулы соединений: 10 000 виртуальных потоков всё равно делят 20 соединений HikariCP. См. [[hikaricp-pool-sizing]].
- Не складывай виртуальные потоки в пул. Создавай по одному на задачу.
