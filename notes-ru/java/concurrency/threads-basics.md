## Кратко
**Процесс** — это запущенная программа со своим адресным пространством и ресурсами; **поток** — единица выполнения внутри процесса, разделяющая память этого процесса. Java даёт доступ к платформенным потокам через `Thread`, к работе — через `Runnable` / `Callable`, а к кооперативной остановке — через флаг прерывания.

## Основное
### Процесс и поток
- Процесс: изолированное виртуальное адресное пространство; для общения с другим процессом нужен IPC. Может содержать много потоков.
- Поток: наименьшая единица, которой управляет планировщик ОС; живёт внутри процесса; разделяет его кучу, дескрипторы и данные с другими потоками. Гораздо дешевле процесса, поэтому масштабируются потоками, а не процессами.

### Конкурентность и параллелизм
- **Конкурентность** (concurrency): система обрабатывает несколько задач, переключаясь между ними, возможно на одном ядре. Иллюзия одновременности.
- **Параллелизм** (parallelism): несколько задач выполняются в один и тот же момент на разных ядрах.
- Связанные термины: *многозадачность* (multitasking: один или несколько процессоров жонглируют задачами), *многопроцессорность* (multiprocessing: два и более процессора). *Кооперативная* многозадачность: задача выполняется, пока сама не уступит. *Вытесняющая* (preemptive): планировщик забирает процессор после кванта времени (так работают потоки ОС; кооперативная модель — в [[virtual-threads]]).

### Создание и запуск
- Унаследоваться от `Thread` и переопределить `run()`; или передать `Runnable` (`void run()`) в `new Thread(r)`; или отправить `Callable<V>` (`V call() throws Exception`, Java 5) в executor ([[executors-and-thread-pools]]).
- `start()` просит у ОС новый поток и вызывает в нём `run()`. Прямой вызов `run()` просто выполняет код в текущем потоке. Классика собеседований.
- `Thread.sleep(ms)` приостанавливает текущий поток; при прерывании бросает `InterruptedException`.
- Приоритет: `setPriority(1..10)`, по умолчанию 5. Подсказка планировщику, на практике учитывается редко.
- Потоки-демоны (`setDaemon(true)`) — фоновые помощники; JVM завершается, когда остаются только потоки-демоны. Главный поток сделать демоном нельзя.

### Остановка потока
- `stop()` устарел и небезопасен: он мгновенно убивает поток, оставляя мониторы и соединения в неизвестном состоянии.
- `interrupt()` только выставляет флаг. Целевой поток должен его проверять (`Thread.currentThread().isInterrupted()`), а блокирующие вызовы (`sleep`, `wait`, `join`, блокирующие очереди) бросают `InterruptedException` и **сбрасывают** флаг.
- `Thread.interrupted()` (статический) читает и сбрасывает флаг; `isInterrupted()` читает его без сброса.

### Состояния потока (`Thread.State`)
`NEW` → `RUNNABLE` (готов или выполняется) → `BLOCKED` (ждёт монитор) / `WAITING` (`wait()`, `join()`, `park()`) / `TIMED_WAITING` (то же с таймаутом, `sleep`) → `TERMINATED`.

### ThreadLocal
Даёт каждому потоку собственную копию переменной; другие потоки её не видят. Используется для контекста на запрос (безопасность, транзакции, MDC). С потоками из пула всегда вызывай `remove()` по завершении, иначе следующая задача унаследует устаревшие данные.

## Пример
```java
Thread worker = new Thread(() -> {
    while (!Thread.currentThread().isInterrupted()) {
        try { poll(); Thread.sleep(500); }
        catch (InterruptedException e) {
            Thread.currentThread().interrupt(); // восстановить флаг, затем выйти
            return;
        }
    }
});
worker.start();
// позже
worker.interrupt();
worker.join();
```

## Подводные камни
- Проглатывание `InterruptedException` пустым catch делает поток неостанавливаемым. Либо пробрасывай дальше, либо заново выставляй флаг, как выше.
- Создавать потоки вручную в сервисе почти всегда неправильно; используй executor.
- Состояния потоков сбивают с толку: поток, ожидающий ввода-вывода, с точки зрения JVM находится в `RUNNABLE`.
