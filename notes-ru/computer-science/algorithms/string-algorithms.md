## Кратко
Большинство задач на строки — это замаскированные задачи на массивы: массивы частот (`int[26]` или `int[128]`), два указателя и скользящие окна ([[two-pointers-and-sliding-window]]), хеш-таблицы. Два специализированных алгоритма стоит знать на уровне идеи: **KMP** находит образец за O(n + m) с помощью таблицы отказов вместо возврата назад, а **скользящий хеш** (rolling hash, Рабин — Карп) превращает сравнение подстрок в сравнение целых чисел за O(1), на чём в реальных системах также построены дедупликация и разбиение на чанки. Особенности Java (неизменяемость, пул строк, `StringBuilder`) описаны в [[strings-and-string-pool]].

## Основное

### Трюки с частотами
- Проверка на анаграмму: посчитать символы через `int[26]`, сравнить массивы. O(n) вместо сортировки за O(n log n).
- Группировка анаграмм: ключ = отсортированная строка или массив частот, закодированный в строку; `HashMap<String, List<String>>`.
- Первый уникальный символ, самый частый, «можно ли составить из журнала»: один проход с подсчётом.
- Палиндром: два указателя с концов; является ли какая-то перестановка палиндромом: не более одного нечётного счётчика.
- Индексация через `char - 'a'` — только когда алфавит гарантирован; для произвольного Unicode используй `HashMap<Integer, Integer>` по кодовым точкам ([[text-encodings-and-unicode]]).

### Поиск подстроки
| Алгоритм | Время | Идея | Применение |
|---|---|---|---|
| наивный | O(n · m) | сравнение на каждом смещении | крошечные входы; `String.indexOf` — это он с быстрым циклом |
| KMP | O(n + m) | префикс-функция `lps[i]` = длина наибольшего собственного префикса `p[0..i]`, который также является суффиксом; при несовпадении переход к `lps[j-1]` вместо начала заново | гарантированно линейный, потоковый вход |
| Рабин — Карп (скользящий хеш) | O(n + m) в среднем | хеш окна обновляется за O(1) при сдвиге; при совпадении хеша — проверка | несколько образцов, плагиат/дедупликация, двумерный поиск |
| Z-функция | O(n + m) | `z[i]` = длина наибольшего совпадения `s[i..]` с префиксом | та же ниша, что у KMP, некоторым проще писать |
| Бойер — Мур | сублинейный на практике | пропуски по последнему символу | `grep`, редакторы |
| Ахо — Корасик | O(n + суммарная длина образцов + число совпадений) | trie плюс ссылки отказов ([[tries]]) | много образцов сразу (фильтры нецензурной лексики, сканеры логов) |

- Таблица `lps` из KMP отвечает и на другие вопросы: кратчайший палиндром дописыванием в начало, наименьшая повторяющаяся единица (`n - lps[n-1]` делит `n`) и проверка поворота строки (`s2` в `s1 + s1`).
- `String.indexOf` в JDK — настроенный наивный поиск с интринсиками; для одного поиска в прикладном коде просто вызывай его.

### Скользящий хеш
- Полиномиальный хеш `h(s) = Σ s[i] · B^(m-1-i) mod M`. Сдвиг на один символ: `h' = (h - s[out] · B^(m-1)) · B + s[in]`, всё по модулю M.
- Используй большой простой модуль или `long` с естественным переполнением плюс случайное основание; используй **два** модуля, если коллизии должны быть пренебрежимо редкими, или всегда проверяй совпадение сравнением настоящей подстроки.
- Применения помимо поиска: самая длинная повторяющаяся подстрока (бинарный поиск по длине + скользящий хеш, [[binary-search-and-variants]]), разбиение на чанки по содержимому в инструментах резервного копирования и дедупликации (rsync, restic), хеширование в фильтре Блума ([[bloom-filters-and-probabilistic]]).

### Другие частые вопросы
- Наибольший общий префикс: вертикальный проход или сортировка и сравнение первой и последней строки.
- Самая длинная палиндромная подстрока: расширение вокруг каждого центра, O(n²); алгоритм Манакера — O(n), но его редко ждут.
- Редакционное расстояние, LCS: [[dynamic-programming]].
- Word break, автодополнение, подсчёт префиксов: [[tries]].
- Разбор и валидация (`isNumber`, сбалансированные теги): конечный автомат или стек ([[stack-and-monotonic-stack]]).
- Сжатие строк, кодирование длин серий (run-length encoding), `StringBuilder` с подсказкой ёмкости.

### Проверка реальностью в бэкенде
- Хеширование строки — O(длины): поиск в `HashMap<String, …>` не бесплатен для длинных ключей; Java кеширует `String.hashCode()` после первого вызова, поэтому повторные поиски по тому же экземпляру дешёвы ([[hashmap-internals]]).
- `LIKE '%foo%'` в Postgres — наивный проход, если не использовать триграммный GIN-индекс, который является n-граммным вариантом трюков с частотами ([[postgres-indexes]]).
- Полнотекстовый поиск токенизирует, нормализует и строит инвертированный индекс; `tsvector` и Elasticsearch — продакшн-ответ на «найти документы, содержащие» ([[postgres-jsonb-and-full-text]], [[elasticsearch-basics]]).

## Пример
```java
// KMP: все начальные индексы `pattern` в `text`, O(n + m).
static List<Integer> kmpSearch(String text, String pattern) {
    int[] lps = prefixFunction(pattern);
    List<Integer> hits = new ArrayList<>();
    for (int i = 0, j = 0; i < text.length(); i++) {
        while (j > 0 && text.charAt(i) != pattern.charAt(j)) j = lps[j - 1];   // откатываемся, а не начинаем заново
        if (text.charAt(i) == pattern.charAt(j)) j++;
        if (j == pattern.length()) {                                           // полное совпадение, заканчивающееся в i
            hits.add(i - j + 1);
            j = lps[j - 1];                                                     // продолжаем ради перекрытий
        }
    }
    return hits;
}

// lps[i] = длина наибольшего собственного префикса pattern[0..i], который также является его суффиксом.
static int[] prefixFunction(String p) {
    int[] lps = new int[p.length()];
    for (int i = 1, len = 0; i < p.length(); ) {
        if (p.charAt(i) == p.charAt(len)) lps[i++] = ++len;
        else if (len > 0) len = lps[len - 1];
        else lps[i++] = 0;
    }
    return lps;
}
```
`prefixFunction("abab")` даёт `[0, 0, 1, 2]`; поиск в `"ababab"` возвращает `[0, 2]`, потому что откат сохраняет перекрытие.

## Подводные камни
- `s += c` в цикле — O(n²); `String.substring` копирует начиная с Java 7u6, поэтому многократная рекурсия по подстрокам тоже O(n²).
- `char` — это единица UTF-16, а не символ: эмодзи и многие письменности занимают два `char`; `length()`, `charAt` и разворот строки их ломают ([[text-encodings-and-unicode]]).
- Скользящий хеш без проверки или с маленьким модулем даёт ложные совпадения; интервьюер обязательно спросит про коллизии.
- Сравнение строк через `==` или сортировка через `compareTo`, когда нужна сортировка с учётом локали.
- Регулярные выражения для структурного разбора больших входов: катастрофический возврат (catastrophic backtracking) на образцах вроде `(a+)+` превращает O(n) в экспоненту; самописный проход или стек безопаснее ([[owasp-top-10-for-backend]] упоминает ReDoS).
- Связанные заметки: [[tries]], [[hash-tables]], [[two-pointers-and-sliding-window]], [[interview-problem-patterns]].
