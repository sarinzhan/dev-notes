## Кратко
Бинарный поиск (binary search) на каждом шаге делит пополам **монотонную** область поиска: O(log n) вместо O(n). Классическая форма ищет значение в отсортированном массиве, но полезная на собеседовании форма — **версия с предикатом**: найти первый индекс, где булево условие переключается с false на true. Один этот шаблон даёт нижнюю границу, верхнюю границу, «поиск по ответу» (минимальная вместимость, наименьшее допустимое время) и поиск в повёрнутом массиве без переписывания цикла каждый раз.

## Основное

### Инвариант, а не код
- Держи полуоткрытый диапазон `[lo, hi)`, про который известно, что ответ внутри, и предикат `p(i)`, который ложен на префиксе и истинен на остальном (монотонный). Каждый шаг проверяет `mid` и сдвигает либо `lo`, либо `hi`; цикл заканчивается, когда `lo == hi`, — это первый индекс со значением `true` (или `n`, если такого нет).
- Всё остальное — выбор предиката:

| Задача | Отсортированный массив `a`, предикат `p(i)` | Результат |
|---|---|---|
| нижняя граница (первый `>= x`) | `a[i] >= x` | точка вставки; равна `x`, если он есть |
| верхняя граница (первый `> x`) | `a[i] > x` | `upper - lower` = количество `x` |
| точный поиск | нижняя граница, затем проверка `a[lo] == x` | индекс или «не найдено» |
| последний `<= x` | верхняя граница − 1 | floor |
| повёрнутый отсортированный массив (без дубликатов) | `a[i] <= a[n-1]` | индекс минимума; затем обычный поиск в правой половине |
| пиковый элемент | `a[i] > a[i+1]` | какой-то локальный максимум |

### Поиск по ответу
- Когда вопрос звучит как «минимальное X, при котором что-то выполнимо», и выполнимость монотонна по X (если вместимость 10 подходит, то и 11 подходит), делай бинарный поиск по X и пиши линейную проверку `feasible(X)`. Итого O(n log range).
- Типичные формулировки: доставить посылки за D дней (вместимость), Коко ест бананы (скорость), разбить массив на k частей, минимизируя наибольшую сумму, минимальное время, за которое воркеры закончат, наименьший размер пачки, при котором Kafka-консьюмер укладывается в бюджет `max.poll.interval.ms`.

### Где встречается в реальности
- `Arrays.binarySearch` и `Collections.binarySearch` возвращают `-(insertionPoint) - 1`, когда ключа нет; `TreeMap.ceilingKey/floorKey` — обходы дерева с той же семантикой ([[trees-and-bst]]).
- B-tree-индексы баз данных делают бинарный поиск внутри каждой страницы и спуск по дереву между страницами ([[database-indexes]]).
- Kafka-консьюмеры используют бинарный поиск по индексному файлу, чтобы найти позицию в файле для offset ([[kafka-architecture]]).
- Git bisect: бинарный поиск по коммитам первого плохого; предикат «сломан ли этот коммит» должен быть монотонным, поэтому нестабильные (flaky) тесты ломают bisect.
- Поиск по числам с плавающей точкой (например, квадратный корень с точностью 1e-9): цикл с фиксированным числом итераций (100) вместо `while (lo < hi)`.

### Сложность
| Вариант | Время | Память |
|---|---|---|
| Поиск в массиве | O(log n) | O(1) |
| Поиск по ответу | O(n log range) | O(1) |
| Повёрнутый массив | O(log n) для различных значений, O(n) в худшем случае с дубликатами | O(1) |

## Пример
```java
// Один шаблон для всех вариантов: первый индекс в [lo, hi), где предикат истинен.
static int firstTrue(int lo, int hi, IntPredicate p) {
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;      // никогда не (lo + hi) / 2: переполнение около Integer.MAX_VALUE
        if (p.test(mid)) hi = mid;         // ответ — mid или левее
        else lo = mid + 1;                 // ответ строго правее
    }
    return lo;                             // == hi, если ничего не истинно
}

static int lowerBound(int[] a, int x) { return firstTrue(0, a.length, i -> a[i] >= x); }
static int upperBound(int[] a, int x) { return firstTrue(0, a.length, i -> a[i] > x); }

// Поиск по ответу: наименьший размер пачки, чтобы n записей уместились в `maxBatches` пачек,
// где каждая пачка вмещает не более `limit` байт. sizes[] — размеры записей по порядку.
static int minBatchBytes(int[] sizes, int maxBatches) {
    int lo = Arrays.stream(sizes).max().orElse(0);           // должна вместить самую большую запись
    int hi = Arrays.stream(sizes).sum() + 1;                  // одна пачка всегда подходит
    return firstTrue(lo, hi, limit -> batchesNeeded(sizes, limit) <= maxBatches);
}

private static int batchesNeeded(int[] sizes, int limit) {   // жадно, O(n)
    int batches = 1, current = 0;
    for (int s : sizes) {
        if (current + s > limit) { batches++; current = 0; }
        current += s;
    }
    return batches;
}
```

## Подводные камни
- `mid = (lo + hi) / 2` переполняется для массивов больше 2³⁰ элементов; этот баг годами жил в JDK. Используй `lo + (hi - lo) / 2` или `(lo + hi) >>> 1`.
- Ошибка на единицу (off-by-one) из-за смешивания соглашений: закрытого `[lo, hi]` и полуоткрытого `[lo, hi)`; выбери один шаблон и переиспользуй его.
- Поиск по немонотонному предикату «работает» на примере и падает в продакшне: сначала докажи монотонность.
- `Arrays.binarySearch` на неотсортированном массиве возвращает мусор, а не ошибку; на массиве с дубликатами возвращает произвольный подходящий индекс, а не первый.
- Бесконечный цикл, если в ветке else написать `lo = mid` вместо `lo = mid + 1` (при `hi - lo == 1` mid вечно равен lo).
- Связанные заметки: [[sorting-algorithms]] (отсортировать один раз и потом много раз искать бинарно выгоднее повторных линейных проходов), [[two-pointers-and-sliding-window]] — альтернатива за O(n) на отсортированных данных, [[interview-problem-patterns]].
