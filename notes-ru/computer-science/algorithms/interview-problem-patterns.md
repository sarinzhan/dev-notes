## Кратко
Почти любая задача на алгоритмическом собеседовании — это один из примерно двадцати паттернов в костюме. Проверяется умение прочитать **сигнал** в условии (отсортированный вход, «непрерывный», «k-й наибольший», «минимальное число шагов», «все комбинации») и сопоставить его с паттерном и целевой сложностью до написания кода. Эта заметка — таблица для поиска; каждая строка ссылается на заметку с шаблоном и подводными камнями. Используй её в первые две минуты над задачей, а затем вслух назови паттерн и сложность, прежде чем писать код.

## Основное

### Сигнал → паттерн
| Сигнал в условии задачи | Паттерн | Целевая сложность | Заметка |
|---|---|---|---|
| отсортированный массив или список; пара/тройка с заданной суммой; палиндром; «на месте» | два указателя | O(n) после сортировки | [[two-pointers-and-sliding-window]] |
| «непрерывный подмассив / подстрока», «самое длинное / короткое окно со свойством», «не более k различных» | скользящее окно | O(n) | [[two-pointers-and-sliding-window]] |
| сумма подмассива равна k при наличии отрицательных; многократная «сумма диапазона [l, r]»; обновления диапазонов, затем один запрос | префиксные суммы / разностный массив | O(n) | [[prefix-sums-and-intervals]] |
| интервалы: слияние, вставка, пересечение, «переговорные комнаты», пиковая одновременность | сортировка по началу или концу + проход / заметающая прямая | O(n log n) | [[prefix-sums-and-intervals]] |
| отсортированный вход и «найти первый / последний / минимальный X такой, что...»; монотонная выполнимость; повёрнутый отсортированный массив | бинарный поиск / поиск по ответу | O(log n), O(n log range) | [[binary-search-and-variants]] |
| связный список: середина, цикл, k-й с конца, слияние отсортированных | быстрый/медленный указатели, фиктивная голова | O(n), память O(1) | [[linked-lists]] |

| «следующий больший / меньший элемент», «дней до», площади гистограммы, задача о дождевой воде | монотонный стек | O(n) | [[stack-and-monotonic-stack]] |

| «k-й наибольший», «top k», «k ближайших», слияние k отсортированных списков, скользящая медиана, планирование задач по приоритету | куча / очередь с приоритетом | O(n log k) | [[heaps-and-priority-queues]] |
| «k самых частых» | хеш-таблица + куча или блочная сортировка | O(n log k) / O(n) | [[heaps-and-priority-queues]] |
| поиск по префиксу, автодополнение, словарь с подстановочными символами, word search II | префиксное дерево (trie) | O(L) на операцию | [[tries]] |
| дерево: глубина, сумма пути, диаметр, LCA, инвертирование, сериализация | рекурсивный DFS по дереву | O(n) | [[trees-and-bst]] |

### Ограничение → допустимая сложность
| n | Самая быстрая допустимая | Типичные паттерны |
|---|---|---|
| ≤ 12 | O(n!) | перестановки, перебор с возвратом |
| ≤ 20–25 | O(2ⁿ · n) | перебор / DP по битовым маскам |
| ≤ 500 | O(n³) | DP по интервалам, Флойд — Уоршелл |
| ≤ 5 000 | O(n²) | двумерное DP, вложенные циклы |
| ≤ 10⁶ | O(n log n) | сортировка, куча, бинарный поиск, одномерное DP |
| ≤ 10⁸ | O(n) | один проход, два указателя, префиксные суммы |
| больше / потоковые данные | O(log n) или O(1) на элемент | хеширование, вероятностные структуры |
Подробности в [[big-o-and-complexity]].

### Пятиминутный порядок действий
1. Перескажи задачу и типы входа/выхода; спроси про размеры, дубликаты, отсортированность, отрицательные числа, пустой вход.
2. Найди сигнал в таблице выше и назови паттерн и целевую сложность.
3. Опиши полный перебор одним предложением с его сложностью, затем улучшенную идею.
4. Напиши код по шаблону паттерна; вспомогательные функции держи маленькими.
5. Прогони один обычный и один граничный случай (пусто, один элемент, все равны, максимальный размер) и назови время и память.

Интервьюеры выясняют, *почему* паттерн применим (монотонность, неотрицательные веса, аргумент обмена, перекрывающиеся подзадачи), и проверяют детали Java, которые просачиваются в алгоритмический код: `ArrayDeque` вместо `Stack`, сравнение `Integer` по ссылке, переполнение `int`, `PriorityQueue` без `decreaseKey`, неопределённый порядок `HashMap` ([[collections-framework]], [[hashmap-internals]]).

## Пример
```java
// Порядок действий для задачи «k самых частых ошибок абонентов за последний час»:
// сигнал: «k самых частых» -> подсчёт в хеш-таблице + min-куча размера k -> O(n log k).
static List<String> topKErrors(List<String> errorCodes, int k) {
    Map<String, Integer> count = new HashMap<>();
    for (String code : errorCodes) count.merge(code, 1, Integer::sum);          // O(n)

    PriorityQueue<Map.Entry<String, Integer>> heap =
            new PriorityQueue<>(Map.Entry.comparingByValue());                  // min-куча по количеству
    for (var e : count.entrySet()) {
        heap.offer(e);
        if (heap.size() > k) heap.poll();                                       // вытесняем наименьший, O(log k)
    }
    List<String> result = new ArrayList<>();
    while (!heap.isEmpty()) result.add(heap.poll().getKey());
    Collections.reverse(result);                                                // самые частые первыми
    return result;
}
```

## Подводные камни
- Бросаться писать код, не назвав паттерн; неправильный паттерн стоит больше времени, чем минута размышлений.
- Выбирать паттерн только по поверхностным словам: «подмассив» с отрицательными числами — это префиксные суммы, а не скользящее окно; «кратчайший путь» с весами — это Дейкстра, а не BFS.
- Забывать проверить предусловие паттерна (отсортировано, монотонно, неотрицательно, DAG).
- Переусложнение: `TreeMap` там, где хватило бы сортировки и прохода, дерево отрезков там, где достаточно префиксной суммы.
- Не назвать сложность в конце; интервьюеры это отмечают, даже если код правильный.
