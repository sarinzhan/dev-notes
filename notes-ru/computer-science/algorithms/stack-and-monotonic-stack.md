## Кратко
Стек решает всё, где есть **вложенность** или семантика **«последний незакрытый»**: сбалансированные скобки, вычисление выражений, отмена действий, нормализация путей, кадры вызовов. **Монотонный стек** (monotonic stack) держит элементы отсортированными (по возрастанию или убыванию от дна к вершине), выталкивая перед добавлением всё, что нарушает порядок; он отвечает на вопросы «следующий больший / предыдущий меньший элемент» для каждого индекса суммарно за O(n) и лежит в основе семейства задач о наибольшем прямоугольнике в гистограмме и daily temperatures. Сама структура данных стека и очереди описана в [[stacks-and-queues]]; эта заметка — про алгоритмы.

## Основное

### Классические задачи на стек
| Задача | Идея |
|---|---|
| сбалансированные скобки | открывающую класть в стек, на закрывающей извлекать и проверять соответствие; корректно тогда и только тогда, когда в конце стек пуст |
| вычисление RPN / инфиксной записи через сортировочную станцию (shunting-yard) | стек операндов и стек операторов; извлекать, пока приоритет вершины ≥ текущего |
| упрощение пути (`/a/./b/../c`) | разбить по `/`, класть имена, извлекать на `..` |
| min-стек (`getMin` за O(1)) | второй стек текущих минимумов или хранить пары `(value, minSoFar)` |
| раскодирование вложенных строк `3[a2[c]]` | стек счётчиков и стек строк, разрешать на `]` |
| простой калькулятор со скобками | на `(` класть текущий результат и знак, на `)` извлекать |
| итеративный DFS / обход дерева | явный стек заменяет рекурсию ([[recursion-and-backtracking]]) |

- Глубина вложенности равна размеру стека; стек вызовов JVM — та же структура ([[stack-vs-heap-memory]]).
- В Java в качестве стека используй `ArrayDeque`; `java.util.Stack` — синхронизированный устаревший подкласс `Vector` ([[collections-framework]]).

### Монотонный стек
- Инвариант: перед тем как положить `x`, вытолкни каждую вершину `t`, для которой `x` сделал бы последовательность немонотонной. Вытолкнутый `t` только что нашёл свой ответ: `x` — первый элемент справа от него, который больше (или меньше). У элементов, оставшихся в стеке в конце, такого элемента нет.
- Каждый индекс кладётся один раз и выталкивается не более одного раза, поэтому весь проход — O(n), несмотря на внутренний цикл ([[big-o-and-complexity]]).

| Вопрос | Порядок в стеке (дно → вершина) | Условие выталкивания |
|---|---|---|
| следующий больший элемент справа | убывающий | `a[i] > a[top]` |
| следующий меньший справа | возрастающий | `a[i] < a[top]` |
| предыдущий больший слева | убывающий | то же, ответ — новая вершина после выталкивания |
| daily temperatures (дней до потепления) | убывающий | `t[i] > t[top]`, ответ `i - top` |
| наибольший прямоугольник в гистограмме | возрастающий | при выталкивании ширина = `i - newTop - 1`, площадь = `height[popped] * width` |
| задача о дождевой воде | убывающий | при выталкивании посчитать воду, ограниченную новой вершиной и `i` |
| stock span / сумма минимумов подмассивов | возрастающий | подсчёт вкладов: каждый элемент — минимум `left * right` подмассивов |
| удалить k цифр, чтобы получить наименьшее число | возрастающий | выталкивать, пока `top > digit` и `k > 0` |

- Храни **индексы**, а не значения: почти всегда нужны расстояние или ширина.
- Кольцевые массивы (следующий больший в кольце): проходи `i` от 0 до 2n−1 и используй `i % n`.
- Та же идея с деком, из которого извлекают с обоих концов, даёт **максимум в скользящем окне** за O(n): держи индексы убывающими по значению, выбрасывай передний, когда он выходит из окна ([[two-pointers-and-sliding-window]]).

### Где встречается вне собеседований
- Парсеры и шаблонизаторы (сопоставление скобок, приоритет операторов), валидаторы JSON.
- Анализ гистограммы задержек: наибольший прямоугольник = самый длинный период, когда задержка держалась выше порога, взвешенный по его высоте.
- Управление offset Kafka-консьюмера в виде «наибольшего непрерывного обработанного offset» использует монотонную структуру, чтобы найти следующий пропуск.

### Сложность
| Паттерн | Время | Память |
|---|---|---|
| сопоставление скобок, RPN | O(n) | O(n) в худшем случае (все открывающие) |
| проход монотонным стеком | O(n) | O(n) |
| максимум в скользящем окне (дек) | O(n) | O(k) |

## Пример
```java
// Для каждого дня — сколько дней до того, как будет зафиксирована строго большая задержка p99.
// 0, если никогда. Монотонно убывающий стек индексов. Время O(n), память O(n).
static int[] daysUntilHigher(int[] p99) {
    int n = p99.length;
    int[] answer = new int[n];
    Deque<Integer> stack = new ArrayDeque<>();        // индексы; значения строго убывают от дна к вершине
    for (int i = 0; i < n; i++) {
        while (!stack.isEmpty() && p99[i] > p99[stack.peek()]) {
            int j = stack.pop();                       // p99[i] — первое большее значение после j
            answer[j] = i - j;
        }
        stack.push(i);
    }
    return answer;                                     // у индексов, оставшихся в стеке, остаётся 0
}

// Сбалансированные скобки: разминка, которую до сих пор спрашивают на каждом собеседовании.
static boolean balanced(String s) {
    Deque<Character> st = new ArrayDeque<>();
    for (char c : s.toCharArray()) {
        switch (c) {
            case '(', '[', '{' -> st.push(c);
            case ')' -> { if (st.isEmpty() || st.pop() != '(') return false; }
            case ']' -> { if (st.isEmpty() || st.pop() != '[') return false; }
            case '}' -> { if (st.isEmpty() || st.pop() != '{') return false; }
            default -> {}
        }
    }
    return st.isEmpty();
}
```

## Подводные камни
- Класть значения вместо индексов, а потом не иметь возможности посчитать ширину или расстояние.
- Использовать `>=` там, где нужно `>` (или наоборот), в условии выталкивания; это меняет обработку равных элементов и ломает подсчёт в «сумме минимумов подмассивов» (дубликаты должны учитываться ровно один раз: строгое сравнение с одной стороны и нестрогое с другой).
- Забыть проход с ограничителем (sentinel) в задачах на гистограмму: добавь столбец высоты 0 (или опустоши стек после цикла), чтобы обработать оставшиеся столбцы.
- `Deque<Integer>` с `stack.pop() != p99[...]` сравнивает упакованные `Integer` по ссылке при значениях больше 127 ([[casting-and-autoboxing]]); сравнивай `int`, как в примере.
- `java.util.Stack.peek()` на пустом стеке бросает `EmptyStackException`; `ArrayDeque.peek()` возвращает `null`, а `pop()` бросает `NoSuchElementException`. Сначала проверяй `isEmpty()`.
