## Кратко
Оба паттерна превращают O(n²)-проход «посмотреть каждую пару / каждый подмассив» в O(n), двигая индексы **монотонно**: они только продвигаются вперёд, поэтому общий объём работы ограничен длиной массива. **Два указателя** (two pointers) идут с обоих концов (или с двумя скоростями) по отсортированным или связным данным; **скользящее окно** (sliding window) хранит непрерывный диапазон `[left, right]` плюс текущую сводку (сумма, map счётчиков, число различных) и расширяет или сужает его, когда нарушается условие. Это два самых частых паттерна на собеседованиях для массивов и строк.

## Основное

### Два указателя
| Вариант | Сигнал в задаче | Пример |
|---|---|---|
| с противоположных концов | отсортированный массив, пара с заданной суммой/разностью, проверка на палиндром, контейнер с наибольшим количеством воды | `lo` и `hi` движутся навстречу |
| в одном направлении, чтение/запись | удалить дубликаты или нули на месте, разбиение | `write` отстаёт от `read` |
| быстрый/медленный | середина связного списка, обнаружение цикла (Флойд), k-й с конца | `fast` делает два шага |
| два массива | слияние отсортированных массивов, пересечение отсортированных списков | по индексу на каждый массив |

- Почему это работает на отсортированных данных: если `a[lo] + a[hi] < target`, то никакая пара с `a[lo]` и меньшим `hi` тоже не подойдёт, поэтому `lo++` безопасен. Это **аргумент обмена** ([[greedy-algorithms]]).
- Неотсортированные данные: сначала отсортировать (O(n log n), [[sorting-algorithms]]) или использовать хеш-множество за O(n) с памятью O(n) ([[hash-tables]]). Three-sum — это сортировка + два указателя внутри цикла, O(n²).
- Быстрый/медленный указатели на связных списках — единственный способ найти цикл или середину с памятью O(1) ([[linked-lists]]).

### Скользящее окно
| Тип окна | Сигнал | Форма кода |
|---|---|---|
| фиксированного размера k | «каждые k подряд», скользящее среднее, максимальная сумма k элементов | прибавить `a[right]`, вычесть `a[right - k]` |
| переменное, сужать, пока невалидно | самая длинная подстрока без повторов, самый длинный подмассив с суммой ≤ S | расширять вправо; пока невалидно — двигать left |
| переменное, сужать, пока валидно | минимальное окно, содержащее все символы, наименьший подмассив с суммой ≥ S | расширять вправо; пока валидно — записать и двигать left |
| окно со счётчиками | анаграммы в строке, «не более k различных» | `int[26]` или `HashMap<Character,Integer>` со счётчиком `distinct` |

- Предусловие: валидность должна быть **монотонной** по размеру окна (расширение может только сделать окно «сумма ≤ S» менее валидным, но никогда более). Отрицательные числа ломают это для окон на основе суммы; вместо этого используй [[prefix-sums-and-intervals]] с хеш-таблицей.
- «Ровно k различных» = «не более k» − «не более k−1»: два прохода скользящим окном.
- Максимум/минимум по скользящему окну за O(n) требует монотонного дека ([[stack-and-monotonic-stack]]).

### Где встречается в бэкенд-работе
- Ограничение частоты (rate limiting) со скользящим логом или счётчиком скользящего окна ([[rate-limiting]]).
- Потоковая агрегация по последним N событиям (p99 за последнюю минуту) в пайплайне метрик ([[otel-metric-types]]).
- Слияние двух отсортированных партиций Kafka по timestamp — это проход указателями по двум массивам.

### Сложность
Оба паттерна: время O(n), потому что каждый указатель суммарно сдвигается не более n раз; дополнительная память O(1) или O(k) для map счётчиков с k различными ключами. Внутренний `while` не делает сложность O(n²): `left` может продвинуться не более n раз за весь прогон ([[big-o-and-complexity]]).

## Пример
```java
// Переменное скользящее окно: самая длинная серия подряд идущих запросов от одного клиента,
// суммарный объём payload которых остаётся меньше `limitBytes`. Возвращает [start, endExclusive).
static int[] longestUnderLimit(int[] bytes, long limitBytes) {
    int left = 0, bestLeft = 0, bestLen = 0;
    long sum = 0;
    for (int right = 0; right < bytes.length; right++) {
        sum += bytes[right];                               // расширяем
        while (sum > limitBytes && left <= right) {        // сужаем, пока снова не станет валидным
            sum -= bytes[left++];
        }
        if (right - left + 1 > bestLen) {                  // записываем
            bestLen = right - left + 1;
            bestLeft = left;
        }
    }
    return new int[]{bestLeft, bestLeft + bestLen};
}

// Два указателя на отсортированных данных: есть ли пара цен тарифов, дающая в сумме ровно `target`?
static boolean hasPairSum(int[] sortedPrices, int target) {
    int lo = 0, hi = sortedPrices.length - 1;
    while (lo < hi) {
        int s = sortedPrices[lo] + sortedPrices[hi];
        if (s == target) return true;
        if (s < target) lo++; else hi--;
    }
    return false;
}
```

## Подводные камни
- Применять скользящее окно на основе суммы к массивам с отрицательными числами: сужение больше не уменьшает сумму монотонно, и ответ получается неправильным. Исправление — префиксные суммы плюс map.
- Обновлять сводку окна после сдвига указателя, а не до него (ошибка на единицу в `sum -= a[left++]`).
- Использовать `HashMap<Character,Integer>` там, где хватило бы `int[128]`; это в десять раз медленнее и засоряет код упаковкой ([[casting-and-autoboxing]]).
- Записывать лучший ответ вне цикла или только когда окно валидно в задачах «сужать, пока валидно»: минимальное окно записывается *внутри* цикла сужения.
- Два указателя на неотсортированных данных без предварительной сортировки; аргумент обмена больше не работает.
- Связанные заметки: [[prefix-sums-and-intervals]] — для немонотонных случаев, [[string-algorithms]] — трюки с массивами частот, [[interview-problem-patterns]].
