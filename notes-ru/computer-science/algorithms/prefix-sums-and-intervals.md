## Кратко
Массив **префиксных сумм** (prefix sums) отвечает на любой запрос суммы диапазона за O(1) после предобработки за O(n): `sum(l, r) = P[r+1] - P[l]`. Обратная к нему структура, **разностный массив** (difference array), применяет обновление диапазона за O(1) и восстанавливает итоговый массив одним проходом префиксных сумм. Задачи на интервалы (слияние, вставка, подсчёт пересечений, переговорные комнаты) сводятся к **сортировке по началу** плюс линейный проход или к **заметающей прямой** (sweep line) по событиям начала/конца с текущим счётчиком. Всё это работает за O(n) после сортировки за O(n log n) и постоянно встречается и на собеседованиях, и в коде биллинга, планирования и мониторинга.

## Основное

### Префиксные суммы
- `P[0] = 0`, `P[i+1] = P[i] + a[i]`. Сумма по диапазону `[l, r]` включительно — `P[r+1] - P[l]`. Используй `long` для префикса, даже если элементы `int`.
- **Подмассив с заданной суммой** (отрицательные допустимы): иди по `i`, храни `HashMap<prefix, firstIndex or count>`; для каждого `P[i]` ищи `P[i] - target`. O(n). Это то, чего не умеет скользящее окно при отрицательных числах ([[two-pointers-and-sliding-window]]).
- Тот же трюк с модулем: в задаче «сумма подмассива делится на k» ключом в map служит `P[i] mod k`.
- Двумерные префиксные суммы: `S[i][j]` = сумма прямоугольника от (0,0); подпрямоугольник — четыре обращения (включения-исключения).
- Префиксный XOR, префиксное произведение (осторожно с нулями), префиксные счётчики символа: та же идея с другим моноидом.
- Мониторинг: счётчик Prometheus — это префиксная сумма по времени; `rate()` — разность по диапазону, делённая на интервал ([[otel-metric-types]]).

### Разностные массивы
- Чтобы прибавить `v` к каждому элементу в `[l, r]`: `D[l] += v; D[r+1] -= v`. После всех обновлений посчитай префиксные суммы `D`, чтобы получить результат. m обновлений на n элементах стоят O(n + m) вместо O(n·m).
- Применение: «car pooling» (загрузка вдоль маршрута), бронирования по дням, пики одновременных соединений по списку сессий `(connectAt, disconnectAt)`.
- Для чередующихся обновлений **и** запросов диапазонов нужно дерево Фенвика или дерево отрезков (O(log n) на каждую операцию); упомяни их, но не реализуй в рамках времени собеседования, если не просят.

### Паттерны для интервалов
| Задача | Подход | Сложность |
|---|---|---|
| слияние пересекающихся интервалов | сортировка по началу; расширить текущий, если `next.start <= cur.end`, иначе выдать | O(n log n) |
| вставка интервала в отсортированный список непересекающихся | скопировать левую часть, слить пересекающуюся середину, скопировать правую | O(n) |
| максимальное число пересекающихся интервалов (meeting rooms II, пик одновременных сессий) | заметающая прямая: события `(+1 at start, −1 at end)`, сортировка, текущий максимум | O(n log n) |
| минимум интервалов для удаления, чтобы не осталось пересечений | сортировка по **концу**, жадно оставлять ([[greedy-algorithms]]) | O(n log n) |
| пересекается ли точка/интервал с каким-либо сохранённым | `TreeMap.floorEntry(start)` и `ceilingEntry` | O(log n) на запрос |
| свободное время между занятыми слотами | слить, затем промежутки между соседними интервалами | O(n log n) |

- Соглашение о полуоткрытых интервалах `[start, end)` снимает двусмысленность «пересекаются ли соприкасающиеся интервалы»; его же используют `tstzrange` в Postgres и `EXCLUDE USING gist`, чтобы запретить пересекающиеся бронирования ([[postgres-indexes]]).
- Разрешение равенства в заметающей прямой: когда времена начала и конца совпадают, для полуоткрытых интервалов сначала обрабатывай концы (сессия, заканчивающаяся в 10:00, не пересекается с начинающейся в 10:00).

### Где встречается в бэкенд-работе
- Биллинг: оплата использования по пересекающимся тарифным периодам — это слияние `[activatedAt, deactivatedAt)` с `[periodStart, periodEnd)`.
- Планирование мощностей по логам сессий: пиковая одновременность через заметающую прямую, p-й перцентиль через префиксные счётчики по гистограмме.
- Планирование и окна SLA ([[slo-sli-and-alerting]]): время в нарушении — суммарная длина слитых интервалов алертов.

## Пример
```java
// Пиковое число одновременно активных eSIM-сессий по парам (start, end), полуоткрытым.
// Заметающая прямая: O(n log n) на сортировку, O(n) на проход.
record Session(long start, long end) {}

static int peakConcurrency(List<Session> sessions) {
    long[][] events = new long[sessions.size() * 2][];
    int k = 0;
    for (Session s : sessions) {
        events[k++] = new long[]{s.start(), +1};
        events[k++] = new long[]{s.end(),   -1};
    }
    // сортировка по времени; при равном времени -1 (конец) обрабатывается раньше +1 (начала)
    Arrays.sort(events, Comparator.<long[]>comparingLong(e -> e[0]).thenComparingLong(e -> e[1]));
    int active = 0, peak = 0;
    for (long[] e : events) {
        active += (int) e[1];
        peak = Math.max(peak, active);
    }
    return peak;
}

// Префиксные суммы: байты, переданные в любом окне [from, to) поминутных счётчиков, O(1) на запрос.
static long[] prefix(int[] perMinute) {
    long[] p = new long[perMinute.length + 1];
    for (int i = 0; i < perMinute.length; i++) p[i + 1] = p[i] + perMinute[i];
    return p;
}
static long bytesBetween(long[] p, int from, int to) { return p[to] - p[from]; }
```

## Подводные камни
- Префиксные суммы в `int` молча переполняются; 2 миллиарда байт набираются после 2 ГБ трафика.
- Ошибка на единицу между `P[r+1] - P[l]` (r включительно) и `P[r] - P[l]` (r не включительно); выбери полуоткрытые интервалы везде.
- Слияние интервалов без предварительной сортировки или сортировка по концу, когда алгоритм предполагает порядок по началу.
- Считать `[1, 5]` и `[5, 8]` пересекающимися или нет в зависимости от файла; сделай соглашение явным в типе (record `Range` с комментарием или `tstzrange` в SQL).
- Использование разностного массива для запросов, чередующихся с обновлениями: каждому запросу понадобится полная перестройка за O(n).
- Связанные заметки: [[two-pointers-and-sliding-window]] — альтернатива для монотонного случая, [[greedy-algorithms]] — планирование интервалов, [[interview-problem-patterns]].
