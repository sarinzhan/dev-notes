## Кратко
Динамическое программирование (dynamic programming, DP) применимо, когда у задачи есть **оптимальная подструктура** (лучший ответ строится из лучших ответов подзадач) и **перекрывающиеся подзадачи** (одна и та же подзадача встречается много раз). Определяется состояние, записывается рекуррентное соотношение, а затем либо рекурсия **мемоизируется** (сверху вниз, top-down), либо таблица заполняется в порядке зависимостей (**табуляция**, снизу вверх, bottom-up). Самое трудное — выбрать состояние; после этого код занимает десять строк. Классические семейства: одномерные последовательности (подъём по лестнице, грабитель домов, LIS), рюкзак (0/1 и неограниченный, размен монет), две последовательности (LCS, редакционное расстояние), пути по сетке, DP по интервалам.

## Основное

### Как распознать DP
- Вопрос требует количества, минимума/максимума или ответа «возможно ли» по множеству выборов, а рекурсия полным перебором экспоненциальна ([[recursion-and-backtracking]]).
- Жадный подход не работает, потому что локально лучший выбор может заблокировать глобально лучший ([[greedy-algorithms]]); размен монет `{1, 3, 4}` на сумму 6 — стандартный контрпример для жадного алгоритма.
- Дерево рекурсии повторяет аргументы. Если `f(i, remaining)` вызывается дважды с одинаковыми значениями — мемоизируй.

### Метод
1. **Состояние**: минимальный набор параметров, который определяет остаток задачи (`i` = позиция, плюс вместимость, предыдущий выбор, сколько использовано и т. д.).
2. **Рекуррентное соотношение**: `dp[state] = combine(dp[smaller states])`, с явно перечисленными вариантами выбора.
3. **Базовые случаи**.
4. **Порядок**: мемоизация сверху вниз получается естественно; снизу вверх порядок циклов должен уважать зависимости.
5. **Где ответ**: `dp[n]`, `max over dp[...]` или `dp[0][n-1]` для DP по интервалам.
6. **Оптимизация памяти**: если `dp[i]` зависит только от `dp[i-1]`, храни две строки (или одну, проходя в обратном порядке для рюкзака 0/1).

### Сверху вниз vs снизу вверх
| | Мемоизация (сверху вниз) | Табуляция (снизу вверх) |
|---|---|---|
| Код | рекурсия плюс кеш (`HashMap` или массив со значением-маркером) | вложенные циклы |
| Вычисляет | только достижимые состояния | все состояния |
| Риск | глубина стека = глубина рекурсии ([[stack-vs-heap-memory]]) | неправильный порядок циклов |
| Оптимизация памяти | трудно | легко (скользящие строки) |
| Когда | пространство состояний разреженное или нерегулярное | пространство состояний — плотная сетка |

### Классические семейства и их состояния
| Семейство | Состояние | Идея рекуррентного соотношения | Время |
|---|---|---|---|
| подъём по лестнице / Фибоначчи / decode ways | `dp[i]` = число способов дойти до i | `dp[i-1] + dp[i-2]` | O(n) |
| грабитель домов / максимальная сумма несмежных | `dp[i]` = лучшее до i | `max(dp[i-1], dp[i-2] + a[i])` | O(n) |
| наибольшая возрастающая подпоследовательность | `dp[i]` = LIS, заканчивающаяся в i | `1 + max dp[j]` для `j < i, a[j] < a[i]`; O(n log n) с patience sorting ([[binary-search-and-variants]]) | O(n²) |
| размен монет (минимум монет / число способов), неограниченный рюкзак | `dp[amount]` | `min(dp[amount - c]) + 1` по монетам | O(amount · coins) |
| рюкзак 0/1, сумма подмножества, разбиение на равные суммы | `dp[i][w]` или одномерный `dp[w]` с обходом в обратном порядке | взять или пропустить предмет i | O(n · W) |
| LCS, редакционное расстояние | `dp[i][j]` по префиксам двух строк | совпадение → диагональ + 1; иначе лучший из соседей | O(n · m) |
| пути по сетке / минимальная сумма пути / уникальные пути с препятствиями | `dp[r][c]` | сверху или слева | O(r · c) |
| word break | `dp[i]` = префикс длины i можно разбить на слова | любой `j < i` с `dp[j]` и словом `s[j..i)` | O(n² · k) |
| DP по интервалам (burst balloons, цепочка матриц, палиндромные подстроки) | `dp[l][r]` | точка разбиения k в `[l, r]` | O(n³) |
| DP по битовым маскам (TSP, распределение задач) | `dp[mask][last]` | добавить один неустановленный бит ([[bit-manipulation]]) | O(2ⁿ · n²) |
| самый длинный путь в DAG | порядок по топологической сортировке | релаксировать рёбра по порядку | O(V + E) |

### Где DP встречается вне собеседований
- Редакционное расстояние в нечётком сопоставлении при поиске ([[elasticsearch-basics]]); `git diff` и JSON patch — варианты LCS.
- Упаковка элементов в пачки ограниченной вместимости в духе рюкзака; планировщики запросов выбирают порядок join с помощью DP по подмножествам таблиц ([[query-planning-and-execution]]).

## Пример
```java
// Минимальное число ваучеров пополнения, чтобы набрать ровно `amount` (неограниченный размен монет).
// Возвращает -1, если невозможно. Снизу вверх, время O(amount * denominations), память O(amount).
static int minVouchers(int[] denominations, int amount) {
    int INF = amount + 1;                              // больше любого допустимого ответа
    int[] dp = new int[amount + 1];
    Arrays.fill(dp, INF);
    dp[0] = 0;                                         // базовый случай: ноль ваучеров для нуля
    for (int a = 1; a <= amount; a++)
        for (int d : denominations)
            if (d <= a && dp[a - d] + 1 < dp[a])       // выбор: последним использовать один ваучер номиналом d
                dp[a] = dp[a - d] + 1;
    return dp[amount] == INF ? -1 : dp[amount];
}
```
Версия сверху вниз — то же соотношение в виде рекурсивного `min(1 + f(amount - d))` с кешем `Map<Integer, Integer>` перед ним. Для «числа способов» вместо «минимума» замени внутреннее условие на `dp[a] += dp[a - d]` и сделай цикл по номиналам **внешним** по отношению к суммам, чтобы считать сочетания, а не перестановки.

## Подводные камни
- Неправильный порядок циклов: подсчёт сочетаний монет с внешним циклом по суммам и внутренним по монетам считает `1+2` и `2+1` отдельно.
- Рюкзак 0/1 с одномерным массивом, обходимым вперёд, использует предмет дважды; обходи `w` от большего к меньшему.
- Использовать `Integer.MAX_VALUE` как «бесконечность» и потом прибавлять к нему 1: переполнение в отрицательное число, которое выигрывает любой `min`. Используй `amount + 1` или проверяй перед сложением.
- Мемо `HashMap<Long, Integer>` с ключом из упакованной пары int: годится, но двумерный массив намного быстрее, когда пространство состояний плотное.
- Мемоизированная рекурсия по `n = 10⁵` состояний может переполнить стек; переведи её в табуляцию.
- Связанные заметки: [[recursion-and-backtracking]] — экспоненциальная отправная точка, [[greedy-algorithms]] — когда DP не нужно, [[big-o-and-complexity]] — псевдополиномиальные оценки (рюкзак — O(n · W), где W — значение, а не размер), [[interview-problem-patterns]].
