## Кратко
Рекурсия решает задачу через решение меньшего экземпляра той же задачи, доверяя вызову вернуть правильный ответ. Каждой рекурсивной функции нужны **базовый случай**, шаг, который **уменьшает входные данные**, и ограничение глубины, потому что каждый вызов занимает кадр стека. **Перебор с возвратом** (backtracking) — это рекурсия по вариантам выбора: выбрать вариант, уйти в рекурсию, отменить выбор. Он перечисляет подмножества, перестановки, сочетания и решения задач удовлетворения ограничений (N ферзей, судоку), а практичным его делает **отсечение** (pruning — раннее отбрасывание частичного выбора).

## Основное

### Как работает вызов
- Каждый вызов кладёт кадр (параметры, локальные переменные, адрес возврата) на стек потока. Стек потока Java по умолчанию — примерно от 512 КБ до 1 МБ, это около 10–20 тысяч простых кадров; более глубокая рекурсия бросает `StackOverflowError` ([[stack-vs-heap-memory]], [[jvm-memory-areas]]).
- JVM **не** делает оптимизацию хвостовых вызовов, поэтому «хвостовая рекурсия» в Java всё равно использует стек O(глубины). Переводи глубокую рекурсию в цикл с явным `ArrayDeque` ([[stacks-and-queues]]); именно так пишется продакшн-DFS по большим графам ([[graph-traversal-bfs-dfs]]).
- Глубина рекурсии на связных структурах: рекурсивный `toString` на списке из 100 тыс. элементов — это баг, а не вопрос стиля ([[linked-lists]]).

### Как спроектировать рекурсивное решение
1. Точно определи, что возвращает `f(args)`.
2. Базовые случаи: наименьший вход с прямым ответом. Отсутствующий или неправильный базовый случай — баг номер один.
3. Рекурсивный случай: вырази `f(n)` через `f(smaller)`; считай, что рекурсивный вызов корректен («прыжок веры»).
4. Проверь, что каждый путь приближает к базовому случаю.
5. Если подзадачи повторяются, мемоизируй или перейди к табуляции ([[dynamic-programming]]).

### Сложность рекурсивного кода
| Форма | Рекуррентное соотношение | Результат | Пример |
|---|---|---|---|
| один вызов, вход уменьшается на 1 | T(n) = T(n−1) + O(1) | O(n) | длина списка, факториал |
| один вызов, вход делится пополам | T(n) = T(n/2) + O(1) | O(log n) | бинарный поиск ([[binary-search-and-variants]]) |
| два вызова, половины, линейное слияние | T(n) = 2T(n/2) + O(n) | O(n log n) | сортировка слиянием ([[sorting-algorithms]]) |
| два вызова, уменьшение на 1 | T(n) = 2T(n−1) + O(1) | O(2ⁿ) | наивный Фибоначчи, все подмножества |
| n вызовов на уровень, глубина n | | O(n!) | перестановки |

Основная теорема о рекуррентных соотношениях (master theorem) — общий инструмент; четыре строки выше покрывают нужды собеседования ([[big-o-and-complexity]]).

### Шаблон перебора с возвратом
- Состояние: частичное решение (список-путь), оставшиеся варианты и часто массив `used[]`.
- В каждом узле: если частичное решение полное, записать **копию**; иначе для каждого кандидата: проверить ограничение, добавить, уйти в рекурсию, убрать.
- Варианты отсечения: отсортировать кандидатов и делать `break`, как только они превышают цель (combination sum), пропускать дубликаты через `if (i > start && a[i] == a[i-1]) continue` на отсортированном входе, хранить число оставшихся элементов и останавливаться, когда они не могут достичь цели.
- Размер вывода ограничивает время работы: 2ⁿ подмножеств, n! перестановок, C(n, k) сочетаний. Интервьюеры спрашивают именно это число, а не более точную оценку.

### Где встречается в работе
- Обход дерева конфигурации JSON/YAML, деревьев каталогов, графов зависимостей в Maven ([[maven]]).
- Генерация тестовых комбинаций (все пары тариф/регион/канал) для параметризованных тестов.
- Деревья retry в движках workflow: родительская activity перезапускает дочерние; глубина рекурсии равна глубине вложенности ([[temporal-concepts]]).

## Пример
```java
// Перебор с возвратом: все сочетания дополнительных опций тарифа, месячная цена которых в сумме ровно `budget`.
// Каждую опцию можно использовать не более одного раза; вход отсортирован, чтобы можно было отсекать.
record AddOn(String code, int price) {}

static List<List<String>> bundlesFor(List<AddOn> sorted, int budget) {
    List<List<String>> out = new ArrayList<>();
    backtrack(sorted, 0, budget, new ArrayDeque<>(), out);
    return out;
}

private static void backtrack(List<AddOn> items, int start, int remaining,
                              Deque<String> path, List<List<String>> out) {
    if (remaining == 0) {                          // базовый случай: точное совпадение
        out.add(new ArrayList<>(path));             // копия! path потом меняется
        return;
    }
    for (int i = start; i < items.size(); i++) {
        AddOn a = items.get(i);
        if (a.price() > remaining) break;           // отсечение: отсортировано, дальше ничего не поместится
        if (i > start && a.price() == items.get(i - 1).price()
                      && a.code().equals(items.get(i - 1).code())) continue; // пропускаем дубликаты
        path.addLast(a.code());                     // выбираем
        backtrack(items, i + 1, remaining - a.price(), path, out);
        path.removeLast();                          // отменяем выбор
    }
}
```
Время ограничено числом подмножеств, исследованных после отсечения, — не более O(2ⁿ); память — O(n) на путь плюс вывод.

## Подводные камни
- Добавлять в результат сам `path`, а не копию: после возвратов каждый сохранённый ответ оказывается пустым.
- Забывать отменить выбор (`used[i] = false`, `removeLast`), из-за чего последующие ветки видят устаревшее состояние.
- Рекурсия по `String` с `substring` в цикле: копирование O(n²) прячется внутри «O(n)»-алгоритма.
- Экспоненциальное время там, где мемоизация дала бы полиномиальное: если две ветки пересчитывают одно и то же `(index, remaining)`, это замаскированная задача на [[dynamic-programming]].
- Глубокая рекурсия в потоках обработки запросов: `StackOverflowError` — это `Error`, а не `Exception`, поэтому общий `catch (Exception e)` его не обрабатывает ([[exceptions]]).
- Связанные заметки: [[graph-traversal-bfs-dfs]] (DFS — это рекурсия по соседям), [[trees-and-bst]] (рекурсивные обходы), [[interview-problem-patterns]].
