## Кратко
В **невзвешенном** графе кратчайшие пути уже даёт BFS. При **неотрицательных весах** используй Дейкстру: очередь с приоритетом из пар `(distance, node)`, всегда фиксируй ближайшую незафиксированную вершину и релаксируй её рёбра; O((V + E) log V) с двоичной кучей. **Беллман — Форд** справляется с отрицательными весами и обнаруживает отрицательные циклы за O(V · E); **Флойд — Уоршелл** даёт пути между всеми парами за O(V³) для небольших плотных графов. На собеседованиях Дейкстру переодевают в задержку в сети, самый дешёвый перелёт, путь с минимальным усилием или «путь с максимальной вероятностью».

## Основное

### Выбор алгоритма
| Ситуация | Алгоритм | Время |
|---|---|---|
| все рёбра веса 1 | BFS ([[graph-traversal-bfs-dfs]]) | O(V + E) |
| веса 0 или 1 | 0-1 BFS с деком | O(V + E) |
| неотрицательные веса, один источник | Дейкстра с двоичной кучей | O((V + E) log V) |
| отрицательные рёбра допустимы или нужно обнаруживать отрицательные циклы | Беллман — Форд (или SPFA) | O(V · E) |
| DAG, любые веса | DP в топологическом порядке ([[topological-sort-and-union-find]]) | O(V + E) |
| все пары, V ≤ ~400 | Флойд — Уоршелл | O(V³) |
| не более k рёбер («самый дешёвый перелёт не более чем с k пересадками») | Беллман — Форд, ограниченный k раундами, или BFS по слоям | O(k · E) |
| максимизировать произведение вероятностей | Дейкстра с max-кучей и умножением или Дейкстра по `-log p` | как у Дейкстры |

### Дейкстра, точно
- `dist[source] = 0`, все остальные — бесконечность. Положить `(0, source)`.
- Извлечь наименьшую `(d, u)`. Если `d > dist[u]`, это устаревшая запись: пропустить. Иначе для каждого ребра `u → v` с весом `w`: если `dist[u] + w < dist[v]`, обновить и положить `(dist[v], v)`.
- «Ленивое удаление» (класть дубликаты, пропускать устаревшие извлечения) проще, чем `decreaseKey`, и `PriorityQueue` в Java всё равно к этому вынуждает, потому что `decreaseKey` в ней нет ([[heaps-and-priority-queues]]).
- Корректность опирается на неотрицательность весов: как только вершина извлечена с расстоянием `d`, никакой более поздний путь не может быть короче. Отрицательное ребро ломает этот инвариант, и поэтому Дейкстра даёт неправильные ответы, а не просто медленные.
- Путь восстанавливается по массиву `prev[]`, который заполняется при релаксации.
- Ранний выход: остановиться, когда цель извлечена (а не когда она впервые добавлена).
- Плотные графы (E ≈ V²): версия на массиве за O(V²) без кучи быстрее версии с кучей.

### Беллман — Форд
- Повторить V − 1 раз: релаксировать каждое ребро. Если V-й раунд всё ещё что-то релаксирует, достижим отрицательный цикл.
- Раунды соответствуют «путям не более чем из i рёбер» — ровно та структура, что нужна в задачах «не более k пересадок» (копируй `dist` перед каждым раундом, чтобы обновления в одном раунде не складывались в цепочку).

### Где встречается в бэкенд-работе
- Сетевая маршрутизация (OSPF — это Дейкстра, RIP — Беллман — Форд) ([[osi-and-tcp-ip-models]]).
- Выбор самой дешёвой цепочки роуминговых партнёров или пути между регионами с наименьшей задержкой в [[multi-region-basics]].
- Взвешенная маршрутизация в service mesh и балансировщиках нагрузки — частный случай с одним переходом ([[load-balancing]]).
- Карты, оценка времени доставки и любая продуктовая функция «минимизации стоимости на графе».

## Пример
```java
// Дейкстра на взвешенном ориентированном графе: наименьшая суммарная задержка от `src` до каждой вершины.
// Граф — списки смежности из (to, weightMs). Ленивое удаление с PriorityQueue.
record Edge(int to, int weight) {}

static int[] lowestLatency(List<List<Edge>> graph, int src) {
    int n = graph.size();
    int[] dist = new int[n];
    Arrays.fill(dist, Integer.MAX_VALUE);
    dist[src] = 0;
    // записи: {distance, node}; в PriorityQueue нет decreaseKey, поэтому кладём дубликаты
    PriorityQueue<int[]> pq = new PriorityQueue<>(Comparator.comparingInt(e -> e[0]));
    pq.add(new int[]{0, src});
    while (!pq.isEmpty()) {
        int[] top = pq.poll();
        int d = top[0], u = top[1];
        if (d > dist[u]) continue;                       // устаревшая запись, уже зафиксирована дешевле
        for (Edge e : graph.get(u)) {
            int nd = d + e.weight();
            if (nd < dist[e.to()]) {
                dist[e.to()] = nd;
                pq.add(new int[]{nd, e.to()});
            }
        }
    }
    return dist;                                         // MAX_VALUE = недостижимо
}
```
Сложность: каждое ребро может добавить одну запись в кучу, поэтому O((V + E) log E), что упрощается до O((V + E) log V), так как E ≤ V².

## Подводные камни
- Запуск Дейкстры с отрицательными весами: результат молча неправильный, и никакое исключение не предупредит.
- Переполнение `int` в `dist[u] + w`, когда `dist[u]` равно `Integer.MAX_VALUE`; всегда сначала проверяй `dist[u] != MAX` или используй `long`.
- Без проверки устаревших записей (`d > dist[u]`) алгоритм остаётся корректным, но работает за O(E²) на графах с большим числом релаксаций.
- Пометка вершины посещённой при добавлении, а не при извлечении: первое добавление — не обязательно кратчайшее расстояние.
- Использование Дейкстры для «наименьшего числа переходов» в невзвешенном графе: BFS проще и быстрее.
