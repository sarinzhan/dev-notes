## Кратко
Жадный алгоритм (greedy algorithm) делает **локально лучший выбор на каждом шаге и никогда к нему не возвращается**. Он быстрый (обычно одна сортировка плюс один проход, O(n log n)), но корректен только тогда, когда у задачи есть **свойство жадного выбора** (greedy-choice property): существует оптимальное решение, содержащее жадный выбор; это доказывается **аргументом обмена** (exchange argument: «замени первый выбор оптимального решения на жадный, и ничего не ухудшится»). Когда этот аргумент не проходит, задаче нужно [[dynamic-programming]]. Классика собеседований: планирование интервалов, jump game, заправочные станции, раздача печенья, кодирование Хаффмана, Дейкстра и Краскал.

## Основное

### Когда жадный подход работает
- Задача оптимизационная (максимальное количество, минимальная стоимость), и существует простое правило упорядочивания, при котором раннее решение никогда не приходится отменять.
- Проверь: прежде чем доверять жадному подходу, поищи маленький контрпример. Размен монет жадно работает для `{1, 5, 10, 25}`, но не для `{1, 3, 4}` (сумма 6: жадно получается 4+1+1, оптимально 3+3).
- Форма доказательства (аргумент обмена): возьми любое оптимальное решение; если его первый выбор отличается от жадного, замени его жадным; покажи, что результат по-прежнему допустим и не хуже; повторяй.

### Канонические жадные задачи
| Задача | Жадное правило | Почему это безопасно |
|---|---|---|
| планирование интервалов (максимум непересекающихся встреч) | сортировать по времени **окончания**, брать каждый интервал, начинающийся после конца последнего взятого | интервал, заканчивающийся раньше всех, оставляет больше всего места; его можно обменом вставить в любое оптимальное решение |
| минимум комнат / платформ | заметающая прямая (sweep line) с подсчётом пересечений ([[prefix-sums-and-intervals]]) | подсчёт, а не выбор |
| минимум интервалов для удаления | то же, что планирование, посчитать остальные | |
| jump game (можно ли дойти до конца) | отслеживать самый дальний достижимый индекс | достижимость только растёт |
| jump game II (минимум прыжков) | уровни по достижимым диапазонам в духе BFS | каждый уровень — один прыжок |
| заправочные станции (gas station) | если сумма неотрицательна, после любого провала начинать со следующей станции | провалившийся префикс не может быть частью ответа |
| раздача печенья / сопоставление двух массивов | отсортировать оба, два указателя ([[two-pointers-and-sliding-window]]) | сначала наименьшее удовлетворимое |
| планировщик задач с перерывом (cooldown) | сначала самая частая задача; max-куча | частые задачи ограничивают длину |
| кодирование Хаффмана | многократно сливать два самых редких символа с помощью min-кучи ([[heaps-and-priority-queues]]) | два самых редких символа всегда можно сделать соседями на самом глубоком уровне |
| дробный рюкзак | сортировать по отношению ценность/вес | предметы делимы; рюкзак 0/1 **не** решается жадно |
| Дейкстра | фиксировать ближайшую вершину ([[shortest-paths-dijkstra]]) | неотрицательные веса |
| MST Краскала / Прима | добавлять самое дешёвое ребро, соединяющее две компоненты ([[topological-sort-and-union-find]]) | свойство разреза |
| partition labels, составить наибольшее число, удалить k цифр | локальное правило после сортировки или с монотонным стеком ([[stack-and-monotonic-stack]]) | |

### Жадный подход vs DP
| | Жадный | DP |
|---|---|---|
| решения | принимаются один раз, не пересматриваются | оцениваются все варианты |
| требование | свойство жадного выбора + оптимальная подструктура | оптимальная подструктура + перекрывающиеся подзадачи |
| стоимость | обычно O(n log n) | O(n · k) или хуже |
| доказательство | аргумент обмена | корректность рекуррентного соотношения |
| когда не уверен | попробуй жадный, ищи контрпример | откатись к DP |

### Где жадные алгоритмы встречаются в системах
- Планирование: shortest-job-first минимизирует среднее ожидание; earliest-deadline-first — для реального времени; оба жадные ([[cpu-scheduling]]).
- Назначатели партиций Kafka range и round-robin, а также sticky-назначение, минимизирующее перемещения, — жадные эвристики ([[kafka-consumer]]).
- Упаковка pod по нодам в планировщиках Kubernetes — жадная с оценкой; оптимальная упаковка в контейнеры NP-трудна ([[kubernetes-basics]]).
- Деревья Хаффмана сидят внутри DEFLATE (gzip), так что каждый сжатый HTTP-ответ — это работающий жадный алгоритм ([[http-fundamentals]]).
- Ограничители частоты (rate limiters) и retry с экспоненциальным backoff жадны по времени: действуют, как только разрешено ([[rate-limiting]]).

## Пример
```java
// Планирование интервалов: максимальное число непересекающихся окон обслуживания, которые
// можно одобрить из списка заявок. Сортируем по концу, оставляем то, что помещается. O(n log n).
record Window(long start, long end) {}       // полуоткрытый [start, end)

static List<Window> approve(List<Window> requests) {
    List<Window> sorted = new ArrayList<>(requests);
    sorted.sort(Comparator.comparingLong(Window::end));      // аргументу обмена нужен порядок по концу
    List<Window> approved = new ArrayList<>();
    long lastEnd = Long.MIN_VALUE;
    for (Window w : sorted) {
        if (w.start() >= lastEnd) {                            // не пересекается с последним одобренным
            approved.add(w);
            lastEnd = w.end();
        }
    }
    return approved;
}

// Проверка на контрпример, которую стоит прогнать в голове, прежде чем доверять жадному подходу:
// окна [1,10), [2,3), [4,5): жадный с сортировкой по началу одобряет 1 окно, с сортировкой по концу — 2.
```

## Подводные камни
- Сортировка не по тому ключу: планирование интервалов по началу или по длине даёт неправильные ответы; время окончания — единственный безопасный ключ.
- Заявлять жадное решение без поиска контрпримера. Интервьюеры спрашивают «почему это оптимально?» и ждут аргумента обмена, а не «кажется, правильно».
- Путать дробный рюкзак (жадный) с рюкзаком 0/1 (DP).
- Жадные эвристики в продакшне (планировщики, назначатели) нормальны, пока никто не ждёт от них оптимальности; запиши это в дизайн-документ.
- Жадное решение, которое проходит примеры, но падает на скрытых тестах, — самая частая неправильная посылка; если сомневаешься, сначала DP, оптимизация потом.
- Связанные заметки: [[dynamic-programming]], [[prefix-sums-and-intervals]], [[sorting-algorithms]] (почти любой жадный алгоритм начинается с сортировки), [[interview-problem-patterns]].
