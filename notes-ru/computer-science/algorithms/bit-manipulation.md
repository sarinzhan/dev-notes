## Кратко
Битовые трюки обращаются с `int` или `long` как с массивом из 32 или 64 булевых значений. Операторы: `&` (маска/проверка), `|` (установить), `^` (переключить и «сократить пары»), `~` (инвертировать), `<<` / `>>` / `>>>` (сдвиг; `>>>` — беззнаковый сдвиг, который нужен Java, потому что её целые числа знаковые). Применение на собеседованиях: флаги и подмножества через битовые маски, XOR для поиска единственного непарного числа, подсчёт установленных битов, проверка на степень двойки и DP по битовым маскам над небольшими множествами. Применение в бэкенде: флаги прав, флаги функциональности (feature flags), байты тегов EMV, заголовки протоколов и `BitSet` для компактной проверки принадлежности.

## Основное

### Операторы и тождества
| Выражение | Смысл |
|---|---|
| `x & (1 << i)` | проверить бит i (не ноль, если установлен) |
| `x \| (1 << i)` | установить бит i |
| `x & ~(1 << i)` | сбросить бит i |
| `x ^ (1 << i)` | переключить бит i |
| `x & (x - 1)` | сбросить младший установленный бит; ноль тогда и только тогда, когда `x` — степень двойки (и `x > 0`) |
| `x & -x` | выделить младший установленный бит |
| `x ^ x == 0`, `x ^ 0 == x` | XOR сокращает пары: XOR всего массива находит элемент, встречающийся один раз |
| `(a + b) >>> 1` | середина неотрицательных int без переполнения ([[binary-search-and-variants]]) |
| `x >> 1` vs `x >>> 1` | арифметический сдвиг сохраняет знак; логический заполняет нулями |
| `x & 0xFF` | младший байт как 0–255; нужно, потому что `byte` в Java знаковый |

- Отрицательные числа хранятся в дополнительном коде (two's complement): `-x == ~x + 1`, поэтому `x & -x` работает; у `Integer.MIN_VALUE` нет положительной пары ([[numbers-bits-and-floating-point]]).
- Величина сдвига берётся по модулю 32 для `int` и 64 для `long`: `1 << 32 == 1` — классический баг. Для масок типа `long` используй `1L << n`.
- `Integer.bitCount`, `numberOfTrailingZeros`, `highestOneBit`, `Long.reverse` компилируются в одиночные инструкции CPU (popcnt, tzcnt); в реальном коде предпочитай их самописным циклам.

### Паттерны для собеседований
| Задача | Трюк |
|---|---|
| единственное число (остальные встречаются дважды) | XOR всего |
| два единственных числа | XOR всего → `d`; разделить по младшему установленному биту `d` (`d & -d`), XOR каждой группы |
| единственное число (остальные встречаются трижды) | подсчёт битов по позициям по модулю 3 или автомат состояний `ones`/`twos` |
| пропущенное число 0..n | XOR индексов и значений или `n(n+1)/2 - sum` |
| подсчёт битов для 0..n | `bits[i] = bits[i >> 1] + (i & 1)` ([[dynamic-programming]]) |
| степень двойки / четвёрки | `x & (x-1) == 0`; для четвёрки ещё `x & 0x55555555 != 0` |
| разворот битов | поменять местами половины, четверти, ... или `Integer.reverse` |
| подмножества множества из n ≤ 20 | перебирать `mask` от 0 до `2ⁿ - 1`; элемент i входит в подмножество тогда и только тогда, когда установлен бит i |
| перебор подмасок `mask` | `for (s = mask; s > 0; s = (s - 1) & mask)` |
| DP по битовым маскам (TSP, задача о назначениях, «кратчайшая надстрока») | `dp[mask][last]`, O(2ⁿ · n²) |
| сложение без `+` | `sum = a ^ b`, `carry = (a & b) << 1`, цикл |

### Где биты встречаются в бэкенд-работе
- Флаги прав и функциональности хранятся в целочисленной колонке: `flags & CAN_EXPORT != 0`. В SQL читается как `(flags & 4) = 4`, но плохо индексируется; для запросов часто лучше булева колонка на каждый флаг или колонка `bit varying`/массив ([[data-modeling-for-services]]).
- `EnumSet` — это битовая маска по порядковым номерам enum: проверка принадлежности за O(1), 1 бит на константу, и он обходит `HashSet<Enum>` в любом бенчмарке ([[enums]]).
- `java.util.BitSet` для компактной принадлежности целочисленных id (какие из 10 миллионов id абонентов уже мигрированы: 1,25 МБ вместо `HashSet<Long>` на 50+ МБ).
- Протоколы EMV и смарт-карт кодируют данные в TLV с флагами на уровне битов (AIP, TVR, результаты CVM); их разбор — это маски и сдвиги по `byte[]` с `& 0xFF` повсюду ([[emv-card-processing]]).
- Проверка CIDR `ip & mask == network & mask` ([[ip-addressing-ports-nat]]), фильтры Блума ([[bloom-filters-and-probabilistic]]), перемешивание хеша в `HashMap` (`h ^ (h >>> 16)`, [[hashmap-internals]]).

## Пример
```java
// Флаги прав на API-ключе, хранятся в одной int-колонке.
final class Permissions {
    static final int READ = 1, WRITE = 1 << 1, PROVISION = 1 << 2, ADMIN = 1 << 3;

    static int grant(int flags, int perm)   { return flags | perm; }
    static int revoke(int flags, int perm)  { return flags & ~perm; }
    static boolean has(int flags, int perm) { return (flags & perm) == perm; }   // работает и для составных масок
    static int count(int flags)             { return Integer.bitCount(flags); }
}

// Трюк с XOR: единственный ICCID, который отгрузили, но не активировали, по логу, где
// каждый активированный ICCID встречается ровно дважды (отгружен + активирован), а один — однажды.
static long unmatched(long[] events) {
    long acc = 0;
    for (long id : events) acc ^= id;          // пары сокращаются, одиночка остаётся
    return acc;
}
```
Перебор подмножеств устроен так же: `for (int mask = 0; mask < (1 << n); mask++)` и проверка `(mask & (1 << i)) != 0` для каждого элемента, O(2ⁿ · n), нормально для n ≤ 20.

## Подводные камни
- `if (flags & WRITE)` в Java не компилируется; нужно `(flags & WRITE) != 0`, а `&` связывает слабее, чем `==`, так что ставь скобки.
- `byte b = (byte) 0xFF; int v = b;` даёт `-1`; при чтении байтов протокола всегда пиши `b & 0xFF`.
- `1 << 31` — это `Integer.MIN_VALUE`, `1 << 32` — это `1`; для 64-битных масок используй `1L`.
- `>>` над отрицательным числом оставляет его отрицательным навсегда (`-1 >> 1 == -1`); для беззнаковой логики используй `>>>`.
- Хранить битовые флаги в базе данных, потому что это «эффективно», а потом нуждаться в запросах `WHERE has_permission_X`, которые не могут использовать индекс.
