## Кратко
Обычное шифрование защищает данные при хранении и передаче, но чтобы вычислять над ними (фильтровать, суммировать, индексировать, искать), сервер должен сначала их **расшифровать**, и тогда сервер, его администраторы и любой злоумышленник на нём видят открытый текст. **Гомоморфное шифрование** позволяет серверу вычислять прямо над шифротекстами: результат после расшифровки клиентом равен результату того же вычисления над открытыми данными. База никогда не видит ни данных, ни значений из запроса. Подвох: это крайне медленно (в тысячи–миллионы раз медленнее), шифротексты большие, и практичны только некоторые операции. В 2026 году его применяют для нишевых приватных вычислений, а не для баз данных общего назначения.

## Основное
### Почему нельзя всегда шифровать
- **При хранении** (диск, бэкапы: TDE, LUKS) и **при передаче** (TLS) задача решена. **При использовании** — нет: чтобы вычислить `WHERE salary > 5000`, построить B-дерево или выполнить `SUM`, базе нужен открытый текст в памяти.
- Шифрование колонок в приложении (шифрование на клиенте) скрывает данные от базы, но тогда база не может индексировать, сортировать, сравнивать и агрегировать эти колонки. Поиск превращается в «забрать всё и расшифровать в приложении».
- Частичные обходные пути: детерминированное шифрование (поиск по равенству, но выдаёт одинаковые значения), шифрование с сохранением порядка (диапазонные запросы, выдаёт порядок), слепые индексы (HMAC значения). Каждый что-то раскрывает.
- Основы симметричного и асимметричного шифрования: [[symmetric-and-asymmetric-crypto]], [[hashing-vs-encryption]].

### Что значит «гомоморфное»
- Шифрование `E` гомоморфно относительно операции, если `E(a) ⊕ E(b) = E(a + b)` для некоторой операции `⊕` над шифротекстами.
- **Частично гомоморфное**: только одна операция. RSA (учебный) мультипликативен; Paillier аддитивен (`E(a)·E(b) = E(a+b)`), этого хватает для зашифрованных сумм и голосования.
- **Ограниченно гомоморфное** (somewhat / leveled): и сложение, и умножение, но каждая операция добавляет шум; после фиксированной глубины умножений шифротекст уже не расшифровать.
- **Полностью гомоморфное (FHE)**: любое вычисление благодаря **бутстрэппингу** (Крейг Джентри, 2009), который сбрасывает шум, гомоморфно вычисляя саму расшифровку. Современные схемы: BFV и BGV (точные целые), CKKS (приближённые вещественные, ML), TFHE (булевы вентили, быстрый бутстрэппинг).
- Библиотеки: Microsoft SEAL, OpenFHE, IBM HElib, Zama Concrete/TFHE-rs.

### Как работает поиск в зашифрованной базе (идея демо из курса)
1. Клиент генерирует ключи, шифрует каждое поле записи и загружает шифротексты на сервер.
2. Для поиска клиент шифрует искомое значение и отправляет его.
3. Сервер вычисляет схему сравнения на равенство между зашифрованным запросом и каждой зашифрованной записью (индекс использовать нельзя: сервер не знает, какая запись подходит) и возвращает зашифрованный вектор результатов.
4. Клиент расшифровывает и видит, какие записи совпали. Сервер ничего не узнал, но проделал работу над **каждой** строкой.

### Готово ли это?
- Стоимость: сложение — от микросекунд до миллисекунд, операция с бутстрэппингом — миллисекунды и больше; шифротексты в 10–1000 раз больше открытых данных; ключи от мегабайт до гигабайт.
- Ни индексов, ни раннего выхода: каждый запрос — полное сканирование шифротекстов.
- Практично сегодня: зашифрованная агрегация и статистика, приватное пересечение множеств, приватный инференс небольших ML-моделей, проверка паролей по утечкам, часть рекламной аналитики. Аппаратные ускорители (программа DARPA DPRIVE) и реализации на GPU сокращают разрыв.
- Альтернативы для «вычислений над секретными данными»: **доверенные среды исполнения** (Intel SGX/TDX, AMD SEV, AWS Nitro Enclaves: быстро, но нужно доверять производителю железа), **безопасные многосторонние вычисления** (MPC) и **поисковое симметричное шифрование**.

## Пример
```python
# additive homomorphism with the Paillier scheme (python-paillier)
from phe import paillier

pub, priv = paillier.generate_paillier_keypair(n_length=2048)
salaries = [4200, 5100, 3900]
enc = [pub.encrypt(s) for s in salaries]   # the server stores only these

enc_total = sum(enc[1:], enc[0])            # server adds ciphertexts, never sees values
enc_raise = enc_total * 2                   # scalar multiplication also works
print(priv.decrypt(enc_total))              # 13200, only the key holder can read it
```

## Подводные камни
- Считать, что «зашифрованная база» значит, что сервер не видит данные: TDE и шифрование диска расшифровывают в памяти на каждом запросе.
- Выбрать шифрование с сохранением порядка или детерминированное, не смирившись с тем, что они раскрывают (частоты, порядок).
- Ожидать, что FHE потянет обычную SQL-нагрузку: нет индексов, огромные шифротексты, на порядки медленнее.
- Писать свою криптографию вместо проверенной библиотеки и набора параметров (уровень безопасности, бюджет шума).
