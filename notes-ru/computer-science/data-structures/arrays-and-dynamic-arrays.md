## Кратко
Массив — это непрерывный блок памяти, в котором элемент `i` лежит по адресу `base + i * elementSize`, поэтому доступ по индексу — O(1), а обход дружелюбен к кэшу. Динамический массив (`ArrayList`, слайсы Go, `vector` в C++) оборачивает массив фиксированного размера и, когда тот заполнен, выделяет больший и копирует: добавление в худшем случае O(n), но **амортизированно O(1)**, потому что копирования происходят геометрически всё реже. Это коллекция по умолчанию почти для всего; обзор того, какое место она занимает среди остальных, — в [[data-structures]].

## Основное

### Размещение в памяти
- Фиксированный размер, один тип, непрерывность. Предвыборка CPU и кэш-линии (64 байта) делают последовательный проход по `int[]` в несколько раз быстрее, чем проход по такому же числу указателей ([[cpu-caches-and-cache-lines]]).
- В Java массив примитивов (`int[]`, `byte[]`) хранит значения прямо внутри. `Object[]` хранит **ссылки**; сами объекты разбросаны по куче, поэтому `List<Integer>` теряет большую часть выгоды от кэша (плюс упаковка, см. [[primitives-and-wrappers]]).
- У массива в Java заголовок 12–16 байт плюс поле длины; длина фиксируется при выделении и проверяется при каждом обращении (`ArrayIndexOutOfBoundsException`, переполнений буфера нет).
- Многомерные массивы в Java — это массивы массивов (`int[][]`), каждая строка — отдельный объект; обход по строкам дружелюбен к кэшу, по столбцам — нет.

### Операции и сложность
| Операция | Статический массив | Динамический массив (`ArrayList`) |
|---|---|---|
| Чтение/запись по индексу | O(1) | O(1) |
| Добавление в конец | неприменимо (фиксирован) | O(1) амортизированно, O(n) при расширении |
| Вставка/удаление по индексу `i` | O(n) сдвиг | O(n) сдвиг (`System.arraycopy`) |
| Поиск в неотсортированном | O(n) | O(n) |
| Поиск в отсортированном | O(log n) ([[binary-search-and-variants]]) | O(log n) |
| Память | ровно n элементов | до 2× n (запасная ёмкость) |

### Амортизированный рост
- `ArrayList` растёт в 1.5× (`oldCapacity + (oldCapacity >> 1)`), слайсы Go — в 2×, затем в 1.25×, `vector` в C++ — обычно в 2×.
- При геометрическом множителе добавление n элементов стоит в сумме не более n + n/1.5 + n/2.25 + ... ≈ 3n копирований, то есть в среднем O(1) на добавление. Рост на константу (+10) стоил бы в сумме O(n²). Это хрестоматийный пример амортизированного анализа ([[big-o-and-complexity]]).
- Сжатие не происходит автоматически: `ArrayList.remove` никогда не освобождает ёмкость; вызывай `trimToSize()`, если список однажды вырос, а теперь остаётся маленьким.
- Расширение — это полное копирование: один `add` может приостановить работу на миллисекунды на списке из 10M элементов и запускает большое выделение памяти, под которое GC должен найти место ([[garbage-collection]]).

### Почему массивы выигрывают на практике
- Big-O говорит, что `LinkedList` вставляет в середину за O(1), но поиск позиции — O(n), и каждый узел — отдельный объект в куче. По измерениям `ArrayList` обгоняет его даже на нагрузках с большим числом вставок при размерах меньше десятков тысяч элементов ([[linked-lists]]).
- Сортировка, двоичный поиск, префиксные суммы, техники двух указателей и скользящего окна — все предполагают массив ([[two-pointers-and-sliding-window]], [[prefix-sums-and-intervals]]).
- Кольцевой буфер поверх массива даёт очередь за O(1) без выделения памяти на каждый элемент ([[stacks-and-queues]]); двоичная куча — это просто массив с индексной арифметикой ([[heaps-and-priority-queues]]).

### Особенности Java, которые стоит знать
- `Arrays.asList` возвращает представление фиксированного размера поверх массива: `set` работает, `add` бросает исключение. `List.of` неизменяем и отвергает `null`.
- `ArrayList` не потокобезопасен; `CopyOnWriteArrayList` копирует весь массив при каждой записи, что годится только для данных, которые в основном читаются ([[concurrent-collections]]).
- Остальной API списков JDK, итераторы и поведение modCount — в [[collections-framework]] и [[iterators-and-fail-fast]].

## Пример
Минимальный динамический массив значений `long` с геометрическим ростом — такое пишут для буфера метрик или когда на собеседовании просят «реализовать ArrayList».

```java
public final class LongList {
    private long[] data;
    private int size;

    public LongList(int initialCapacity) {
        data = new long[Math.max(initialCapacity, 1)];
    }

    public void add(long value) {
        if (size == data.length) {
            data = Arrays.copyOf(data, data.length + (data.length >> 1)); // x1.5, как в ArrayList
        }
        data[size++] = value;
    }

    public long get(int index) {
        Objects.checkIndex(index, size);              // бросает IndexOutOfBoundsException
        return data[index];
    }

    public long removeAt(int index) {
        Objects.checkIndex(index, size);
        long removed = data[index];
        System.arraycopy(data, index + 1, data, index, size - index - 1); // сдвиг O(n)
        size--;
        return removed;
    }

    public int size() { return size; }
}
```

## Подводные камни
- Построение списка в цикле через `new ArrayList<>()` при известном итоговом размере тратит впустую несколько расширений; передавай ожидаемый размер в конструктор (`new ArrayList<>(rows.size())`).
- Удаление элементов при обходе по индексу (`for (int i = 0; i < list.size(); i++) list.remove(i)`) пропускает каждый второй элемент; обходи с конца или используй `removeIf`.
- `list.remove(int)` и `list.remove(Object)` на `List<Integer>` выбирают разные перегрузки; `list.remove(1)` удаляет элемент с индексом 1, а не значение 1.
- Огромный `ArrayList<Integer>` стоит примерно 20 байт на элемент (ссылка + упакованный объект) против 4 для `int[]`; для числовых горячих путей используй массивы примитивов или библиотеку, специализированную под примитивы.
