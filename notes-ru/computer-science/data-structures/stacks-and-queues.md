## Кратко
Стек — это LIFO (push/pop с одного конца), очередь — FIFO (добавление в хвост, извлечение из головы), а дек (deque) делает и то и другое с обоих концов. Все три работают за O(1) на операцию, если реализованы кольцевым буфером поверх массива или связным списком. В Java правильный класс для всех трёх — `ArrayDeque`; `Stack` — это устаревший синхронизированный `Vector`, а `LinkedList` медленнее. Стеки моделируют рекурсию, разбор и отмену действий; очереди — буферизацию, BFS и схему «производитель–потребитель». Ограниченные варианты (`ArrayBlockingQueue`, `LinkedBlockingQueue`) — примитив передачи между потоками, лежащий в основе любого executor-а ([[executors-and-thread-pools]]).

## Основное

### Абстракции
| АТД | Операции | Порядок | Типичные применения |
|---|---|---|---|
| Стек | `push`, `pop`, `peek` | LIFO | стек вызовов, DFS, проверка скобок, вычисление выражений, undo, монотонный стек ([[stack-and-monotonic-stack]]) |
| Очередь | `offer`, `poll`, `peek` | FIFO | BFS ([[graph-traversal-bfs-dfs]]), очереди задач, буферизация между производителем и потребителем, ограничение частоты |
| Дек | всё вышеперечисленное с обоих концов | оба | максимум в скользящем окне, кража работы (work stealing, [[fork-join-framework]]), LRU-подобный порядок давности |
| Очередь с приоритетом | `offer`, `poll` по приоритету | по ключу | отдельная структура, см. [[heaps-and-priority-queues]] |

### Реализации и размещение
| Основа | push/pop/offer/poll | Память | Примечания |
|---|---|---|---|
| Массив как стек (индекс вершины) | O(1), амортизированно при росте | непрерывно | проще всего; `ArrayDeque` для одного конца |
| **Кольцевой буфер (ring buffer)** (циклический массив, индексы `head`/`tail` по модулю ёмкости) | O(1), амортизированно при росте | непрерывно, без выделения памяти на элемент | `ArrayDeque`, `ArrayBlockingQueue`, Disruptor, концептуально — аккумулятор продюсера Kafka |
| Двусвязный список | O(1) | один узел на элемент, враждебен к кэшу | `LinkedList`, `LinkedBlockingQueue`, `ConcurrentLinkedQueue` (lock-free CAS на голове/хвосте) |
| Два стека | O(1) амортизированно | два массива | классический вопрос «очередь из двух стеков» |

- Кольцевой буфер с ёмкостью-степенью двойки заменяет `% capacity` на `& (capacity - 1)`; `ArrayDeque` делает именно так и удваивается, когда после записи `head == tail`.
- Ограниченные кольцевые буферы — естественный инструмент обратного давления: когда буфер полон, производитель блокируется или быстро получает отказ, вместо того чтобы безгранично наращивать память ([[backpressure-and-flow-control]]).

### Очередь из двух стеков (амортизированно O(1))
- Стек `in` принимает каждый `offer`. При `poll`, если `out` пуст, снять всё из `in` и положить в `out`, затем снять из `out`. Каждый элемент перемещается не более двух раз, поэтому общая стоимость n операций — O(n).

### Карта API Java
| Нужно | Использовать | Избегать |
|---|---|---|
| Однопоточный стек | `ArrayDeque` (`push`/`pop`) | `java.util.Stack` (синхронизирован, расширяет `Vector`) |
| Однопоточная очередь/дек | `ArrayDeque` | `LinkedList` |
| Передача между потоками, ограниченная | `ArrayBlockingQueue` (одна блокировка), `LinkedBlockingQueue` (две блокировки) | неограниченные очереди в пуле потоков (OOM вместо отказа) |
| Lock-free, неограниченная | `ConcurrentLinkedQueue`/`ConcurrentLinkedDeque` | — |
| С задержкой или приоритетом | `DelayQueue`, `PriorityBlockingQueue` | — |

`ArrayDeque` отвергает `null`, потому что `poll`/`peek` используют `null` для обозначения «пусто». Подробности о конкурентных вариантах — в [[concurrent-collections]]; методы интерфейсов `Queue`/`Deque` (`add` бросает исключение, а `offer` возвращает false) — в [[collections-framework]].

### Где они встречаются в системах
- Стек вызовов JVM — это стек фреймов; `StackOverflowError` — это то, что эта структура исчерпала свой фиксированный размер ([[stack-vs-heap-memory]]).
- Пул потоков — это очередь плюс исполнители; тип очереди определяет, будет ли пул отвергать, блокировать или расти ([[executors-and-thread-pools]]).
- Партиции Kafka и брокеры сообщений — это долговечные очереди/логи ([[message-queues-and-streams]]); очередь в памяти — та же идея без долговечности.

## Пример
Кольцевой буфер фиксированной ёмкости — структура, лежащая в основе `ArrayDeque` и `ArrayBlockingQueue`; здесь используется как ограниченный буфер в памяти для последних N образцов трейсов.

```java
public final class RingBuffer<T> {
    private final Object[] items;
    private int head;   // индекс самого старого элемента
    private int size;

    public RingBuffer(int capacity) {
        if (Integer.bitCount(capacity) != 1) throw new IllegalArgumentException("power of two");
        items = new Object[capacity];
    }

    /** Добавляет; когда буфер полон, перезаписывает самый старый (семантика «хранить последние»). */
    public void offer(T item) {
        int tail = (head + size) & (items.length - 1);
        items[tail] = item;
        if (size == items.length) head = (head + 1) & (items.length - 1); // выбросить самый старый
        else size++;
    }

    @SuppressWarnings("unchecked")
    public T poll() {
        if (size == 0) return null;
        T item = (T) items[head];
        items[head] = null;                       // дать GC его забрать
        head = (head + 1) & (items.length - 1);
        size--;
        return item;
    }

    public int size() { return size; }
    public boolean isFull() { return size == items.length; }
}
```

## Подводные камни
- Использовать `java.util.Stack` в новом коде: он синхронизирован, наследует индексный API `Vector` и обходится снизу вверх, что удивляет тех, кто ожидает порядок LIFO.
- `Executors.newFixedThreadPool` использует неограниченную `LinkedBlockingQueue`: медленный потребитель превращается в `OutOfMemoryError`, а не в отклонённые задачи. Строй пулы с ограниченной очередью и политикой отказа.
- Если не обнулять ячейку в стеке/очереди на массиве, мёртвые объекты остаются достижимыми (утечка памяти в долгоживущем буфере).
- Использование очереди вместо стека или наоборот в BFS/DFS переворачивает обход; BFS нужен FIFO.
