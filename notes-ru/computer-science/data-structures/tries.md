## Кратко
Префиксное дерево (trie) хранит строки как пути от корня, по одному символу на ребро, поэтому все ключи с общим префиксом разделяют один и тот же путь. Поиск, вставка и вопрос «начинается ли какой-нибудь ключ с X» стоят O(L) от длины ключа и не зависят от числа ключей. Поэтому это структура для автодополнения, поиска самого длинного совпадающего префикса (IP-маршрутизация, префиксы телефонных номеров, диапазоны MSISDN) и проверки орфографии. Цена — память: наивный узел с массивом детей на 26 или 256 ячеек огромен, поэтому реальные реализации используют детей в хеш-map, сжатые рёбра (radix tree) или битовые трюки.

## Основное

### Структура
- Корень — пустая строка. У каждого узла есть дети с ключом-символом и флаг `terminal` (здесь заканчивается ключ); опционально — значение, число ключей ниже или полезная нагрузка (маршрут, тариф, вес подсказки).
- Ключ **нигде не хранится** как строка; он восстанавливается по пути. Ключи с общим префиксом разделяют узлы — это выигрыш в памяти для больших словарей похожих строк и проигрыш для немногих длинных непохожих строк.

### Операции и сложность (L = длина ключа, A = размер алфавита)
| Операция | Trie | Хеш-map | Отсортированный массив / `TreeMap` |
|---|---|---|---|
| Вставка / точный поиск | O(L) | O(L) в среднем (хешируется весь ключ) | O(L log n) |
| `startsWith(prefix)` | O(L) | O(n·L) проход | O(L log n), чтобы найти начало, затем проход |
| Все ключи с префиксом | O(L + размер вывода) | O(n·L) | O(L log n + размер вывода) |
| Самый длинный совпадающий префикс текста | O(L) | O(L²) попыток для каждого префикса | O(L log n) на кандидата |
| Упорядоченный обход | O(всего символов), лексикографический порядок бесплатно | не упорядочено | да |
| Память | O(всего символов) узлов, у каждого хранилище детей | O(n) записей + строки ключей | O(n) + строки ключей |

### Компромиссы хранения детей
| Дети в виде | Поиск на символ | Память на узел | Когда |
|---|---|---|---|
| Фиксированный массив `Node[26]` / `Node[256]` | O(1) | 26–256 ссылок (200 Б–2 КБ) | маленький алфавит, плотные ключи, олимпиадный код |
| `HashMap<Character, Node>` | O(1) в среднем | накладные расходы map на каждый узел | Unicode, разреженные ключи |
| Маленький отсортированный массив + двоичный поиск | O(log A) | компактно | когда важна память |
| **Radix / Patricia-дерево**: цепочки с единственным ребёнком сливаются в одно ребро с подстрокой | O(L) в целом | гораздо меньше узлов | таблицы маршрутизации Linux, HTTP-роутеры Go, Redis streams/RAX, концептуально — сопоставление шаблонов путей в Spring |

### Где префиксные деревья встречаются в системах
- **Автодополнение / typeahead**: дойти до узла префикса, затем DFS, либо хранить в каждом узле заранее вычисленные top-k подсказок (куча на узел, [[heaps-and-priority-queues]]). При масштабе trie шардируется по первым буквам и обслуживается из памяти (разветвление в стиле [[design-news-feed]] здесь не применяется; нагрузка в основном на чтение).
- **Поиск самого длинного префикса**: таблицы IP-маршрутизации (двоичный trie по битам адреса, [[ip-addressing-ports-nat]]), телеком-планы нумерации (какому оператору/тарифу принадлежит `+99655…`), URL-роутеры, сопоставляющие `/api/v1/sims/{id}`.
- **Строительные блоки полнотекстового поиска**: словарь терминов с префиксными запросами; инвертированные индексы в Lucene/Elasticsearch используют FST (finite state transducer) — сжатый trie ([[elasticsearch-basics]]).
- **Сжатые in-memory-индексы**: адаптивные radix-деревья в базах данных; префиксные операторы в Postgres вроде `btree_gin` опираются на B-деревья ([[postgres-indexes]]); на практике trie — чисто in-memory-структура.
- **Строковые алгоритмы**: Ахо–Корасик (trie + ссылки неудач) находит много шаблонов за один проход; суффиксные tries/деревья отвечают на запросы о подстроках ([[string-algorithms]]).

### Trie против хеш-map для словаря
- Только точная принадлежность: хеш-map, она проще и часто быстрее, потому что хеширование — один проход и одно чтение корзины ([[hash-tables]]).
- Префиксные, упорядоченные запросы или поиск самого длинного совпадения: trie.
- Приближённая принадлежность с крошечной памятью: фильтр Блума ([[bloom-filters-and-probabilistic]]).

## Пример
Trie над строчными ASCII-буквами с поиском по префиксу и поиском самого длинного префикса — форма плана нумерации или таблицы маршрутов.

```java
public final class Trie {
    private static final class Node {
        final Node[] next = new Node[26];
        boolean terminal;
        String value;                                 // полезная нагрузка терминальных узлов (например, код оператора)
    }

    private final Node root = new Node();

    public void put(String key, String value) {
        Node n = root;
        for (char c : key.toCharArray()) {
            int i = c - 'a';
            if (n.next[i] == null) n.next[i] = new Node();
            n = n.next[i];
        }
        n.terminal = true;
        n.value = value;
    }

    public boolean contains(String key) {
        Node n = find(key);
        return n != null && n.terminal;
    }

    public boolean startsWith(String prefix) { return find(prefix) != null; }

    /** Значение самого длинного ключа, являющегося префиксом text, или null (поиск самого длинного префикса). */
    public String longestPrefixValue(String text) {
        Node n = root; String best = null;
        for (char c : text.toCharArray()) {
            n = n.next[c - 'a'];
            if (n == null) break;
            if (n.terminal) best = n.value;
        }
        return best;
    }

    public List<String> keysWithPrefix(String prefix, int limit) {
        List<String> out = new ArrayList<>();
        Node n = find(prefix);
        if (n != null) collect(n, new StringBuilder(prefix), out, limit);
        return out;
    }

    private Node find(String s) {
        Node n = root;
        for (char c : s.toCharArray()) {
            n = n.next[c - 'a'];
            if (n == null) return null;
        }
        return n;
    }

    private void collect(Node n, StringBuilder path, List<String> out, int limit) {
        if (out.size() >= limit) return;
        if (n.terminal) out.add(path.toString());
        for (int i = 0; i < 26 && out.size() < limit; i++) {
            if (n.next[i] != null) {
                path.append((char) ('a' + i));
                collect(n.next[i], path, out, limit);
                path.setLength(path.length() - 1);
            }
        }
    }
}
```

## Подводные камни
- Взрыв памяти: `Node[256]` на каждый символ для словаря из миллиона слов — это гигабайты. Используй map или radix-дерево и измеряй, прежде чем выбрать trie вместо отсортированного массива с двоичным поиском ([[binary-search-and-variants]]).
- Забыть флаг `terminal`: после вставки `"apple"` `startsWith("app")` истинно, но `contains("app")` должно быть ложно.
- Удаление требует обрезать на обратном пути узлы без детей и без флага terminal, иначе в trie остаются мёртвые ветви.
- Регистр, Unicode и нормализация: приводи ключи к нижнему регистру и нормализуй перед вставкой и поиском, иначе `"É"` и `"é"` станут разными путями ([[text-encodings-and-unicode]]).
- Связанные заметки: [[data-structures]] — обзор, [[string-algorithms]] — Ахо–Корасик и суффиксные структуры, [[hash-tables]] — когда нужен только точный поиск.
