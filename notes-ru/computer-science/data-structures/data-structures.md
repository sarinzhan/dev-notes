## Кратко
Структура данных — это способ организовать данные так, чтобы нужные операции были дешёвыми. Те, что важны каждый день: массивы (O(1) по индексу), связные списки (O(1) вставка у известного узла), хеш-таблицы (O(1) поиск в среднем), сбалансированные деревья (O(log n) упорядоченные операции), стеки (LIFO), очереди и деки (FIFO), кучи (приоритет), графы. Знание таблицы сложностей позволяет выбрать правильный класс из `java.util` ([[collections-framework]]).

## Основное
### Линейные структуры
| Структура | Доступ по индексу | Поиск | Вставка/удаление | Java |
|---|---|---|---|---|
| Массив | O(1) | O(n), O(log n), если отсортирован | O(n) (сдвиг), фиксированный размер | `int[]`, `ArrayList` (расширяемый, рост ×1.5) |
| Односвязный/двусвязный список | O(n) | O(n) | O(1) у известного узла, O(n) на его поиск | `LinkedList` (двусвязный) |
| Стек (LIFO) | только вершина | – | push/pop O(1) | `ArrayDeque`; `Stack` устарел |
| Очередь (FIFO) | только голова | – | offer/poll O(1) | `ArrayDeque`, `LinkedList`, `ArrayBlockingQueue` |
| Дек (deque) | оба конца | – | O(1) с обоих концов | `ArrayDeque` |

- Массивы непрерывны в памяти, поэтому доступ по индексу — O(1), а обход дружелюбен к кэшу; размер у них фиксирован, так что рост означает выделение нового массива и копирование (это и делает `ArrayList.add` при расширении, амортизированно O(1)).
- Связные списки тратят лишний объект и две ссылки на элемент и враждебны к кэшу; на практике `ArrayList` обгоняет `LinkedList` даже на многих нагрузках со вставкой в середину, потому что сдвиг — это `System.arraycopy`. Используй связный список, когда держишь итераторы/узлы и сращиваешь их (LRU-кэши, `LinkedHashMap`).
- Стек моделирует рекурсию, отмену действий (undo), вычисление выражений и DFS; очередь моделирует буферизацию, BFS и схему «производитель–потребитель» ([[executors-and-thread-pools]]).

### Хеш-таблица
- Массив корзин (buckets) с индексом `hash % capacity`; коллизии разрешаются цепочками (Java) или открытой адресацией. В среднем O(1) для get/put/remove, O(n) в худшем случае; Java 8 ограничивает худший случай корзинами в виде красно-чёрных деревьев. Нужен хороший `hashCode` ([[equals-and-hashcode]]). Подробности — в [[hashmap-internals]].

### Деревья
- **Дерево**: иерархические узлы с одним родителем и нулём или более детей; корень наверху, листья внизу. Используется для упорядоченных данных, иерархий (файловые системы, DOM), индексов.
- **Двоичное дерево**: не более двух детей у узла.
- **Двоичное дерево поиска (BST)**: левое поддерево < узел < правое поддерево; поиск/вставка/удаление за O(высоты), что деградирует до O(n), когда вставки приходят отсортированными.
- **Самобалансирующиеся BST** держат высоту O(log n):
  - **Красно-чёрное дерево**: каждый узел красный или чёрный; корень чёрный; у красных узлов чёрные дети; каждый путь от корня до листа содержит одинаковое число чёрных узлов (null-листья считаются чёрными). Высота не более 2·log₂(n+1); перебалансировка при вставке дешевле, чем у AVL. Используется в `TreeMap`/`TreeSet`, корзинах HashMap, планировщике CFS в Linux.
  - **AVL-дерево**: более строгий баланс (высоты различаются не более чем на 1), быстрее чтение, больше поворотов при записи.
- **B-дерево / B+-дерево**: широкие узлы размером со страницу диска; структура, лежащая в основе индексов баз данных ([[postgres-indexes]], [[database-indexes]]).
- **Куча (heap)**: полное двоичное дерево в массиве, где родитель ≤ детей (min-куча); peek O(1), вставка/извлечение O(log n). `PriorityQueue`; используется в планировщиках, top-k, алгоритме Дейкстры.
- **Префиксное дерево (trie)**: дерево по символам; автодополнение, таблицы маршрутизации.

### Графы
- Вершины и рёбра, ориентированные или нет, взвешенные или нет; хранятся как списки смежности (разреженные) или матрица смежности (плотные). Графы зависимостей (Maven, бины Spring), сетевые топологии, конечные автоматы.

### Алгоритмы, которые нужно знать
| Алгоритм | Сложность | Примечания |
|---|---|---|
| Линейный поиск | O(n) | неотсортированные данные |
| Двоичный поиск | O(log n) | отсортированный массив; `Arrays.binarySearch`, `Collections.binarySearch` |
| Сортировка пузырьком | O(n²) | только для обучения |
| Сортировка слиянием | O(n log n), устойчивая | `Arrays.sort(Object[])` использует TimSort — гибрид слияния и вставок |
| Быстрая сортировка | O(n log n) в среднем, на месте | `Arrays.sort(int[])` использует быструю сортировку с двумя опорными элементами (dual-pivot quicksort) |
| Пирамидальная сортировка | O(n log n), на месте, неустойчивая | |
| BFS | O(V+E) | кратчайший путь в невзвешенных графах, обход по уровням; нужна очередь |
| DFS | O(V+E) | достижимость, поиск циклов, топологическая сортировка; рекурсия или стек |
| Обходы дерева | O(n) | прямой (узел, левое, правое), симметричный (отсортированный вывод для BST), обратный (сначала удалить детей), по уровням (BFS) |
| Дейкстра | O((V+E) log V) | кратчайший путь при неотрицательных весах, на основе кучи |
| Жадный алгоритм | по-разному | берётся локально лучший выбор; работает, когда у задачи есть свойство жадного выбора (планирование интервалов, Хаффман, дробный рюкзак). Рюкзак 0/1 — стандартный контрпример: жадный подход не работает, и нужно динамическое программирование (O(n·W)) |
| Динамическое программирование | по-разному | перекрывающиеся подзадачи + оптимальная подструктура; мемоизация или таблица снизу вверх |

## Пример
```java
// BFS по графу зависимостей (имена бинов -> зависимости), чтобы найти всё, что бину транзитивно нужно.
static Set<String> transitiveDeps(Map<String, List<String>> graph, String root) {
    Set<String> seen = new LinkedHashSet<>();          // порядок вставки = порядок обнаружения
    Deque<String> queue = new ArrayDeque<>();          // FIFO-очередь; ArrayDeque, а не LinkedList
    queue.add(root);
    while (!queue.isEmpty()) {
        String bean = queue.poll();
        for (String dep : graph.getOrDefault(bean, List.of())) {
            if (seen.add(dep)) queue.add(dep);         // add возвращает false, если уже встречался
        }
    }
    return seen;
}

// Top-k самых медленных запросов с ограниченной min-кучей: O(n log k) вместо сортировки всего.
static List<Long> slowest(LongStream latenciesMs, int k) {
    PriorityQueue<Long> heap = new PriorityQueue<>();   // min-куча: наименьший из top-k наверху
    latenciesMs.forEach(v -> { heap.offer(v); if (heap.size() > k) heap.poll(); });
    return heap.stream().sorted(Comparator.reverseOrder()).toList();
}
```

## Подводные камни
- Big-O скрывает константы: при n меньше нескольких сотен проход по массиву обгоняет поиск в хеш-таблице, а `ArrayList` почти всегда обгоняет `LinkedList`.
- BST без балансировки (написанное вручную или наивное дерево с отсортированным вводом) незаметно деградирует до связного списка.
- Рекурсивный DFS на глубоких структурах переполняет стек (по умолчанию ~512 КБ–1 МБ на поток); для всего глубже нескольких тысяч уровней используй явный стек.
- Порядок обхода `PriorityQueue` не отсортирован; только `poll()` возвращает элементы по порядку.
