## Кратко
Дерево — это иерархия узлов с одним корнем и без циклов. Двоичное дерево поиска (binary search tree, BST) поддерживает `left < node < right`, поэтому поиск, вставка и удаление стоят O(высоты): O(log n), когда дерево сбалансировано, O(n), когда оно вырождается в цепочку. Самобалансирующиеся деревья (красно-чёрные, AVL) выполняют повороты при вставке/удалении, чтобы высота оставалась логарифмической, и именно это дают `TreeMap`/`TreeSet`: отсортированные ключи, запросы по диапазону и floor/ceiling за O(log n). На диске та же идея превращается в B-дерево с широкими узлами размером со страницу, поэтому любой индекс базы данных — это B-дерево ([[database-indexes]]).

## Основное

### Словарь
- **Корень**, **лист** (нет детей), **глубина** (рёбер от корня), **высота** (самый длинный путь от корня до листа), **поддерево**.
- **Двоичное дерево**: не более двух детей. **Полное (complete)**: все уровни заполнены, кроме, возможно, последнего, который заполняется слева направо (это и есть куча, [[heaps-and-priority-queues]]). **Строгое (full)**: у каждого узла 0 или 2 ребёнка. **Совершенное (perfect)**: строгое, и все листья на одной глубине, n = 2^h − 1.
- Дерево — это связный ациклический граф с n − 1 рёбрами; графы в общем виде — в [[graphs-representation]].

### Обходы
| Порядок | Последовательность посещения | Что даёт |
|---|---|---|
| Прямой (pre-order) | узел, левое, правое | копирование/сериализация дерева, префиксная запись выражения |
| Симметричный (in-order) | левое, узел, правое | **отсортированный вывод для BST** |
| Обратный (post-order) | левое, правое, узел | удаление детей до родителя, вычисление деревьев выражений, подсчёт размеров |
| По уровням (level-order, BFS) | по глубине, слева направо | кратчайший путь в невзвешенном дереве, печать по уровням |

Рекурсивные обходы используют стек вызовов (глубина = высота, нормально для сбалансированных деревьев, рискованно для вырожденных); итеративные используют явный стек или очередь ([[stacks-and-queues]], [[recursion-and-backtracking]]).

### Операции BST
| Операция | Сбалансированное | Вырожденное | Как |
|---|---|---|---|
| поиск / вставка | O(log n) | O(n) | спуск вниз со сравнением ключей |
| удаление | O(log n) | O(n) | 0 детей: отцепить; 1 ребёнок: срастить; 2 ребёнка: заменить симметричным преемником (минимум правого поддерева) и удалить его |
| min / max | O(log n) | O(n) | самый левый / самый правый |
| floor / ceiling / диапазон `[a, b)` | O(log n + k) | O(n) | спуститься вниз, затем симметричный обход от найденного узла |
| k-й наименьший | O(log n) с размерами поддеревьев | O(n) | дерево порядковых статистик |

Вставка уже отсортированных ключей в наивное BST даёт связный список — стандартная ловушка.

### Самобалансирующиеся деревья
| Дерево | Инвариант | Оценка высоты | Стоимость перебалансировки | Где |
|---|---|---|---|---|
| **AVL** | высоты двух поддеревьев различаются не более чем на 1 | ≈ 1.44 log₂ n | до O(log n) поворотов при удалении | in-memory-индексы с преобладанием чтения |
| **Красно-чёрное** | узлы красные/чёрные; корень чёрный; у красного нет красного ребёнка; одинаковое число чёрных на каждом пути от корня до null | ≤ 2 log₂(n+1) | ≤ 2 поворотов на вставку, ≤ 3 на удаление | `TreeMap`, `TreeSet`, корзины-деревья `HashMap`, планировщик CFS в Linux, `std::map` в C++ |
| **Декартово дерево (treap) / список с пропусками (skip list)** | рандомизированные | ожидаемо O(log n) | просто | `ConcurrentSkipListMap` (lock-free отсортированная map) |
| **Splay-дерево** | переносить узел, к которому обратились, в корень | амортизированно O(log n) | — | кэши с локальностью |

Красно-чёрное дерево жертвует немного худшим балансом ради более дешёвых записей, поэтому оно по умолчанию используется в библиотеках общего назначения. Поворот — это перезапись указателей за O(1), сохраняющая симметричный порядок и опускающая одно поддерево на уровень.

### B-деревья и B+-деревья
- B-дерево — сбалансированное дерево поиска с очень широкими узлами (сотни ключей, один узел = одна страница диска), поэтому для миллиардов ключей оно остаётся глубиной 3–4 уровня; B+-дерево хранит значения только в связанных листьях. Это структура, на которой стоят индексы баз данных; подробный разбор (поиск, расщепления, B-дерево и B+-дерево, размер страницы, MySQL и Postgres) — в [[b-tree-vs-b-plus-tree]].
- LSM-деревья (RocksDB, Cassandra) — альтернатива, оптимизированная под запись ([[database-engines]]).

### Другие деревья, которые встретятся
- **Префиксное дерево (trie)**: дерево по символам для поиска по префиксу ([[tries]]).
- **Дерево отрезков / дерево Фенвика**: суммы на диапазонах и обновления за O(log n) ([[prefix-sums-and-intervals]]).
- **Дерево Меркла**: хеши от хешей для проверки целостности (объекты git, anti-entropy repair в Cassandra, блокчейны).
- **Деревья выражений / AST**: компиляторы, SQL-планировщики ([[query-planning-and-execution]]).

### API Java
- `TreeMap`/`TreeSet` (красно-чёрное, `NavigableMap`: `floorKey`, `ceilingKey`, `subMap`, `headMap`, `descendingMap`). Ключам нужен `Comparable` или `Comparator`; компаратор, не согласованный с `equals`, заставляет map считать «равные» ключи одним и тем же. См. [[collections-framework]].
- `ConcurrentSkipListMap` — для конкурентной отсортированной map ([[concurrent-collections]]).

## Пример
Минимальное BST с итеративным поиском, рекурсивной вставкой и удалением через симметричного преемника; без балансировки — именно это обычно просят на собеседовании перед вопросом «а как бы ты его сбалансировал?».

```java
public final class IntBst {
    private static final class Node {
        int key; Node left, right;
        Node(int key) { this.key = key; }
    }
    private Node root;

    public boolean contains(int key) {
        Node n = root;
        while (n != null) {
            if (key == n.key) return true;
            n = key < n.key ? n.left : n.right;
        }
        return false;
    }

    public void insert(int key) { root = insert(root, key); }
    private Node insert(Node n, int key) {
        if (n == null) return new Node(key);
        if (key < n.key) n.left = insert(n.left, key);
        else if (key > n.key) n.right = insert(n.right, key);
        return n;                                   // дубликат: игнорировать
    }

    public void delete(int key) { root = delete(root, key); }
    private Node delete(Node n, int key) {
        if (n == null) return null;
        if (key < n.key) n.left = delete(n.left, key);
        else if (key > n.key) n.right = delete(n.right, key);
        else {
            if (n.left == null) return n.right;     // 0 или 1 ребёнок
            if (n.right == null) return n.left;
            Node succ = n.right;                    // 2 ребёнка: симметричный преемник
            while (succ.left != null) succ = succ.left;
            n.key = succ.key;
            n.right = delete(n.right, succ.key);
        }
        return n;
    }

    public void inOrder(IntConsumer visit) {        // отсортировано по возрастанию
        Deque<Node> stack = new ArrayDeque<>();
        Node cur = root;
        while (cur != null || !stack.isEmpty()) {
            while (cur != null) { stack.push(cur); cur = cur.left; }
            cur = stack.pop();
            visit.accept(cur.key);
            cur = cur.right;
        }
    }
}
```

## Подводные камни
- Самописные BST без балансировки незаметно деградируют на отсортированных или почти отсортированных входных данных (временные метки, последовательные id): используй `TreeMap` или отсортируй массив и применяй двоичный поиск ([[binary-search-and-variants]]).
- Компаратор `TreeMap`, возвращающий 0 для разных объектов (`comparing(User::getAge)`), молча теряет записи: сравнивай по уникальному полю в последнюю очередь (`thenComparing(User::getId)`).
- Рекурсия по вырожденному дереву из 100 тыс. узлов переполняет стек потока; сбалансированные деревья безопасны, потому что глубина ~40 ([[stack-vs-heap-memory]]).
- Изменение объекта-ключа внутри `TreeSet` ломает порядок без всякого исключения; ключи должны быть неизменяемыми ([[immutable-objects]]).
- Связанные заметки: [[data-structures]] — обзор, [[hash-tables]] — когда порядок не нужен (O(1) вместо O(log n)), [[database-indexes]] и [[postgres-indexes]] — B-деревья на практике.
