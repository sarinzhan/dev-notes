## Кратко
Очередь с приоритетом (priority queue) первым отдаёт наименьший (или наибольший) элемент, независимо от порядка вставки. Стандартная реализация — **двоичная куча (binary heap)**: полное двоичное дерево, хранящееся в обычном массиве, где каждый родитель ≤ своих детей (min-куча). Peek — O(1), вставка и извлечение минимума — O(log n), построение кучи из n элементов — O(n). Это структура, лежащая в основе `PriorityQueue`, таймеров и планировщиков, алгоритма Дейкстры, запросов top-k и k-путевых слияний. Когда нужно найти или удалить произвольный элемент или обойти элементы по порядку, это неподходящая структура; используй сбалансированное дерево ([[trees-and-bst]]).

## Основное

### Размещение в массиве
- У узла `i` дети `2i + 1` и `2i + 2`, а родитель — `(i - 1) / 2` (индексация с 0). Ни указателей, ни объектов-узлов: вся куча — один непрерывный массив, что дружелюбно к кэшу ([[arrays-and-dynamic-arrays]]).
- Дерево **полное** (заполняется уровень за уровнем, слева направо), поэтому в массиве нет дыр, а высота равна ⌊log₂ n⌋.
- Куча **не отсортирована**: гарантированно экстремален только корень. Обход массива даёт произвольный порядок.

### Операции
| Операция | Сложность | Как |
|---|---|---|
| `peek` | O(1) | `a[0]` |
| `offer` (вставка) | O(log n) | добавить в конец, **просеивать вверх (sift up)**, пока меньше родителя |
| `poll` (извлечение минимума) | O(log n) | перенести последний элемент в корень, **просеивать вниз (sift down)**, меняясь с меньшим ребёнком |
| построение из n элементов (heapify) | O(n) | просеивать вниз от последнего внутреннего узла до корня; дешевле n вставок (O(n log n)) |
| `remove(Object)` / `contains` | O(n) | линейный проход; у `PriorityQueue` нет индекса |
| уменьшение ключа (decrease-key) | O(log n) с индексной map | нужно хрестоматийному Дейкстре; в Java вместо этого вставляют заново ([[shortest-paths-dijkstra]]) |
| пирамидальная сортировка | O(n log n), на месте, неустойчивая | heapify, затем многократно переставлять корень в конец и просеивать вниз ([[sorting-algorithms]]) |

### Варианты
| Куча | Вставка | Извлечение минимума | Слияние | Где |
|---|---|---|---|---|
| Двоичная | O(log n) | O(log n) | O(n) | `PriorityQueue`, почти везде |
| d-арная (d = 4) | O(log_d n) | O(d log_d n) | — | меньше промахов кэша при просеивании вниз; используется в некоторых планировщиках |
| Биномиальная / Фибоначчи | O(1) амортизированно | O(log n) | O(log n) / O(1) | теоретическая оценка для Дейкстры; на практике редко используется |
| Pairing heap | O(1) | O(log n) амортизированно | O(1) | практичная сливаемая куча |
| Иерархическое колесо таймеров (hierarchical timing wheel) | O(1) | O(1) за тик | — | purgatory в Kafka, таймеры Netty: много таймаутов с грубым разрешением |

### Классические применения
- **Top-k из потока**: держать min-кучу размера k; добавлять каждый элемент, извлекать, когда размер превышает k. O(n log k) по времени и O(k) по памяти вместо сортировки всего. Самые медленные запросы, самые большие файлы, самые частые слова (вместе с map частот).
- **K-путевое слияние (k-way merge)**: слить k отсортированных входов (сегменты логов, отсортированные партиции, компактизация Kafka) кучей из k голов: O(N log k).
- **Планирование**: `ScheduledThreadPoolExecutor` хранит задачи в `DelayedWorkQueue` (двоичная куча, упорядоченная по времени срабатывания); `DelayQueue` — то же для произвольных отложенных элементов ([[executors-and-thread-pools]]). Temporal и cron-подобные планировщики концептуально делают то же самое ([[background-jobs-and-schedulers]]).
- **Алгоритмы на графах**: Дейкстра и Прим извлекают из кучи ближайшую непосещённую вершину.
- **Скользящая медиана**: max-куча нижней половины и min-куча верхней половины.
- **Ограничители частоты и балансировщики нагрузки**: выбирать наименее загруженный бэкенд из кучи с ключом по текущей нагрузке ([[load-balancing]]).

### API Java
- `PriorityQueue<E>`: min-куча по естественному порядку или по `Comparator`; `offer`/`poll`/`peek`; не потокобезопасна; порядок итератора не определён; элементы `null` отвергаются. Max-куча: `new PriorityQueue<>(Comparator.reverseOrder())`.
- `PriorityBlockingQueue` — потокобезопасная неограниченная версия ([[concurrent-collections]]). Всё остальное об интерфейсах очередей — в [[collections-framework]].

## Пример
Компактная двоичная min-куча значений `long` плюс паттерн top-k на ней. На собеседовании для паттерна принимают `PriorityQueue`, но любят один раз увидеть просеивание вверх/вниз.

```java
public final class LongMinHeap {
    private long[] a = new long[16];
    private int size;

    public void offer(long v) {
        if (size == a.length) a = Arrays.copyOf(a, size * 2);
        a[size] = v;
        siftUp(size++);
    }

    public long poll() {
        if (size == 0) throw new NoSuchElementException();
        long min = a[0];
        a[0] = a[--size];
        if (size > 0) siftDown(0);
        return min;
    }

    public long peek() { return a[0]; }
    public int size() { return size; }

    private void siftUp(int i) {
        while (i > 0) {
            int parent = (i - 1) >>> 1;
            if (a[parent] <= a[i]) break;
            swap(i, parent); i = parent;
        }
    }

    private void siftDown(int i) {
        while (true) {
            int l = 2 * i + 1, r = l + 1, smallest = i;
            if (l < size && a[l] < a[smallest]) smallest = l;
            if (r < size && a[r] < a[smallest]) smallest = r;
            if (smallest == i) return;
            swap(i, smallest); i = smallest;
        }
    }

    private void swap(int i, int j) { long t = a[i]; a[i] = a[j]; a[j] = t; }

    /** Top-k наибольших задержек за O(n log k): куча хранит k наибольших из увиденных. */
    static long[] topK(long[] latencies, int k) {
        LongMinHeap heap = new LongMinHeap();
        for (long v : latencies) {
            heap.offer(v);
            if (heap.size() > k) heap.poll();     // вытеснить наименьшего из кандидатов
        }
        long[] out = new long[heap.size()];
        for (int i = out.length - 1; i >= 0; i--) out[i] = heap.poll(); // по убыванию
        return out;
    }
}
```

## Подводные камни
- Считать `PriorityQueue` отсортированной: `toString()`, `iterator()` и `stream()` дают порядок кучи, а не порядок приоритетов. Отсортирован только результат повторных `poll()`.
- Использовать max-кучу размера n для top-k: O(n log n) и O(n) памяти; правильная форма — min-куча размера k.
- Изменять приоритет элемента, пока он лежит в куче (менять поле `deadline` задачи), незаметно ломает инвариант; удали, измени, вставь заново.
- `PriorityQueue.remove(Object)` — O(n); для нагрузок вида «отменить запланированную задачу» держи вспомогательную map или используй флаг-надгробие и пропускай при poll.
- Связанные заметки: [[data-structures]] — обзор, [[trees-and-bst]] — когда нужен ещё и упорядоченный обход или удаление произвольных элементов, [[shortest-paths-dijkstra]] — основное применение на графах.
