## Кратко
Связный список (linked list) — это цепочка узлов, каждый из которых хранит значение и ссылку на следующий (односвязный) или на обоих соседей (двусвязный). Он даёт вставку и удаление за O(1) **у узла, который у тебя уже есть**, и O(n) для всего, что требует найти позицию. Поскольку каждый узел — отдельный объект в куче, список враждебен к кэшу и на практике почти везде проигрывает [[arrays-and-dynamic-arrays]]. Своё место он заслуживает ровно в двух ситуациях: когда ты держишь ссылки на узлы и сращиваешь их (LRU-кэши, интрузивные очереди) и когда нужна структура, которая никогда не копирует данные.

## Основное

### Варианты
| Вариант | В каждом узле | Можно удалить узел, имея только сам узел? | Типичное применение |
|---|---|---|---|
| Односвязный | значение + `next` | нет (нужен предшественник) | стеки, списки свободных блоков, неизменяемые/персистентные списки в ФП |
| Двусвязный | значение + `next` + `prev` | да, O(1) | `LinkedList`, цепочка порядка в `LinkedHashMap`, LRU-кэши |
| Кольцевой | последний указывает на первый | зависит | планировщики round-robin, концептуально — кольцевые буферы |
| С сигнальными (sentinel) головой/хвостом | фиктивные узлы на обоих концах | да | убирает все проверки на null из кода вставки/удаления |

### Операции и сложность
| Операция | Односвязный | Двусвязный | `ArrayList` для сравнения |
|---|---|---|---|
| Доступ по индексу | O(n) | O(n) | O(1) |
| Вставка/удаление в голове | O(1) | O(1) | O(n) |
| Вставка/удаление в хвосте | O(1) с указателем на хвост (удаление O(n)) | O(1) | O(1) амортизированно / O(1) |
| Вставка/удаление у известного узла | O(1) после, O(n) перед | O(1) | O(n) |
| Поиск | O(n) | O(n) | O(n) |
| Память на элемент | значение + 1 ссылка (+ заголовок) | значение + 2 ссылки (+ заголовок) | 1 ссылка, непрерывно |

### Размещение в памяти и почему это медленно
- Каждый узел — отдельное выделение памяти: `LinkedList.Node` в Java занимает ~24 байта плюс упакованное значение плюс заголовок объекта. Обход следует по указателям на произвольные адреса кучи, поэтому почти каждый шаг — промах кэша ([[cpu-caches-and-cache-lines]]).
- Обход `ArrayList` последовательно читает 64-байтные кэш-линии, и предвыборка успевает вперёд. Бенчмарки регулярно показывают, что `ArrayList` в 5–10 раз быстрее при обходе и быстрее даже при вставке в середину вплоть до больших размеров, потому что `System.arraycopy` — это плотный memmove.
- Платит и GC: много маленьких объектов с перекрёстными ссылками обходить дороже, чем один массив ([[garbage-collection]]).

### Где связные списки действительно выигрывают
- **Сращивание по ссылке на узел**: LRU-кэш хранит `HashMap<K, Node>` и перемещает узел в начало за O(1) ([[lru-cache-design]]). Ровно это `LinkedHashMap` делает внутри ([[hashmap-internals]]).
- **Неограниченные очереди без пауз на расширение**: `ConcurrentLinkedQueue` и `LinkedBlockingQueue` растут узел за узлом и поддерживают lock-free CAS на голове/хвосте ([[concurrent-collections]], [[lock-free-and-cas]]).
- **Персистентные/неизменяемые списки** в функциональном стиле: добавление в начало разделяет весь хвост со старым списком, без копирования ([[immutability-and-side-effects]]).
- **Цепочки в хеш-таблицах**: корзины — это односвязные списки, пока не превратятся в деревья ([[hash-tables]]).

### Классические приёмы для собеседований
- **Быстрый и медленный указатели**: обнаружить цикл (Флойд), найти середину, найти k-й с конца двумя указателями на расстоянии k.
- **Разворот на месте**: три указателя (`prev`, `cur`, `next`), O(1) дополнительной памяти.
- **Фиктивная голова (dummy head)**: начинать с сигнального узла, чтобы вставка перед первым реальным узлом не была особым случаем.
- **Слияние двух отсортированных списков**: строительный блок сортировки слиянием на списках и k-путевого слияния ([[heaps-and-priority-queues]]).

## Пример
Односвязный список с сигнальной головой, разворотом на месте и обнаружением цикла. Используется как интрузивная очередь, где вызывающий код хранит ссылки на узлы.

```java
public final class SinglyLinkedList<T> {
    private static final class Node<T> {
        T value; Node<T> next;
        Node(T value, Node<T> next) { this.value = value; this.next = next; }
    }

    private final Node<T> head = new Node<>(null, null); // сигнальный узел: никогда не хранит значение
    private Node<T> tail = head;
    private int size;

    public void addLast(T value) {
        tail.next = new Node<>(value, null);
        tail = tail.next;
        size++;
    }

    public T removeFirst() {
        if (head.next == null) throw new NoSuchElementException();
        Node<T> first = head.next;
        head.next = first.next;
        if (first == tail) tail = head;          // список стал пустым
        size--;
        return first.value;
    }

    public void reverse() {                      // O(n) по времени, O(1) по памяти
        Node<T> prev = null, cur = head.next;
        tail = cur;
        while (cur != null) {
            Node<T> next = cur.next;
            cur.next = prev;
            prev = cur;
            cur = next;
        }
        head.next = prev;
    }

    static <T> boolean hasCycle(Node<T> start) { // Флойд: медленный ходит на 1, быстрый на 2
        Node<T> slow = start, fast = start;
        while (fast != null && fast.next != null) {
            slow = slow.next; fast = fast.next.next;
            if (slow == fast) return true;
        }
        return false;
    }

    public int size() { return size; }
}
```

## Подводные камни
- Хвататься за `java.util.LinkedList` «потому что я вставляю в середину»: проход через `get(i)` или итератор до середины — O(n), а выделения узлов медленнее сдвига в `ArrayList`. По умолчанию бери `ArrayList`, а для очередей — `ArrayDeque` ([[stacks-and-queues]]).
- `LinkedList.get(i)` внутри цикла `for` по индексам — это O(n²); используй итератор.
- Рекурсивные алгоритмы на длинных списках (рекурсивный разворот, рекурсивное слияние) переполняют стек примерно на 10–20 тыс. узлов; пиши их итеративно ([[recursion-and-backtracking]]).
- Забыть обновить `tail` или `size` при удалении последнего узла — самый частый баг в самописных списках; сигнальный узел плюс тест на случай с одним элементом его ловят.
- Связанные заметки: [[data-structures]] — обзор, [[collections-framework]] — API `LinkedList`/`Deque` в JDK, [[lru-cache-design]] — то единственное место, где двусвязный список — правильный ответ.
