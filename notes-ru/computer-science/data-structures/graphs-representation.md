## Кратко
Граф — это множество вершин V и рёбер E, возможно ориентированных и возможно взвешенных. Выбранное представление определяет стоимость двух вопросов, которые задаёт любой алгоритм на графах: «кто соседи v?» и «есть ли ребро u–v?». **Список смежности (adjacency list)** (для каждой вершины — список соседей) отвечает на первый за O(deg v) и занимает O(V + E) памяти, что подходит для разреженных графов, встречающихся в реальных системах (графы зависимостей, сети, workflow). **Матрица смежности (adjacency matrix)** отвечает на второй за O(1), но стоит O(V²) памяти и оправдана только для плотных или крошечных графов. Сами обходы — в [[graph-traversal-bfs-dfs]].

## Основное

### Словарь
- **Ориентированный** (у рёбер есть направление: зависимости, HTTP-вызовы, потоки между топиками Kafka) против **неориентированного** (дружба, сетевые связи).
- **Взвешенный** (стоимость, задержка, расстояние) против невзвешенного.
- **Степень** (входящая/исходящая для ориентированного), **путь**, **цикл**, **компонента связности**, **DAG** (ориентированный ациклический граф: системы сборки, связывание бинов Spring, шаги workflow в Temporal, DAG-и Airflow).
- **Разреженный** означает, что E порядка V (большинство реальных графов); **плотный** — что E приближается к V².
- Дерево — это связный ациклический неориентированный граф с V − 1 рёбрами ([[trees-and-bst]]).

### Представления
| Представление | Память | Соседи v | Есть ребро u–v? | Добавить ребро | Лучше всего для |
|---|---|---|---|---|---|
| **Список смежности** `Map<V, List<V>>` или `List<List<Integer>>` | O(V + E) | O(deg v) | O(deg u) | O(1) | разреженные графы, BFS/DFS/Дейкстра, вариант по умолчанию |
| Список смежности с `Set` на вершину | O(V + E) | O(deg v) | O(1) в среднем | O(1) | разреженные + частые проверки рёбер |
| **Матрица смежности** `boolean[V][V]` / `int[V][V]` | O(V²) | O(V) | O(1) | O(1) | плотные графы, V ≤ нескольких тысяч, Флойд–Уоршелл, трюки с битсетами |
| **Список рёбер** `List<Edge(u, v, w)>` | O(E) | O(E) | O(E) | O(1) | Краскал (сортировка рёбер), Беллман–Форд, формат ввода/вывода |
| **CSR** (compressed sparse row: один `int[] offsets` и один `int[] neighbours`) | O(V + E), два массива | O(deg v), непрерывно | O(deg u) | перестроение | статические большие графы, дружелюбен к кэшу, аналитика |
| Граф объектов (`Node` с `List<Node> edges`) | O(V + E) + накладные расходы объектов | O(deg v) | O(deg) | O(1) | доменные модели, маленькие графы, читаемость |

### Выбор
- Вариант по умолчанию на собеседовании: список смежности как `List<List<Integer>>` с вершинами, пронумерованными 0..V−1 (или `Map<String, List<String>>` для именованных узлов). Память O(V + E), обход O(V + E).
- Взвешенный: `List<List<int[]>>` с парами `{to, weight}` или небольшой `record Edge(int to, int weight)`.
- Неориентированный: хранить каждое ребро дважды (u→v и v→u).
- Матрица — когда V мало и нужны проверки рёбер за O(1), транзитивное замыкание или трюк «число путей длины k» (степени матрицы).
- Размещение в памяти важно: `List<List<Integer>>` — это списки упакованных ссылок, разбросанных по куче; массивы CSR или `int[][]` непрерывны и в несколько раз быстрее на больших графах ([[cpu-caches-and-cache-lines]], [[arrays-and-dynamic-arrays]]).

### Графы, с которыми ты уже работаешь
- **Графы зависимостей**: модули Maven, определения бинов Spring (цикл — это `BeanCurrentlyInCreationException`, [[spring-bean-lifecycle]]), происхождение данных между топиками Kafka, графы вызовов микросервисов, построенные по трейсам ([[distributed-tracing]]). Их упорядочивание — топологическая сортировка ([[topological-sort-and-union-find]]).
- **Конечные автоматы**: жизненный цикл eSIM-профиля (`RELEASED → DOWNLOADED → INSTALLED → ENABLED`), статус заказа, шаги workflow ([[temporal-concepts]]); таблица переходов — это список смежности.
- **Сети**: маршрутизаторы и линки с весами-задержками, кратчайшие пути ([[shortest-paths-dijkstra]]), service mesh.
- **Базы данных**: планы запросов — это DAG-и операторов ([[query-planning-and-execution]]); графовые базы данных (Neo4j) хранят смежность нативно, реляционные моделируют рёбра таблицей связей `(from_id, to_id)` и обходят её рекурсивными CTE ([[sql-vs-nosql-choosing]]).

### Оценка памяти
Список смежности из 1M вершин и 10M рёбер в виде `int`-CSR: ~44 МБ. В виде `List<List<Integer>>`: несколько сотен МБ (упакованные `Integer`, накладные расходы `ArrayList` на каждую вершину). Поэтому библиотеки графовой аналитики используют массивы примитивов.

## Пример
Небольшой тип ориентированного взвешенного графа со списком смежности; здесь он моделирует граф вызовов сервисов с задержкой на каждый переход — в той форме, которую потребляют Дейкстра и BFS.

```java
public final class DirectedGraph {
    public record Edge(int to, int weight) {}

    private final List<List<Edge>> adj;           // adj.get(u) = исходящие рёбра u
    private final Map<String, Integer> index = new HashMap<>();
    private final List<String> names = new ArrayList<>();

    public DirectedGraph() { adj = new ArrayList<>(); }

    public int vertex(String name) {              // получить или создать id вершины
        return index.computeIfAbsent(name, n -> {
            names.add(n);
            adj.add(new ArrayList<>());
            return adj.size() - 1;
        });
    }

    public void addEdge(String from, String to, int weight) {
        adj.get(vertex(from)).add(new Edge(vertex(to), weight));
        // в неориентированном графе добавили бы и обратное ребро
    }

    public List<Edge> neighbours(int v) { return adj.get(v); }
    public int size() { return adj.size(); }
    public String name(int v) { return names.get(v); }

    /** Обратный граф: кто вызывает меня? Нужен для «радиуса поражения» и обратного топологического порядка. */
    public DirectedGraph reversed() {
        DirectedGraph r = new DirectedGraph();
        for (String n : names) r.vertex(n);
        for (int u = 0; u < adj.size(); u++)
            for (Edge e : adj.get(u)) r.adj.get(e.to()).add(new Edge(u, e.weight()));
        return r;
    }
}

// использование
var g = new DirectedGraph();
g.addEdge("api-gateway", "esim-service", 5);
g.addEdge("esim-service", "sm-dp-plus", 120);
g.addEdge("esim-service", "postgres", 2);
```

## Подводные камни
- Использовать матрицу смежности для разреженного графа со 100 тыс. вершин: 10¹⁰ ячеек, нехватка памяти ещё до первого обхода.
- Забыть обратное ребро в неориентированном графе или добавить его в ориентированном; здесь половина багов в задачах на графы.
- `List<List<Integer>>` с `list.remove(v)` удаляет по индексу, а не по значению, когда `v` — `int` (в [[arrays-and-dynamic-arrays]] та же ловушка).
- Изменяемые объекты вершин в роли ключей `HashMap` для отображения смежности: их изменение ломает поиск ([[hash-tables]]).
- Связанные заметки: [[data-structures]] — обзор, [[graph-traversal-bfs-dfs]] — BFS/DFS по этим структурам, [[topological-sort-and-union-find]] — упорядочивание DAG и связность.
