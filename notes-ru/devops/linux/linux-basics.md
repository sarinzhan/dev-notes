## Кратко
Чтобы работать с Linux-машиной, нужны четыре вещи: знать иерархию файловой системы (где лежат бинарники, конфиги, логи и состояние времени выполнения), базовые команды для файлов и процессов, как устроены пользователи, группы и биты прав доступа, и как устанавливаются пакеты. Всё остальное в заметках про [[linux-architecture-and-kernel|архитектуру]] и [[linux-processes|процессы]] строится на этом.

## Основное
### Иерархия файловой системы (FHS)
| Путь | Что там лежит |
|---|---|
| `/bin`, `/sbin` | Основные пользовательские и системные бинарники (`ls`, `mount`); в современных дистрибутивах — символические ссылки на `/usr/bin`, `/usr/sbin` |
| `/usr` | Установленное ПО: `/usr/bin`, `/usr/lib`, `/usr/local` для установленного вручную |
| `/etc` | Общесистемная конфигурация: `/etc/passwd`, `/etc/nginx/`, `/etc/systemd/` |
| `/var` | Изменяемые данные: логи (`/var/log`), очереди (spools), кеши, данные Docker (`/var/lib/docker`), данные Postgres (`/var/lib/postgresql`) |
| `/proc` | Псевдофайловая система, отражающая состояние ядра и процессов (`/proc/<pid>/`, `/proc/meminfo`) |
| `/sys` | Псевдофайловая система для устройств, драйверов и параметров ядра (sysfs) |
| `/dev` | Файлы устройств (`/dev/sda`, `/dev/null`, `/dev/shm`) |
| `/home`, `/root` | Домашние каталоги пользователей; домашний каталог root |
| `/tmp`, `/run` | Временные файлы; состояние времени выполнения (pid-файлы, сокеты, например `/run/docker.sock`) |
| `/opt` | Самодостаточные сторонние пакеты |

### Базовые команды
- Файлы: `ls -la`, `cd`, `cp -r`, `mv`, `rm -rf`, `cat`, `less`, `head`/`tail -f`, `find`, `grep -rn` ([[linux-commands]]).
- Владелец и режим доступа: `chmod`, `chown user:group`, `umask`.
- Процессы: `ps aux`, `top`/`htop`, `kill -15 <pid>`, `systemctl status|start|stop|enable <unit>` ([[linux-processes]]).
- Связки в оболочке: `|`, `>`, `>>`, `2>&1`, `$(...)`, `&&`, `xargs`.

### Пользователи, группы, права доступа
- У каждого файла есть владелец, группа и девять битов прав: `rwx` для владельца, группы и остальных. `r=4 w=2 x=1`, поэтому `chmod 640` = владелец читает и пишет, группа читает, остальные ничего.
- Для каталога `x` означает «можно войти / пройти насквозь», `r` — «можно получить список», `w` — «можно создавать и удалять записи».
- Специальные биты: `setuid` (запуск от имени владельца файла, например `passwd`), `setgid` на каталоге (новые файлы наследуют группу), sticky bit на `/tmp` (удалять может только владелец).
- `sudo` запускает команду от root; членство в группе `docker` равносильно root ([[docker-socket-dind-dood]]).
- `/etc/passwd` перечисляет пользователей, `/etc/shadow` хранит хеши паролей, `/etc/group` перечисляет группы; `id`, `whoami`, `groups`.

### Менеджеры пакетов
- Debian/Ubuntu: `apt update && apt install -y <pkg>`; пакеты `.deb`, `dpkg -l`.
- Fedora/RHEL: `dnf install <pkg>`; пакеты `.rpm`.
- Arch: `pacman -S <pkg>`.
- Alpine (частая база для Docker): `apk add --no-cache <pkg>` ([[dockerfile-and-images]]).

### Текстовые редакторы
- `nano`: без режимов, подсказки внизу (`Ctrl+O` записать, `Ctrl+X` выйти). Подходит для исправления одной строки в конфиге.
- `vim`: модальный. `i` вставка, `Esc` назад в обычный режим, `:wq` записать и выйти, `:q!` выйти без сохранения, `/pattern` поиск, `dd` удалить строку, `u` отменить. Стоит выучить, потому что он есть на каждом сервере и в большинстве контейнеров (как минимум `vi`).

## Пример
```bash
# Пользователь для деплоя, который может запускать сервис, но не может читать секреты других пользователей
sudo useradd --system --home /opt/esim --shell /usr/sbin/nologin esim
sudo mkdir -p /opt/esim /var/log/esim
sudo chown -R esim:esim /opt/esim /var/log/esim
sudo chmod 750 /opt/esim              # группа может войти, остальные — нет
sudo chmod 640 /opt/esim/application.yml   # конфиг читают только владелец и группа

# Проверить, что получилось
ls -la /opt/esim
# -rw-r----- 1 esim esim  812 Oct 22 10:14 application.yml
sudo -u esim java -jar /opt/esim/app.jar   # запуск от пользователя сервиса
```

## Подводные камни
- `rm -rf` с незаданной переменной (`rm -rf $DIR/`) удаляет `/`; используй `set -u` в скриптах и бери переменные в кавычки.
- `chmod 777`, «чтобы заработало», — никогда не решение; найди пользователя/группу-владельца и выставь 750/640.
- Файлы, удалённые, пока процесс держит их открытыми, продолжают занимать место на диске, пока процесс их не закроет; про `ls`, `du` и `df` см. [[linux-memory-filesystems-io]].
- `apt install` в Dockerfile без `rm -rf /var/lib/apt/lists/*` раздувает слой образа ([[dockerfile-and-images]]).
- Связанные заметки: [[linux-commands]], [[linux-architecture-and-kernel]].
