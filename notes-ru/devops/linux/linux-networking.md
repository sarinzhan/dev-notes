## Кратко
Пакет, покидающий приложение, проходит путь сокет -> TCP/UDP в ядре -> IP-маршрутизация -> netfilter (файрвол) -> драйвер сетевого интерфейса -> провод, а приходит в обратном порядке. Чтобы эксплуатировать сервер, нужно знать модель уровней (ARP, IP, ICMP, TCP/UDP), инструменты `iproute2` (`ip a`, `ip r`, `ss`), файрвол (`nftables` или `iptables` в старых системах) и то, как DNS и DHCP дают хосту имена и адреса.

## Основное
### Путь пакета
1. Приложение вызывает `write()`/`send()` на сокете (файловом дескрипторе); для JVM это `SocketChannel` или блокирующий `Socket` ([[java-nio]], [[java-io-streams]]).
2. Транспортный уровень: TCP разбивает данные на сегменты, назначает порядковые номера, отвечает за повторную передачу и управление потоком и перегрузкой; UDP просто добавляет порты и контрольную сумму.
3. Сетевой уровень: IP выбирает следующий узел (next hop) по **таблице маршрутизации** (`ip r`), устанавливает TTL, при необходимости фрагментирует.
4. Хуки netfilter: здесь пакет видят правила файрвола и NAT (`nftables`/`iptables`); публикация портов в Docker — это правило DNAT ([[docker-fundamentals]]).
5. Канальный уровень: ARP разрешает IP следующего узла в MAC-адрес (`ip neigh`), драйвер кладёт кадр в кольцевой буфер сетевой карты, DMA отправляет его.
6. Сторона приёма: прерывание сетевой карты -> драйвер -> IP -> TCP сопоставляет четвёрку (src ip, src port, dst ip, dst port) с сокетом -> данные попадают в приёмный буфер сокета -> возвращается `read()` приложения.

### Протоколы, которые нужно уметь объяснить
- **ARP**: отображает IPv4-адрес в MAC в локальном сегменте; широковещательный запрос «у кого 10.0.0.1?». Устаревшие записи объясняют ситуацию «сервер переехал, но никто не может до него достучаться».
- **IP**: адресация и маршрутизация; CIDR (`10.20.0.0/16`), шлюз по умолчанию, приватные диапазоны (10/8, 172.16/12, 192.168/16). В IPv6 нет ARP (используется NDP) и в обычном случае нет NAT.
- **ICMP**: управляющие сообщения; `ping` (echo), `traceroute` (истечение TTL), «destination unreachable», определение MTU пути (path MTU discovery). Блокировка всего ICMP ломает PMTU, и большие пакеты пропадают.
- **TCP**: с установлением соединения, упорядоченный, надёжный. Трёхстороннее рукопожатие (SYN, SYN-ACK, ACK), четырёхстороннее закрытие, `TIME_WAIT` на стороне, которая закрывает первой (удерживает четвёрку 60 с). Nagle, delayed ACK, keepalive. Состояния сокетов видны в `ss -t`.
- **UDP**: датаграммы без соединения; DNS, DHCP, QUIC/HTTP3, метрики (StatsD), syslog.
- **DNS**: имя -> адрес. Настройки резолвера в `/etc/resolv.conf` (часто `systemd-resolved` на 127.0.0.53); `/etc/hosts` проверяется первым согласно `/etc/nsswitch.conf`. Типы записей A/AAAA, CNAME, SRV, TXT; TTL управляет кешированием. JVM по умолчанию кеширует успешные разрешения навсегда, если задан `SecurityManager`, иначе 30 с (`networkaddress.cache.ttl`); ставь маленькое значение, когда IP сервисов меняются (Kubernetes, VIP в Swarm, [[docker-swarm]]).
- **DHCP**: хост рассылает DISCOVER, сервер отвечает OFFER с адресом, сроком аренды, шлюзом и DNS-серверами; хост отправляет REQUEST и получает ACK. Серверы обычно вместо этого используют статические адреса или резервирования.

### iproute2 (заменяет ifconfig/route/netstat)
| Задача | Команда |
|---|---|
| Интерфейсы и адреса | `ip a` (`ip addr show`), `ip -br a` |
| Состояние линка, MTU, up/down | `ip link`, `ip link set eth0 up` |
| Таблица маршрутизации | `ip r`, `ip route get 8.8.8.8` (какой интерфейс/шлюз будет использован) |
| Кеш ARP | `ip neigh` |
| Сокеты и слушатели | `ss -ltnp` (слушающие TCP с процессом), `ss -s` (сводка), `ss -tan state established` |
| Сетевые пространства имён | `ip netns list`, `ip netns exec <ns> ss -ltn` |
| Живой трафик | `tcpdump -i eth0 -nn port 5432`, `tcpdump -w cap.pcap` и открыть в Wireshark |
| Достижимость | `ping`, `traceroute`/`mtr`, `nc -zv host 443`, `curl -v`, `dig +short api.example.com` |

### Файрвол
- **nftables** — текущий фреймворк (по умолчанию с Debian 10, RHEL 8); `iptables` — совместимый фронтенд поверх него (`iptables-nft`). Понятия: таблицы -> цепочки (подключённые к хукам `input`, `forward`, `output`, `prerouting`, `postrouting`) -> правила с вердиктами (`accept`, `drop`, `reject`).
- Правило с учётом состояния `ct state established,related accept` пропускает ответы, поэтому открывать нужно только входящие порты.
- `ufw` (Ubuntu) и `firewalld` (RHEL) — обёртки. Docker вставляет свои цепочки `DOCKER` и обходит `ufw` для опубликованных портов; публикуй на `127.0.0.1:port`, если сервис должен оставаться локальным.

## Пример
```bash
# Разбор «приложение не может достучаться до Postgres» по порядку
ip -br a                                  # есть ли у хоста адрес и в состоянии ли UP линк
ip route get 10.20.5.10                   # какой интерфейс/шлюз будет использован
dig +short db.internal                    # разрешается ли имя и во что
nc -zv db.internal 5432                   # только TCP-рукопожатие: open, refused или timeout
ss -tanp | grep 5432                      # какие соединения уже держит JVM (проверка размера пула)
sudo tcpdump -nn -i eth0 host 10.20.5.10 and port 5432 -c 20   # SYN без SYN-ACK = файрвол/маршрут

# Минимальная политика nftables для API-хоста
sudo nft -f - <<'EOF'
table inet filter {
  chain input {
    type filter hook input priority 0; policy drop;
    ct state established,related accept
    iif lo accept
    ip protocol icmp accept
    tcp dport { 22, 443 } accept
    tcp dport 8080 ip saddr 10.20.0.0/16 accept   # порт приложения только из внутренней сети
  }
}
EOF
```

## Подводные камни
- «Connection refused» означает, что хост ответил RST (никто не слушает или слушает только на 127.0.0.1); «timeout» означает, что пакет отбросил файрвол или маршрут. Они указывают на разные исправления.
- `TIME_WAIT` накапливается, когда клиент открывает новое соединение на каждый запрос; используй пул соединений ([[hikaricp-pool-sizing]], [[rest-clients]]).
- `netstat` устарел и часто отсутствует в минимальных образах; учи `ss`. Внутри контейнера `ss` тоже может не быть; используй `nsenter` с хоста ([[linux-architecture-and-kernel]]).
- Опубликованные порты Docker доступны снаружи даже при включённом `ufw`.
