## Кратко
TCP-сегмент — это заголовок в 20–60 байт плюс данные внутри IP-пакета. Заголовок содержит порты, 32-битный **номер последовательности** (с какого байта потока начинается сегмент), 32-битный **номер подтверждения** (следующий байт, который ждёт отправитель), флаги вроде SYN/ACK/FIN/RST, приёмное **окно**, контрольную сумму и опции, согласуемые в SYN (MSS, масштаб окна, SACK, временные метки). Любая возможность TCP, от порядка до управления потоком, — это арифметика над этими полями.

## Основное
### Поля заголовка
| Поле | Бит | Значение |
|---|---|---|
| Порт источника / назначения | 16 + 16 | вместе с IP из [[ip-packet-structure]] образуют четвёрку, идентифицирующую соединение |
| Номер последовательности | 32 | номер первого байта данных в сегменте; в SYN это случайный начальный номер (ISN) |
| Номер подтверждения | 32 | следующий ожидаемый от собеседника байт, т. е. «всё до этого у меня есть»; действителен при выставленном ACK |
| Смещение данных (data offset) | 4 | длина заголовка в 32-битных словах: от 5 (20 байт) до 15 (60 байт) |
| Зарезервировано | 4 | должно быть нулём |
| Флаги | 8 | CWR, ECE, URG, ACK, PSH, RST, SYN, FIN |
| Окно | 16 | сколько байт отправитель этого сегмента ещё может принять ([[tcp-flow-control]]) |
| Контрольная сумма | 16 | по псевдозаголовку (IP, протокол, длина), заголовку и данным; обязательна |
| Указатель срочности (urgent pointer) | 16 | конец срочных данных при выставленном флаге URG; исторический, не используется |
| Опции | 0–320 | MSS, масштаб окна, SACK, временные метки, выравнивание NOP |

### Флаги
- **SYN**: синхронизировать номера последовательности, только в первых двух сегментах рукопожатия ([[tcp-handshake-and-connection-states]]).
- **ACK**: номер подтверждения действителен. Выставлен в каждом сегменте после первого SYN.
- **FIN**: «больше данных не отправлю». Обратное направление остаётся открытым, пока та сторона не отправит свой FIN.
- **RST**: немедленно оборвать соединение. Отправляется для порта без слушателя («connection refused») или при данных на закрытый сокет.
- **PSH**: отдать приложению, не дожидаясь заполнения буфера. Linux ставит его на последний сегмент каждого `write()`; в tcpdump отображается как `P`.
- **ECE / CWR**: явное уведомление о перегрузке (Explicit Congestion Notification). Маршрутизаторы помечают пакеты вместо отбрасывания, получатель возвращает ECE, отправитель уменьшает окно и отвечает CWR ([[tcp-congestion-control]]).

### Опции
- **MSS** (только в SYN): наибольшая полезная нагрузка, которую принимает эта сторона, 1460 в Ethernet (1500 − 20 IP − 20 TCP) ([[mss-mtu-pmtud]]).
- **Масштаб окна** (window scale, только в SYN): сдвиг 0–14, применяемый к 16-битному окну, так что окно может достигать ~1 ГиБ вместо 64 КиБ. `win 502` при `wscale 7` означает 502 × 128 = 64 256 байт.
- **SACK permitted / блоки SACK**: получатель сообщает, какие диапазоны у него есть за пропуском, чтобы отправитель повторил только дыру.
- **Временные метки** (timestamps): 10 байт, используются для измерения RTT и PAWS (защита от переполнившихся номеров последовательности). На 10 Гбит/с 32-битное пространство номеров переполняется примерно за 3,4 секунды.
- У SYN в Linux заголовок 40 байт (20 байт опций); у сегментов с данными и временными метками — 32 байта.

### Арифметика номеров последовательности и подтверждения
Возьмём ISN клиента 1000 и ISN сервера 5000.
| # | Направление | Флаги | seq | ack | Данные |
|---|---|---|---|---|---|
| 1 | C → S | SYN | 1000 | — | 0 |
| 2 | S → C | SYN, ACK | 5000 | 1001 | 0 |
| 3 | C → S | ACK | 1001 | 5001 | 0 |
| 4 | C → S | PSH, ACK | 1001 | 5001 | 100 байт |
| 5 | S → C | PSH, ACK | 5001 | 1101 | 300 байт |
| 6 | C → S | FIN, ACK | 1101 | 5301 | 0 |
| 7 | S → C | ACK | 5301 | 1102 | 0 |

- SYN и FIN занимают по одному номеру последовательности даже без данных; поэтому подтверждение ISN — это ISN + 1.
- Следующий seq всегда равен `seq + длина данных`. Номер подтверждения кумулятивный: `ack 1101` подтверждает байты 1001–1100.
- Сегмент 5 подтверждает данные клиента и несёт ответ в одном пакете (piggybacking). Отложенный ACK ждёт до ~40 мс в надежде на такой ответ ([[nagle-and-delayed-ack]]).
- ISN случайны (RFC 6528), поэтому атакующий вне пути не может их угадать и внедрить данные или RST в твоё соединение.

## Пример
Тот же обмен в выводе tcpdump против сервера Postgres. После SYN tcpdump показывает **относительные** номера, начиная с 1 (для абсолютных — `-S`).
```bash
$ sudo tcpdump -ni eth0 'tcp port 5432'
IP 10.0.0.5.51000 > 10.0.0.9.5432: Flags [S], seq 2830113744, win 64240, options [mss 1460,sackOK,TS val 4011 ecr 0,nop,wscale 7], length 0
IP 10.0.0.9.5432 > 10.0.0.5.51000: Flags [S.], seq 1729370016, ack 2830113745, win 65160, options [mss 1460,sackOK,TS val 9120 ecr 4011,nop,wscale 7], length 0
IP 10.0.0.5.51000 > 10.0.0.9.5432: Flags [.], ack 1, win 502, length 0
IP 10.0.0.5.51000 > 10.0.0.9.5432: Flags [P.], seq 1:101, ack 1, win 502, length 100
IP 10.0.0.9.5432 > 10.0.0.5.51000: Flags [P.], seq 1:301, ack 101, win 510, length 300
IP 10.0.0.5.51000 > 10.0.0.9.5432: Flags [F.], seq 101, ack 301, win 501, length 0
IP 10.0.0.9.5432 > 10.0.0.5.51000: Flags [.], ack 102, win 510, length 0
# [S.] = SYN+ACK, [.] = только ACK, [P.] = PSH+ACK, [F.] = FIN+ACK
```

## Подводные камни
- `tcpdump` на отправляющем хосте часто сообщает «bad cksum» для исходящих сегментов. Контрольные суммы вычисляет сетевая карта (checksum offload) уже после захвата; это не повреждение.
- Сравнение seq в двух захватах с относительной нумерацией: каждый захват начинает со своей «1». Используй `-S`, когда сопоставляешь трассы клиента и сервера.
- Промежуточные устройства (middleboxes), вырезающие масштаб окна или SACK, молча ограничивают пропускную способность; проверь опции SYN на обоих концах.
- Ожидание, что сегменты совпадут с твоими вызовами `write()`. Ядро режет поток по MSS и склеивает мелкие записи; TSO/GRO даже показывают в захватах «сегменты» по 64 КБ.
- Связанные заметки: [[tcp-vs-udp]] — обзор, [[udp-in-depth]] — 8-байтная альтернатива, [[socket-management]] — буферы, в которые указывают эти номера.
