## Кратко
Redis — однопоточный сервер в памяти с типизированными значениями. Структуру выбирают по нужной операции, а не по форме данных.

## Основное
- **String**: записи кэша, счётчики (`INCR`), распределённые блокировки (`SET k v NX PX 30000`).
- **Hash**: один объект с полями, которые обновляются независимо.
- **List**: очереди (`LPUSH` / `BRPOP`).
- **Set / Sorted set**: уникальность, таблицы лидеров, ограничение частоты запросов (rate limiting) с оценкой (score) = метка времени.
- **Stream**: журнал только для дописывания с consumer group; лёгкая альтернатива Kafka для небольших объёмов.
- Ключи истекают через `EX`; на ключи кэша всегда ставь TTL.
- **Ключи и ограничения**: ключ — любая бинарно-безопасная строка (до 512 MB, но держи его коротким: `idem:<id>`, `cache:user:<id>`), один экземпляр адресует до 2^32 ключей (> 4 миллиардов), а одно значение (String или один элемент коллекции) ограничено 512 MB. Значения — байтовые строки; типизированные структуры построены поверх них.
- **Pub/Sub** (`PUBLISH` / `SUBSCRIBE`, по шаблону `PSUBSCRIBE`): рассылка по принципу «отправил и забыл» (fire-and-forget), без сохранения и без доставки отключённым подписчикам. Подходит для инвалидации кэша или живых уведомлений; для очереди, которая действительно нужна, используй List или Stream.
- **Geo** (`GEOADD` / `GEOSEARCH`): точки с широтой/долготой хранятся как Sorted set с geohash в качестве оценки; запросы по радиусу и прямоугольнику за O(log n).
- Типичные роли в одном стеке: кэш перед Postgres, ключи идемпотентности и блокировок, ограничитель частоты запросов, хранилище сессий, лёгкая очередь сообщений или stream, шина pub/sub. Для долговечных, воспроизводимых потоков большого объёма он не заменяет [[kafka-architecture|Kafka]].


### Внутреннее устройство
- **Один поток команд** крутит цикл событий по всем клиентским сокетам (epoll, [[socket-management]]): каждая команда атомарна без блокировок, а одна медленная команда (`KEYS *`, `HGETALL` на огромном хэше, большой Lua-скрипт) останавливает всех клиентов. С 6.0 есть необязательные потоки ввода-вывода, которые разбирают запросы и пишут в сокеты; выполнение по-прежнему однопоточное.
- Пространство ключей — одна большая **хэш-таблица** с постепенным рехэшированием: при росте каждая команда переносит несколько корзин, поэтому нет паузы на изменение размера.
- У каждого типа есть компактная и полная **кодировки**, переключаемые автоматически по размеру: маленькие хэши, списки и сортированные множества — это **listpack** (один непрерывный блок, дружелюбный к кэшу); большие становятся хэш-таблицей, **quicklist** (связный список listpack-ов) или **skiplist + хэш-таблица** для сортированных множеств (O(log n) по score, O(1) по элементу). Маленькие множества целых чисел — **intset**. `OBJECT ENCODING key` показывает, какая используется.
- Память — это всё: значения, ключи и накладные расходы на ключ (~50–70 байт) должны помещаться в RAM; `maxmemory` + политика вытеснения (`allkeys-lru`, `allkeys-lfu`, `volatile-ttl`) решают, что уходит при заполнении.
- Персистентность (снимки RDB через fork + copy-on-write, журнал AOF) и её компромиссы: [[redis-patterns-and-persistence]], [[wal-redo-undo-and-durability]].
- Репликация асинхронная (реплика может отставать и потерять подтверждённые записи при переключении); Redis Cluster делит ключи на 16 384 хэш-слота между primary-узлами; команды над несколькими ключами работают, только если все ключи в одном слоте (используй `{hash tags}`).
- В сравнении с Memcached: типизированные значения и персистентность против более простого многопоточного кэша строк ([[memcached-architecture]]).
## Пример
```java
// ключ идемпотентности с TTL 24 ч, см. заметку про идемпотентность
Boolean first = redis.opsForValue().setIfAbsent("idem:" + requestId, "1", Duration.ofHours(24));
if (!Boolean.TRUE.equals(first)) return cachedResponse(requestId);
```

## Подводные камни
- `KEYS *` блокирует сервер; используй `SCAN`.
- Большие значения (> 1 MB) и горячие ключи заставляют всё остальное ждать в очереди за ними.
- Связанные заметки: [[idempotency]], [[spring-cache-abstraction]]
